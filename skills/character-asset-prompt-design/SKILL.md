# 剧本角色资产提示词设计 — 总控调度器

把剧本角色变成"原始外观文生图 + 变体外观图生图"的成组提示词。**本文件只做调度**：执行到哪个阶段读哪个规则文件，禁止凭记忆跳过读取。

## 0. 定位与边界（流水线中的位置）

```
script-asset-extraction（资产清单 Excel）
        ↓ 提供角色清单与状态变化线索
【本技能】剧本角色 → 原始外观 T2I + 变体外观 I2I 提示词（中英双版）
        ↓ 提供角色视觉锚（与场景资产平级，共用母题索引）
cinematic-seedance-director（视频提示词：角色+场景同框在此合成）
```

与 `script-asset-prompt-design`（场景）为**平级姊妹技能**，方法论共享（证据考古/三级分级/中英双版/画面控制/跨文档索引），核心差异：

> **场景全链路文生图；角色仅原始外观文生图，其余外观一律图生图/图片编辑，锚定原始外观参考图**——防止换装/年龄/进化时脸和身体漂移。用户会在生图工具中 @ 参考图：提示词写"锚定 + 变更"，需要贴参考图的位点写中文占位标识 `@资产名`（CAP-12），用户替换为参考图。

边界：一次一个角色；同框多人构图属视频提示词阶段职责。

## 1. 全局铁律

1. **先证据后设计**：任何外貌/服装元素必须有剧本出处，或标注 ⚠️视觉延展并给出锚点（CHR-01/02）。
2. **一角色一原始外观**：每个角色只出一份完整文生图提示词（原始外观），其余全部为参考式变体（CHR-03/04）。
3. **身份锚不可侵犯**：变体只改变更层，锚定层（脸/发/瞳/体型/印记）逐字复用 + 声明"与参考图完全一致"（CHR-05、CVC-01）。
4. **变体五段结构**：锚定段→变更段→保持段→画面控制段→负面清单（含编辑漂移层）（CAP-02、CVC-05）。
5. **角色画幅固定 9:16 竖幅、真人写实电影风格、低饱和**（2026-08-29 用户拍板：全身像应竖长；**画幅不随管线变化**，理由见 `rules/PIPELINE_PRESETS.md` PP-C1——角色立绘是身份参考图，竖幅全身信息最全，横用可裁）；**统一构图基准**：全身像、居中笔直站立、双手自然下垂、无手持物、平面柔光、浅灰色背景（CVC-03）。**场景资产画幅才跟随管线**（P1=9:16 / P2/P3=16:9 / P4=21:9），归场景技能管，角色勿混。
6. **管线决定风格调性（PP-C2/PP-C3，2026-09-03 新增）**：开工前读 `rules/PIPELINE_PRESETS.md` 定管线（P1 下沉中老年 / P2 女频恋爱 / P3 女频诡异恐怖 / P4 海外），按该管线的**人物类型 / 服装调性 / 皮肤质感 / 色调 / 变体重点**设计角色，未定则提问确认（国内主力默认 P1）；交付文档开头须标注管线（PP-C4）。**同时按 `rules/cultural-context.md`（ETH-01~08，2026-09-04 新增）做文化坐标定位**：判定市场×时代×地域×族群，产出强化族群五官的描述（ETH-02）、民族服装发型纹身（ETH-04）、语言个性档案（ETH-05）；P4 海外按"当地电影"原生制作（ETH-06），全管线禁止中式套皮/模板脸。
7. **反馈转译为正向描述**，禁止把否定式反馈原文写进提示词（CVC-04）。
8. **中英双版同时交付**，结构完全对应（CAP-03）。
9. **提示词正文纯净**：代码块内禁入证据标注（✅/⚠️/行号）、规则编号（CHR/CAP/CVC-xx）、延展声明、剧情解释（CAP-08）。
10. **生成前先做 S0 跨文档检测**（CHR-09~13）：同角色已有文档则变体必须锚定其原始外观；亲缘角色复用家族锚 token；角色环境/服装材质与场景母题一致；首次生成后向母题索引「角色资产」区块登记。
11. **角色身上有特殊符号必须独立登记与出图**（CHR-14/15）：凡符文/纹身/徽记/烙印/痣/疤/雀斑/胎记等「有造型或有位置」的符号，文档最前列「符号注册表」，并按分级出独立资产图——T1 叙事符号出 1:1「符号设计图」（浅符暗底/深符浅底，正交平铺不含身体），**章节前置到原始外观之前**（先确认形态再出角色）；T2 定位标记出「区域特写」锁位置，**章节后置到变体之后**（先出角色再锁位）。原始外观与全部变体引用之，防连镜漂移。
12. **提示词自包含（无关内容禁令）**（CAP-10）：代码块内只允许"单看提示词本身就能理解"的内容——禁外部资产引用（如《符号设计图 §M1》）、禁角色名/剧名标签（如"莱拉·原始外观"）、禁工具操作指令（@哪张图）；符号形态一律自描述；@ 参考图与符号资产由块外标题标注提醒（CAP-11：变体标题加"· 记得参考印记生成"）。**唯一例外（CAP-12）**：需要贴参考图的位点，在该位置写一行中文占位标识 `@资产名`（如 `@银白月裔印记`、`@莱拉原始外观`），中英版同位置，用户生成时替换为对应参考图。
13. **体裁分支（2026-09-17 新增，开工前必确认）**：铁律 5 的"真人写实电影风格"是**默认值**，不是唯一值。开工前必须确认用户要的体裁，三种分支风格锁不同（**画幅规则不变，角色仍 9:16**）：

| 体裁 | 触发词 | 风格锁关键词 | 补充要求 |
|---|---|---|---|
| **真人写实电影**（默认） | 电影、真人写实、默认不说明 | 真人写实电影风格，电影摄影机，电影布光，低饱和 | 铁律 5 原样执行 |
| **写实真人电视剧 / 短剧** | 电视剧、短剧、竖屏剧、真人剧 | 写实真人电视剧，35mm 电影定焦镜头，ARRI Alexa，T2.0 浅景深，三点式自然主义布光，真实皮肤纹理与毛孔，**无磨皮无美颜无滤镜**，轻微胶片颗粒，年代剧调色 | 加焦段/光孔/布光方案；帧率 25fps；横屏 16:9 发行时仅换画幅 token 与焦段（28mm→24mm），角色锚不变 |
| **AI 动态漫 / 漫剧** | 动态漫、漫剧、条漫、2D | 2D 国漫动态漫画风，粗描边，扁平光影叠加局部厚涂，暖调低饱和，头身比成年 7 / 少年 6 | 负面必须含"无写实照片质感、无 3D 渲染感"；少年角色面容按 16-17 岁画 |

**真人/电视剧分支下的额外合规约束（RL-xx）**：RL-01 少年角色一律**成年演员**出演（提示词写"成年演员饰演，面容呈现十七八岁"，**禁止** child/kid/具体儿童年龄数字）；RL-02 未成年演员不得演受虐戏；RL-03 伤残只出**空袖管 / 义肢道具**，禁创口、疤痕、缝合线、断端；RL-04 无婴幼儿、无孕妇；RL-05 无血、无烟、无刃器；RL-06 纸质道具文字留白；RL-07 负面固定带"明星脸 / celebrity likeness"规避肖像权。

> 判据：只要用户说"电视剧/短剧/真人"，就走电视剧分支；说"动态漫/漫剧/2D"，走漫剧分支；都没说，按默认真人写实电影，并在交付时注明体裁。

## 3. 交付物约定

```
{剧本目录}\outputs\角色提示词\
└── {角色名}\
    └── {角色名}_角色提示词.md    ← 一个角色一个文档：
                                     0 跨文档关联说明 + 管线标注（PP-C4）+ 文化坐标（ETH-01 市场×时代×地域×族群）
                                     / 1 符号注册表（CHR-14，置顶：凡有符文/纹身/痣/疤即列，无则写「无」）
                                     / 2 外观树+证据分级
                                     / 3 身份锚表
                                     / 4 语言个性档案（ETH-05 口音/用词/节奏/性格——供台词配音，不进视觉代码块）
                                     / 5 T1 符号设计图章节（CHR-15 前置：先于角色出图；无 T1 则省略）
                                     / 6 原始外观（T2I 中英双版，⑦段符号形态自描述；身份锚含族群五官强化 ETH-02，禁编号引用）
                                     / 7 变体×N（I2I 中英双版，标题带「记得参考印记生成」标注；符号与参考图完全一致）
                                     / 8 T2 区域特写章节（CHR-15 后置：后于角色出图；无 T2 则省略）
                                     / 9 衔接说明
```
> 每个外观用连续性 ID `{角色名}-{外观名}`（如 `莱拉-原始`、`凯尔-战损`）；跨文档引用一律用 ID。
> 角色首次生成后向 `{剧本目录}/outputs/场景提示词/母题索引.md` 的「已登记角色资产」区块追加登记（文件不存在则创建，含场景/角色两区块模板）。

## 5. 维护约定

修改任何规则前先读 rules/ 对应文件全文；新增规则写入对应模块并编号（只增不复用），同步登记进 review/preflight.md 清单项；变更记入 CHANGELOG.md。
