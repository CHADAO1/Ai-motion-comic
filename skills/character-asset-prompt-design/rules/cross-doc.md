# 规则模块 — CHR-09~13 跨文档一致性（分次生成的角色复利）

作用域：跨多次对话、按角色逐个生成提示词文档时，保证"同一批人、同一个世界"。与场景技能 SPC-09 同构。

## 为什么需要

角色几乎总是一个一个生成，且常跨对话完成。角色的"脸"只定一次（原始外观），因此一致性比场景更刚性：**新任务必须先读已有角色文档，让一切变体锚定既定原始外观**。三类核心情形：

---

## CHR-09 S0 检测流程（生成前必做）

1. `glob {剧本目录}/outputs/角色提示词/**/*.md` 与 `outputs/场景提示词/**/*.md`，获取全部已有文档。
2. 新角色名/别名匹配已有角色文档：命中 → 读其外观树、身份锚表，按 CHR-10 处理。
3. 检查亲缘：剧本中与已有角色有血缘/家族关系的 → 按 CHR-11 亲缘一致性。
4. 检查场景关联：角色服装材质/所处环境涉及已生成场景母题 → 按 CHR-11 场景关联。
5. 读取 `母题索引.md`（若存在）可跳过全文，直接拿「角色资产」区块与场景母题摘要。
6. 无命中 → 普通新角色走 S1~S5。
7. **未做 S0 直接生成，视为未过 preflight（检查项 15）**，须回补关联声明。

---

## CHR-10 角色外观重复三选项

新需求与该角色已有文档出现重叠时：

- **选项 1 · 变体已存在**
  所需外观已生成 → **不再生成**。在新任务处注明：
  `已在《{角色名}》文档 {外观ID} 生成，本需求引用，无需重出。`

- **选项 2 · 新变体**
  所需外观未覆盖（如已有婚裙，现需祭袍）→ **逐字复用其身份锚 token**，按五段结构（CAP-02）展开新变体。注明：
  `与《{角色名}》{原始外观ID} 同锚，本张为{变体名}变体（CHR-10 选项2）。`

- **选项 3 · 既有外观与剧本冲突**
  外貌/服装与剧本证据不符 → 正常生成新版本，并**写明具体错误**（哪句描写/哪条证据被误用），不能只说"有误"。登记母题索引"已知冲突"，旧文档加：
  `⚠️ 校正见《{角色名}》{新外观ID}（CHR-10 选项3）。`

---

## CHR-11 亲缘与场景关联

- **亲缘一致性**：血缘角色共享部分锚 token（瞳色/发色基因/家族印记）。
  新角色生成时读取亲缘角色的锚表，在身份锚表中注明：
  `与{角色名}（{原始外观ID}）为{姐弟/父女/...}关系，共享{锚token}。`
  判定以剧本明写为准（"和她一样的银发"），无明写不强行关联。

- **场景关联（资产相关的角色侧）**：角色变体若带环境（场景内立绘/背景可辨场景），环境母题**必须从场景文档复用**，注明：
  `环境风格沿用《{场景组}》{视角ID}（CHR-11 场景关联）。`
  禁止另起环境。角色服装材质同理对齐场景母题（CHR-07）。

---

## CHR-12 角色索引登记

每份角色文档首次生成时，向 `{剧本目录}/outputs/场景提示词/母题索引.md` 的「已登记角色资产」区块追加一行（文件不存在则创建，含场景/角色两区块模板）：

```
| 角色 | 外观(名·ID) | 身份锚 token | 关联 | 备注 |
```

- 外观 ID 格式：`{角色名}-{外观名}`（如 `莱拉-原始`、`莱拉-祭袍`、`凯尔-战损`）。
- 锚 token 用短词串：`银白长发/琥珀色瞳/左肩月牙胎记/高挑纤细`。
- "已知冲突"登记 CHR-10 选项3；"历史修正记录"登记 CHR-13。
- 索引是轻量索引：新任务优先读它，避免重读全部文档全文。

---

## CHR-13 历史修正（非冲突的漂移）

旧文档确有可统一之处（变体漏了保持段、锚 token 表述漂移、负面清单缺编辑漂移层等）→ **优先直接补一笔**到旧文档对应外观（并登记母题索引"历史修正"），而非新文档另立版本。仅剧本冲突时才走 CHR-10 选项3。与场景技能 SPC-09 9.7 同理。

> 例：早期变体忘了写"配饰（古法符牌）保持不变"，后续发现符牌被 AI 随机增删 → 按 CHR-13 直接给该变体保持段补入符牌，而不是另立新变体。
