# cinematic-seedance-director — 电影级 Seedance 提示词导演

双模式剧本技能包：把剧本编译成 Seedance 2.0/2.5 电影级提示词（Mode 1），或按四维度优化剧本（Mode 2）。纯 Markdown + Node.js 脚本，无平台专有依赖。

> 本文件是技能包的通用说明，供人类和其他 AI 工具快速理解本包；
> 平台内的调度入口永远是 `SKILL.md`，维护者入口是 `MAINTENANCE.md`。

## 双模式

| 模式 | 触发短语 | 功能 |
|---|---|---|
| Mode 1 剧本转提示词 | 剧本转提示词 / 视频提示词 / 生成提示词 / Seedance 提示词 / 分镜提示词 | 解析剧本 → 匹配导演风格（Deakins/Lubezki/Fincher 等 8 位 DP）→ 输出九段结构提示词 |
| Mode 2 剧本优化 | 剧本优化 / 优化剧本 / 文戏优化 / 武戏优化 | 四维优化：画面情绪 / 剧情扩写 / Ekman 表情动态 / 逻辑链 |

内置生产实测规则：资产锁定与反推缓存、逐镜头对账、反馈记事本、动作因果、状态守恒、台词本土化、台词表（剪辑用）、**管线预设**（见 `rules/PIPELINE_PRESETS.md`）。产物为纯净纯文本，不含任何元注释。

## 在 OpenCode 中使用

放入 `.opencode/skills/cinematic-seedance-director\` 即被自动发现。说触发短语即可，技能内部按流水线自动执行：

```
S0解析 → S1脚本估时 → S2拆段 → S3空间图三件套 → 中途审查(A1–A4)
→ S4提示词编译 → S5台词对照TXT → S6双审查(Preflight+Audit) → 交付
```

中间产物落盘在 `{剧本目录}\pipeline\`，中断后可断点续跑。

## 在其他宿主中使用

本包对宿主能力的要求从高到低有三档降级：

1. **全能型**（能读本地文件 + 能跑 node）：直接以 `SKILL.md` 为入口提示词，按其调度执行，体验与 OpenCode 相同。
2. **只能读文件**：以 `SKILL.md` 为入口；跑到某阶段时手动把对应模块内容贴进上下文（需要哪个文件见 SKILL.md §3 流水线表"必读文件"列）。跳过两个脚本，改用手工估算（公式见 `rules/timeline-splitting.md` TIME-01）。
3. **只能贴文本**：把 `SKILL.md` + 本次任务涉及的单个 rules 文件拼接成系统提示词使用。注意保持"一次只带一个阶段所需的规则"，不要把全部文件一次性塞入。

所有档位共享同一套产物目录约定（SKILL.md §2），保证跨工具接力时状态兼容。

## 注意事项（最易踩的坑）

1. 提示词代码块第一行必须是 `【风格参考：…】`，最后一行必须是 `[N]秒。[画幅]。`（画幅按管线：P1=9:16、P2/P3=16:9、P4=21:9）——题头/分隔线一律禁止。
2. 以台词结尾的段必须追加独立收尾镜（切镜、无台词、0.5–1s 缓冲），否则平台掐词。
3. 单段时长按管线：P1-P3 每段 12–15s（硬性，PP-01）、P4 ≤30s；段数由内容量决定（`段数 ∈ [ceil(总内容量/15), floor(总内容量/12)]`），且每段写清全部仍在画面内人物的站位。
4. 方位描述必须双参照（上下左右前后 + 东南西北并列），禁止跨段编号引用（模型看不到段号）。
5. 交付前必须过 Preflight（review/preflight.md）+ Audit（review/audit.md），审查报告缺失视为未完成。
6. 修改技能本身前先读 `MAINTENANCE.md`，改完跑 `scripts/lint_skill.mjs` 自检。
