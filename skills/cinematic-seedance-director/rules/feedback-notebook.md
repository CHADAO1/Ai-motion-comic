# 规则模块 R8 — 镜头反馈记事本（防遗忘）

> 总控在任何修改类任务开始时读本文件。规则编号 NB-*。

多次反馈后会出现"忘前忘后"：旧反馈被新对话冲掉。解决办法是为每个镜头维护持久化的反馈记事本，所有历史反馈沉淀其中，修改前必读。

## 位置与命名

- 存放目录：`{剧本目录}\反馈历史\`，目录不存在则创建。
- 每个镜头一个文件，命名对齐镜头输出，如 `4-3-镜头01.md`；一段一镜时用 `{集}-{段}.md`（如 `4-3.md`）。
- 与具体镜头无关的全局偏好（如"统一按 P1 管线 9:16""都从背后机位开场"），记入 `{剧本目录}\反馈历史\_全局.md`，每次编译任何镜头前同样先读。

## NB-02 写入规则（每次用户反馈后）

1. 把用户反馈**精炼成可执行要点**（去掉对话语气，只留修改指令），追加到该镜头记事本，每条带日期。
2. 反馈要点允许用"要改成 X / 开场用背后机位摇镜"这种正向指令写法，也可保留"不要…"备注——记事本是给编译者看的内部文件，不受 PUR"提示词纯净"规则约束。
3. 同一条被推翻时，追加新条目并注明"取代 2026-XX-XX 的某条"，不删旧条目（保留修改轨迹）。

## NB-01 读取规则（每次修改镜头前，硬性）

1. 先读该镜头记事本 + `_全局.md` 全文。
2. 把记事本里所有历史要点逐条纳入本次编译，逐条对照落地。
3. Preflight 复查与 Audit A1 项各加一项：**本镜头记事本中的每条历史反馈是否都已落到提示词正文**。

## 与 PUR 的关系

记事本允许出现"不要传送/不要消失"这类备注；但**写进最终提示词的正文**时，一律只写正向动作（"自动门向两侧滑开"），禁止把反馈的否定表述搬进提示词（purity-wording.md PUR-04）。
