# 规则模块 R11 — 即梦全能参考 · 全模态素材绑定（OR-*）

> 总控在 Stage S4（提示词组装）读本文件。当用户使用**即梦全能参考（Omni-Reference）**入口、且已上传角色/场景/物品/运镜/配音/风格素材时，本模块的 @绑定规则**硬性生效**。
> 若用户未使用全能参考入口（纯文生视频），本模块整体跳过，只在"参考图占位"层面沿用资产技能的约定。
> 来源：即梦 Seedance 全能参考专用提示词工程（六文件融合）。

## OR-01 @符号的唯一合法用途

`@` 只用于绑定**已上传至即梦全能参考入口**的实际素材文件：

| 可绑定类型 | 素材文件 | 示例标注 |
|---|---|---|
| 角色参考图/视频 | `shenwanqing.png` | 画面主体为 @shenwanqing 沈婉清 |
| 场景参考图/视频 | `xitang.png` | 场景为 @xitang 喜堂 |
| 物品/道具参考图/视频 | `dagaitou.png` | 物品为 @dagaitou 大红盖头 |
| 运镜参考视频 | `yunjing.mp4` | 仅参考 @yunjing 的运镜方式 |
| 配音参考音频 | `peiyin.mp3` | 仅参考 @peiyin 的音色、语气、语速 |
| 风格参考图/视频 | `style_a.png` | 仅参考 @style_a 的风格质感 |

**绝对禁止**：`@角色名`、`@场景名` 这类**没有对应上传素材**的空标记——模型识别不到，会污染权重。

## OR-02 素材命名规范（硬性）

- 只用**英文/数字/下划线**：`shenwanqing.png`、`scene_01.jpg`、`peiyin_02.mp3`
- **禁止**：中文名、空格、特殊符号、乱码（`@沈婉清`、`@喜堂 1.png` 均失效）
- 命名与资产 ID 建立映射表，写入交付文档（如 `CHAR-01 → shenwanqing.png`）

## OR-03 绑定格式模板（全维度通用）

每条绑定都必须写出**"对象 + 素材名 + 参考范围"**三段：

```text
角色：画面主体为@shenwanqing 沈婉清，人物面部、发型、体型特征与参考图完全一致
场景：场景为@xitang 喜堂，场景布局、陈设、光影与参考图完全一致
物品：画面中的物品为@dagaitou 大红盖头，物品样式、颜色、材质与参考图完全一致
运镜：仅参考@yunjing 的运镜方式，人物、场景、服饰与该视频无关
配音：仅参考@peiyin 的音色、语气、语速，台词内容与该音频无关
```

**核心要求**：必须写明"**仅参考什么**"与"**与该素材无关的是什么**"——否则模型会无差别复刻素材里的无关元素（运镜参考视频里的人脸会被抄进画面）。

## OR-04 权重与位置（硬性）

1. **分镜组头部**设「参考素材绑定」栏，列出全组用到的**所有**素材（无则写"无"）
2. **每个镜头**的 @绑定描述放在该**镜头最前端**——越靠前权重越高
3. **数量上限**：单镜头 @素材 ≤ 3 个；单分镜组 @素材 ≤ 6 个（超限会互相稀释、素材冲突）
4. **场景/物品双写**：场景绑定除头部栏外，还要在**第一个镜头**的场景描述中重复；物品绑定要在**物品出现的对应镜头**重复

## OR-05 四类绝对禁止（翻车红线）

| # | 禁止行为 | 后果 |
|---|---|---|
| 1 | 无对应上传素材的 @标记 | 权重污染、无效绑定 |
| 2 | 同一角色绑定多张不同人脸图 | 人脸融合、特征混乱 |
| 3 | 同一场景/物品绑定多张不同参考图 | 场景/物品融合混乱 |
| 4 | 未声明参考范围 | 模型无差别复刻无关元素 |

**附加**：
- 单角色**只绑 1 张**固定人脸参考图；单场景、单物品同理
- 全能参考入口**禁止同时使用首尾帧参考图**（模型逻辑冲突、画面崩坏）
- 生成视频时长须与参考视频/音频时长匹配，否则音画错位、动作截断

## OR-06 调试与正式生成流程

1. **先用 4-5 秒短时长**测试提示词 + 素材绑定效果，确认无误
2. 再生成正式成片（P1-P3 组 12-15s；P4 组 ≤30s）
3. 素材调试阶段单独建"测试组"，不与正式组混排

## OR-07 与资产技能的闭环（跨技能协作）

本模块消费的是**资产技能产出的图**，流程：

```text
character-asset-prompt-design（角色立绘 9:16）
script-asset-prompt-design（场景图，画幅随管线）
script-asset-extraction（物品/道具图）
        ↓ 生成出图
        上传即梦全能参考入口
        ↓ 按 OR-02 规范命名
本模块 @绑定（OR-03/04）
        ↓
视频提示词（主控 S4）
```

**登记义务**：资产 ID 与素材文件名必须在交付文档里逐条映射，例如：

| 资产 ID | 类型 | 素材文件名 | 绑定写法 |
|---|---|---|---|
| CHAR-01 | 角色 | `shenwanqing.png` | 画面主体为@shenwanqing 沈婉清 |
| SCENE-03 | 场景 | `xitang.png` | 场景为@xitang 喜堂 |
| PROP-05 | 物品 | `dagaitou.png` | 物品为@dagaitou 大红盖头 |

## OR-08 无参考素材时的降级写法（硬性）

未上传素材时**禁止**编造 @标记。降级为**功能描述标签**：

- ❌ 错误：`画面主体为@沈婉清，人物面部与参考图一致`（没上传图）
- ✅ 正确：`画面主体是一名年轻女子：鹅蛋脸、高鼻梁、黑长直发、青碧色长裙`（纯文字描述到位）

降级时人物/场景一致性靠**文字锚**（五官/服装/发型的固定描述串）维持——这正是角色资产技能"身份锚"的用途。

## OR-09 @绑定自检（交付前必过）

- [ ] 每个 @ 都有对应上传素材，无空标记
- [ ] 素材命名全部英文/数字，无中文/特殊符号
- [ ] 每条绑定写明"仅参考什么 + 与什么无关"
- [ ] 单镜头 @ ≤3、单组 @ ≤6
- [ ] 场景/物品在头部栏 + 对应镜头双写
- [ ] 资产 ID ↔ 素材文件名映射表已列入交付文档

## OR-10 资产清单头（每段提示词开头必设，硬性）

**用户诉求原文（2026-09-10）**：「能不能在开头标明出现的角色场景音色道具啊，我方便直接去"@"我的参考图」——用户手上已有一批角色立绘/场景图，需要在提示词开头一眼看到本段用了哪些资产，方便复制 `@` 标记去绑定参考图。

**位置**：紧随 `【风格参考：…】` 风格声明之后、`【场景概述】` 之前。**不占镜头块**，不参与 FMT/P6 校验。

**四类分组，固定顺序**：场景 → 角色 → 音色 → 道具。每组一行 `【组名】@file 中文名（简述）`，多个资产用全角缩进换行对齐。

**模板**：
```text
【资产清单·可直接@引用参考图】
【场景】@scene_rental_room　日/内 老破小出租屋（宋末房间 + 客厅，白日光、直播支架）
【角色】@songmo 宋末（女主｜18岁左右｜齐肩短发｜青碧色长裙）
　　　　@cuilili 崔莉莉（租户主播｜25岁左右｜亮色卷发｜都市休闲装）
【音色】@voice_cuilili 国漫都市女声｜亮脆做作｜语速偏快
【道具】@prop_scissors 书桌上的剪刀（宋末剪发用）
（注：以上为可选参考图绑定；若未上传对应素材，请忽略 @ 标记，直接按下方文字描述生成。）
```

**硬性要求**：
1. **按段实际内容动态生成**——只列本段真正出现的角色/道具，不照抄全集清单（避免空 `@` 污染权重，OR-01）。
2. **文件名全剧固定**：同一角色在 13 段里必须是同一个 `@` 标记，禁止一段写 `@songmo`、另一段写 `@songmo_01`。
3. **命名遵循 OR-02**：英文/数字/下划线。中文名只作为 `@file` 后面的**显示名**，不参与绑定。
4. **必须附免责注**：说明未上传素材时可忽略 `@`，按文字描述生成——保证在"纯文生视频"路径下提示词仍可用（OR-08 降级）。
5. **音色组标注的是"配音参考"可选绑定**；不绑定时由镜头内 `【配音指令】` 五段式描述驱动，两者不冲突。
6. **配套交付「资产命名对照表」**：列出 资产 → `@`标记 → 建议文件名 → 参考图说明 → 画幅，让用户照着命名上传。

**分离原则**：`@` 是**可选增强**，文字锚是**保底**。写清单不等于强制绑定——用户没出图时删掉 `@` 即可，提示词本体不受影响。
