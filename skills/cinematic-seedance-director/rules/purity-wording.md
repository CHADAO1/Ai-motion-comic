# 规则模块 R7 — 产物纯净与特定场景措辞

> 总控在 Stage S4 读本文件；Preflight 终检时复查。规则编号 PUR-/FMT-/SCENE-*。

## 提示词是独立成品文本（最高频失败模式，独立成节）

### FMT-01 无题头（硬性）
提示词正文第一行必须是 `【风格参考：…】`，前面不允许出现任何题头/标题/分隔线/段落名。**禁止**任何形式的题头行，包括：
- ❌ `场景 5-1 | INT. 万斯家主居室·客厅 — 恩谢承诺`
- ❌ `段1 | 万斯家主居室·客厅 — 恩谢承诺（15秒）`
- ❌ `风格参考：Deakins → Khondji`（独立题头行）
- ❌ `═════════` 分隔线块

### FMT-02 无结尾分隔线（硬性）
提示词正文以 `[N]秒。[画幅ratio]。` 收尾后，**不再**追加任何分隔线（`═════`、`---` 等）。代码块内最后一行为时长+画幅。

**画幅与秒数一律按管线（PP-01）取值，禁止沿用出厂默认值**：

| 管线 | 尾行格式 |
|---|---|
| P1 国内下沉中老年 | `[12]秒。9:16。` |
| P2 国内女频恋爱 | `[12]秒。16:9。` |
| P3 国内女频诡异恐怖 | `[12]秒。16:9。` |
| P4 海外 | `[30]秒。21:9。` |

（秒数按该段实际估算值替换 12 / 30；用户指定其他画幅时用指定值。）

这些标题/时长/段落名/镜头分析只写在提示词代码块**之外**作为交付说明。正确形式（代码块第一行即风格参考，最后一行即时长）：

```
【风格参考：Deakins】…
【场景概述】…
⚠️空间布局与资产锁定：…
…
[12]秒。9:16。
```

（上例为 P1 管线；P2/P3 尾行改 16:9，P4 改 21:9。）

### PUR-03 禁止写入对话反馈与元信息
禁止出现这类字眼/写法：`（不做暗面开场）`、`（反推发现…）`、`为了…所以…`、`已实测`、`修正：…`、`上面说的…`、`与上一版不同…`、`参考对话…`。模型不理解这些元信息，只会被干扰判断。反馈意见通过**改写正文本身**落地。例：要说"开场空间站已明亮"，直接写"空间站远景已完全明亮地呈现在画面右侧"，不要写"空间站开场即明亮（不做暗面开场）"。

### PUR-04 禁止把反馈对话的否定标注带进提示词（硬性）
用户反馈（如"正常开门，不是传送门，不要消失"）是沟通元信息，只用于指导正文改写，**不得把其中的否定表述原样写进提示词**（"非传送""不要消失""不是…"）。提示词只写正常动作本身。
- 错误写法：`自动门向两侧滑开——非传送、无空间扭曲、不瞬移`。
- 正确写法：`自动门向两侧滑开，她迈步走入`。
- 自检：全文检索"不是/不要/非/无"等由反馈衍生的否定标注，一旦出现一律删除，改写为正向动作。（注意 NEG 负面约束里的"不要X"是给模型的技术性禁令，属正常内容；此条针对的是由用户反馈衍生、解释"我改了什么"的否定标注。）

### PUR-05 自检方法
写完逐句读一遍，凡是不属于画面/声音/风格的实际内容（任何"原因、修正记录、备注、括号解释"）都删掉。

### PUR-06 提示词自包含原则（无关内容禁令，与角色资产 CAP-10 / 场景资产 PRM-08 同源）
**无关内容的定义：单看提示词本身无法理解的内容，就是无关内容。** 视频模型只能看到本提示词块——它不认识角色名/场景名/资产编号/镜头文件。四类典型禁入：
1. **外部资产引用**：`如《符号设计图 §M1》所示`、`按 母题索引 灰石母题`、`保持 莱拉-原始 形象`——模型拿不到这些文档。→ 改写为**画面直接自描述**（符号/服饰/环境形态写全）。
2. **名字标签**：`莱拉·原始外观`、`凯尔-战损` 作为纯标签——模型不认识这些名字。→ 身份与资产用描述性语言；资产锚定靠工具里 @ 参考图（操作不进正文）。
3. **工具操作指令**：`@参考图`、`参考 城堡-C 的图`——@ 哪张图是用户在工具里完成的动作，不是画面内容。→ @ 写在块外说明。
4. **文档内部交叉引用**：`见第3段`、`同上一版`——块内没有章节概念。

**自检**：逐句问"单看这一句，模型能理解吗？"——不能 → 删或改写为自包含描述。此条与 FMT-01/02（无题头/无分隔线）、PUR-03/04 同属"提示词是可独立投喂的成品文本"总原则。

### PUR-07 代码块内禁止排版标记与编辑沿革（硬性）

**提示词代码块是"整块复制粘贴"的载体，块内的字符全部会被送进模型。** 因此块内必须是纯提示词正文，两类东西一律清除：

**① 排版标记**：`**加粗**`、`*斜体*`、`> 引用`、`# 标题`、"—— 重点 ——"这类给阅读者做的视觉强调。模型不认 Markdown 强调语法，它们只是被当成普通符号或噪音塞进上下文。
- 错误：`拖布杆的金属端头**已经**插进插销，**不拍她走过来的过程**`
- 正确：`拖布杆的金属端头已经插进插销，不拍她走过来的过程`
- 注意：**代码块之外**（文件标题、说明区、衔接锚点区）的加粗不受此限——那里本就是给人读的，加粗是功能性的。

**② 编辑沿革**：`（替换原"僵持两秒"）`、`（上一版是…）`、`（已删除…）`、`（新增）`、`（修正为…）`这类"我改了什么"的痕迹。它们属于 PUR-03/04 的元信息，只是**藏在了括号里、混在正文行内**，比整句元信息更难被自检发现。
- 错误：`第四拍（替换原"僵持两秒"）：那扇门极缓慢地回位了半寸`
- 正确：`第四拍：那扇门极缓慢地回位了半寸`

**为什么容易漏**：写作者在一轮轮修改中，会顺手把"这次改了什么"标注在原地，既方便自己回溯，也向用户证明改到了——但这些标注落在代码块内就变成了模型要读的内容。**修改痕迹一律写在块的说明区（块外）或变更记录里，不写在块内。**

**自检**：对每个代码块做两次检索——(a) 搜 `**`；(b) 搜 `替换原|上一版|已删|新增|修正|改为`。任一命中即不合格。
**机器校验**：`scripts/verify_integrated.py` 会在比对整合文档与分文件时暴露块内差异，是发现这类残留的有效手段（两侧若都带标记会一致通过，故仍需人工做上面的 (a)(b) 检索）。

## 特定场景措辞速查

### SCENE-01 深空/黑暗场景措辞（重要）
避免写"纯黑""死黑""全黑"——AI 会照字面把画面做成死黑一团：
- 宇宙场景要**先说清光源**：主光源方位与色温（如左上方恒星/星光，冷蓝或冷白）、次要光源（星云辉光、空间站自身能源光、远处星系光）。
- 阴影面/背光面写**相对暗**而非"黑"：用"深蓝/暗灰、仅透出微弱轮廓光、背光侧保持低照度"，明确仍有环境光存在。
- 由暗转亮必须写"视角/自转转到受光面"：空间站自转或摄影机绕行使受光面转进画面——不是画面整体变亮。
- 负面约束里锁"不要全局变亮/死黑"。

### SCENE-02 巨型结构尺度表现
表现"空间站/巨型建筑巨大"时，画面主体是机甲/飞行器，不能靠"缩小飞行器"来衬托（会让飞行器不自然），而是靠**放大空间站**：
- 让摄影机跟随机甲由远飞近，空间站逐渐放大；到环绕侧面时，画面中**只剩空间站局部**（某面外环结构侧面、某条能源带、某个机库门）占满画面，机甲贴着站体边缘飞——局部本身就巨大，观感才真实。
- 物理合理性：若空间站从远景快速放大到占满画面，会显得飞行速度异常。解法：**镜头可从"空间站已占较大画面"的状态开始**——不去展示完整全貌，"全貌"合理化为"展现一角"即可（因为巨大，一角即全貌感）。
- 尺度对照用相对参照写进画面内容：环形结构厚度远大于机甲长度、机库门高度是机甲数十倍、能源带宽度大机甲一个数量级。
