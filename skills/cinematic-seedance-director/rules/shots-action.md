# 规则模块 R4 — 镜头块、动作与表演

> 总控在 Stage S4 读本文件。结构模板详见 references/PROMPT_PATTERNS.md §3.4–§3.6。规则编号 SHOT-/PERF-/ENV-/ACT-/CAM-/POV-/NEG-*。

## ★ 镜头行格式（SHOT-00，最高优先级，用户 2026-10-15 明确要求）

用户要的是**可直接复制的五/六行一镜制**，不是七要素长段。**交付给用户的每一镜，
顶部必须有一行镜头行**，格式固定六段、顺序不可换：

```
镜头：中景 ｜ 四分之三侧面 ｜ 50mm T4.0 ｜ 平视 ｜ 固定 ｜ 视觉效果真实
语气：……
微表情：……
微动作：……
台词：……
```

### 六段取值表（硬性）

| 段 | 取值 |
|---|---|
| **① 景别** | 特写（大特写／近特写）｜ 近景 ｜ 中景 ｜ 中远景 ｜ 远景 |
| **② 人物角度** | 正面 ｜ 侧面 ｜ 背面 ｜ 四分之一侧 ｜ 四分之三侧 ｜ 三分之二侧 ｜ 侧后 ｜ 过肩 ｜ 前景遮挡（门框／柱子／帘子／玻璃／人群，写具体） |
| **③ 焦段光圈** | 85mm T2.0 特写 ｜ 50mm T2.0 近景 ｜ 50mm T4.0 中景 ｜ 100mm T2.8 大特写 ｜ 24mm T4.0 远景 |
| **④ 视角** | 平视 ｜ 俯视（必带角度：15°／30°／45°，垂直俯拍要写明）｜ 仰视 ｜ 鸟瞰 ｜ 定时 ｜ 第一人称 POV 主观视角 ｜ 过肩视角 |
| **⑤ 运镜** | 固定 ｜ 推 ｜ 拉 ｜ 摇 ｜ 移 ｜ 跟 ｜ 升降 ｜ 手持（动态镜必带速度+幅度，如「匀速横移 10% 画幅」） |
| **⑥ 视觉效果** | 视觉效果真实 ／ 视觉效果真实带电影感调色 |

分隔符统一用 `｜`（全角竖线），前后各一个空格。

### SHOT-00a 竖屏 9:16 景别默认（P1/P2 管线）
特写=情绪｜ 中近景=对话 ｜ 中景=动作 ｜ 中远景=空间 ｜ 远景=环境。
焦段与景别的绑定关系是硬约束：**特写必长焦浅景深（85mm T2.0 以上）**，
用广角拍特写会变成手机随拍；**远景/对切硬对撞用 24mm T4.0**。

### SHOT-00b 对切段镜头行必须同参数
A/B 两侧景别、焦段、视角、运镜速度幅度四项全部一致，唯一变量只能是画面内容与色温。
观众先注意参数差异，就看不见内容对比了。

### SHOT-00c 俯拍必带角度
写「俯视」而不给角度等于没写。15° 俯角能同时看到「动作往下走」和「落点」两个信息；
45° 用于手部/桌面微细节；90° 垂直俯拍会把动作压平，除非刻意要平面感否则避免。

### SHOT-00d 视觉效果是投喂锚点，不可省
第⑥段是模型的画质锚点词，省掉会让生成结果偏插画/偏塑料。

## 表演四栏（PERF-00）——⚠️ 已废止，表演必须写成整段

**用户 2026-10-15 两次返工的最终结论：不要分栏，要整段。**

曾按「语气／微表情／微动作／台词」四栏交付（第五集 54 镜改过一次、第七集 47 镜改过一次），
**用户两次反馈"语气和微表情没有"、"表演怎么没有"**。根因：

1. **分栏后信息被切碎，投喂时模型只抓得到最大那块**（通常是"微动作"里的
   「拉开椅子」「拍腿」这类大动作），语气与微表情两栏整段被忽略。
2. **栏目标签本身是给人看的，不是给模型看的**。`语气：` `微表情：` 这些前缀对
   模型是噪音，模型要的是一段连续的、自然语言描述的画面。
3. **投喂场景是整段复制粘贴**——用户复制一段丢给模型，栏目标签留在文本里只会占字数。

### PERF-00 ★ 正确格式：逐镜三行制

```
▸ K-XX-X-XX（X.Xs）
镜头：景别 ｜ 人物角度 ｜ 焦段光圈 ｜ 视角 ｜ 运镜 ｜ 视觉效果真实
表演：<一整段自然语言：动作 → 微表情（带顺序）→ 语气（挂在具体字上）→ 光影环境 → 声音>
台词（角色·语气）：逐字照念
```

**表演段的目标长度 80–220 字**。低于 60 字说明没写开，高于 250 字说明该拆镜。

### PERF-00a 表演段内部顺序（硬性）
按这个顺序写，读起来才顺，模型抓取优先级才正确：
1. **动作** —— 用「→」串起完整弧线，每个动作有落点，不要「动了动手」这种半截动作
2. **微表情** —— 写肌肉（见 PERF-01），**必须带顺序与失败态**
3. **语气** —— 挂在具体台词字上（见 PERF-00e），不写「他语气诚恳」，写
   「说到『凑不齐』三个字说得慢，中间一次明显的停顿」
4. **光影/环境** —— 与人物表演有因果关系的那一条（如「灶火窜上来打在他侧脸上，
   那道火光让他的脸一半暖橙一半阴影——他自己不知道」）
5. **声音** —— 无台词镜尤其重要（见 PERF-00c）

### PERF-00b 微表情要写顺序，也要写失败态
不只写「先眼睛后眉毛」，还要写「顺序反了就变成演的」「差得多像笑出来了，差得少就剩一个平脸」。

### PERF-00c 无台词镜也要给声音
写清楚是呼吸、喉音、鼻音、爆炒声、排风扇还是环境声。
**安静的镜头不等于没有表演**——转折点往往全在无声的那几秒。

### PERF-00d 内心 OS 镜不做说话口型
明确写「嘴唇完全不动，只有气」，并写清 OS 镜的气口要比台词镜浅一半、短一半。

### PERF-00e 语气五要素 + 气息位置是隐藏主线
音量 / 语速 / 音高走向 / **气息位置（胸腔／喉咙／鼻腔）** / 尾音与停顿。
> 气息位置按角色分层写：反派气在胸腔上方（油亮轻）、主角服软时气托胸腔往上飘（讨好）、
> 摊牌后压到喉咙（平不托腔）、女声线人后段落回胸腔。同样的字，位置一换就是两个人。
> 同一句话在不同场景的说法要分开（字面一样，语气完全两样）。

### PERF-00f 给出「不要什么」
「明确写眼睛完全不参与」「不要任何多余表情，眼神不要乱飘」「嘴上的笑没了，
眼睛里的东西才刚到位」——比只给「要什么」更有效。

### PERF-00g 多人对戏：各走各的线，不要互相带
一张桌上几个人就有几条情绪线，各自独立推进，并显式提醒「不要让所有人演成同一种情绪」。
同时点明「谁是需要真实反应的那个人」——观众要有一个可信的反应者，才敢相信其他人都在演。

> **交付教训**：用户要的是**可以直接复制粘贴投喂模型的成品文本**，
> 不是给人审阅的分析表格。凡是需要用户自己再拼装/再翻译成提示词的中间产物，
> 都是交付失败——判据很简单：**用户复制一段就能用吗？**

## 镜头块七要素（SHOT-01）

每个【镜头N】必须包含：
- **机位** — focal length + aperture + shot type + camera type (handheld/static/dolly)
- **构图** — composition rule (三分法/对称/框中框/引导线/负空间/前景遮挡/纵深调度) + subject placement + background description
- **景深** — aperture + depth type + what's sharp / what's blurred
- **拍摄角度** — eye level / low angle / high angle / Dutch tilt (with degree if specific)
- **摄影机运动** — movement type + speed + direction + emotion sync
- **动作** — step-by-step character action with numbered beats (① ② ③) for arcs
- **微表演细节** — physical micro-events

### 输出格式（硬性，可读性）
每个【镜头N】按标签逐行书写——`机位：`/`构图：`/`景深：`/`拍摄角度：`/`摄影机运动：`/`动作：`各自独立成段（对白、表演等用 ⚠️ 前缀独立行），镜头间用 `⚠️约X秒后——硬切至镜头N。` 衔接。**禁止把镜头要素挤成一段连续文本**——挤成一段难以校对、易漏要素。

### SHOT-02 镜头参照锚点（硬性）
机位/构图/拍摄角度必须给出**画面内参照**——以角色或物件为基准（"从艾琳贴地仰视的视角""以婴儿床为前景参照""从马库斯高领背影处拍向门"），禁止只写"低角度仰拍""机位在东侧"这类无锚的抽象描述。写 POV 时，POV 源头角色本身就是参照，须写明该角色此刻的姿势与位置。

### SHOT-03 段首状态继承（硬性，拆多段时）
段首镜头必须重述上一段结尾各角色的精确姿势+位置+起始表情（以场景要素为基准、不写段编号）。例：上段结尾"艾琳右手撑地、侧身抬头看向马库斯"，本段首镜写"艾琳保持右手撑地、侧身抬头的卧姿，位于婴儿床旁，仰视马库斯"。段中镜头若某角色状态与段首一致，不重复声明。

### SHOT-04 首镜起始表情（硬性）
段首镜头（及每段各角色首次入画的镜头）必须显式写明该角色的起始表情（由当下情绪推导，见 spatial-assets.md SPAT-02），写入该镜的"动作/微表演"行。例：6-2 街道闲逛，塞拉首镜即写"眉梢微抬、目光好奇地追视两旁新奇建筑与滑板"。禁止首镜留中性脸、等后续镜头才补表情。

## 表演指导（PERF-*）

### PERF-01 微事件替代标签
写导演的核心创作输出：把情绪指令分解为**物理微事件**，绝不使用笼统标签（如"看起来悲伤"）。情绪→身体微事件目录见 reference/quick-ref.md §1 与 references/PROMPT_PATTERNS.md §3.5。

### PERF-02 表演弧线
每段表演弧线至少 3-5 拍（萌芽→积聚→释放→余波），不要只给 1 拍。避免只写"震惊、愤怒、自信"等结果，优先写：**刺激 → 判断 → 身体反应 → 眼神/呼吸 → 决定 → 新动作**。

### PERF-03 起始表情先于弧线（硬性）
写表演弧线前，先按角色当下处境确定**起始表情**——它是整段表演的基线。起始表情必须落进该角色首镜的微表演行，写明眉/眼/嘴角/呼吸的具体微事件（quick-ref.md §1 取用），不能只写情绪词。基线确定后，弧线的"积聚/释放"才有对照物。

## 环境活动（ENV-01）

有人的场景禁止空背景——写背景中角色/环境在做什么（模板见 PROMPT_PATTERNS.md §3.6）。安静场景写"完全寂静"的缺席感。

## 动作因果（ACT-*）

### PERF-04 在场角色收尾义务
- 每个被写出场的角色（含背景配角）在场景结束前必须有交代：让位／跟随／退下／继续手头动作，至少其一。
- 台词说完就"消失"的配角，生成视频中会原地呆立到镜头结束。典型补法：拦路者在引路者经过后"收械让开道路"，旁观者"交换眼神转向别处"。

### PERF-05 亲密接触进度保真（硬性）
- 欲吻／将触未触／轻触／相拥／完成之吻，是不同等级的关系资产；改写时接触等级只允许与原作一致或经用户明确指令升级，禁止无意升降级。
- "想要吻她"≠"吻到了"：未完成动作必须保留未完成性（唇将及未及、被推开于接触之前），否则后续的拒绝戏在逻辑上不成立。

### ACT-01 高风险动作六步链
**准备 → 触发 → 接近 → 接触/未接触 → 结果 → 残留状态。**
- 格挡必须明确发生在命中之前。不要只写"即将命中时挥刀"，要写："飞行物仍与身体保持清楚可见距离时，她已经判断轨迹并挥刀，刀刃先接触飞行物，随后飞行物破碎。"
- 反震要明确："刀锋先接触法场并停滞，随后法场才反震。"同时动作要明确"同步发生"。

### ACT-02 多人战斗（最高优先级）
- **格挡/对撞必须给攻击方一个物理结果**：格挡后攻击方要被反震弹飞/震退/扑空转势，不能停在原地看戏。攻击方与防御方的后续动作**成对写、缺一不可**。
- 动作戏中每个在场角色都必须有"做完这个动作之后去哪/干什么"的交代，否则 AI 会让该角色呆立。
- 攻击动作三要素齐全：蓄力（抬手/拧身/压低重心）→ 朝向与发力（朝她肩头/当头/喉咙抓落）→ 结果（命中否/被挡开→被弹飞/震退）。缺朝向或缺结果的攻击 = 无效攻击。
- 攻防交换至少两个来回才算一场打斗；防御后下一镜必须交代攻击方的后续。

### ACT-03 微动描写会被模型忽略

- "探向""变位躲开""稍微侧身"这类小位移描述，实际生成≈没动。
- 解决办法：**给足位移幅度**（扑击/翻滚/跃出/前扑/滑退数步），或**并入一个更大的动作里**，别单独依赖微动来表现。
- 连续攻击（如三度扑击）要给每次攻击**不同的轨迹 + 不同的收势 + 不同的闪避动作**，否则 AI 会复制同一种动作。

### ACT-06 工序缺失：只写结果不写过程（硬性，2026-10-15 用户提出）

**症状**：剧本写「一盘菜端上桌」「茶递过去」「伤口包好了」，分镜就只拍到端上桌、
递出去、包好——**中间那道工序凭空消失**。

**为什么必须补**：结果镜头给不了信息量。观众看着一盘菜从锅里出来，
但没看见菜怎么进的锅——**爆炒的力、火的能量、厨师的熟练，全在那一下里**。
缺了它，烟笋烧肉就只是一盘菜，不是一道手艺。

**判定**：凡涉及「制作/烹调/装配/交付/处理」类动作，若原稿只有起点和终点，
**必须在两者之间插入一镜工序特写**。

**工序镜四要素（一镜之内给完，例：抓食材下锅爆炒）**：
1. **抓／取** —— 五指张开，指节收拢时物件是被握住不是被攥烂（看得出专业还是业余）
2. **送／移** —— 手腕送出，物件越过临界点（锅沿／台面边缘／模具口）
3. **落／合** —— **在临界点前一点松手／合拢，让它自己到位**。
   例：离锅沿三厘米时才松手让食材自己落进去——**不能像倒垃圾一样撒**，
   撒进去的是生的、散的；自己落进去才是厨师的手。
4. **爆／反馈** —— 作用发生（油锅炸开、蒸汽窜起、锁扣咬合），并让手**往后撤让开**

**技术选择默认值**：
- 焦段 **85mm T2.0**：必须长焦浅景深，背景虚化成光斑，用广角会变成手机随拍
- 俯角 **15°**（不是垂直俯拍）：垂直俯拍把动作压平成面；15° 能同时看到动作方向和落点
- 机位**固定**：这一镜不能动，动作本身够满了，机位再动就抢

**声音**：工序发生的那一声（「呲啦」「咔哒」「哗啦」）要顶起来。
它是观众第一次听见「这家店真的在做这件事」的证据，比任何画面都管用。

### ACT-04 运载工具的"移动采集"机制（硬性）

当剧本要素是**"交通工具在移动中完成采集/吸收/收纳"**（如鬼车沿途自动吸素材、飞行器扫过收集物、船行中水下渔获自动入舱）时，**主体必须是"载具本身"**，不是乘员用手去抓。

**错误写法（2026-09-10 第十集原稿）**：写"宋末坐在车里，探身快速将手伸出车窗外，指尖对准街边灰影"——把"鬼车的自动采集特性"降级成了人的手动操作，丢掉了核心奇观。

**正确写法三要素**：
1. **载具高速运动**：明写"高速飞驰／疾驰／窜出"，给速度感（广角低角度跟拍、同速横移、路边景物拉成流动光带作构图要素）。
2. **载具是吸收器**：车身/舷侧形成**半透明吸附场**（描述为能量场，不是实体光束），沿途目标被"自动、连续、一串串"卷进来；不用乘员伸手。
3. **乘员坐享其成**：乘员只需侧身、抬手**轻轻一引**（可省略），主要反应是"从容愉悦 + 看着面板刷屏"。

**配套负面约束（必加）**：`禁载具静止或缓慢蠕动`／`禁乘员手臂伸出窗外去抓取`／`禁用手一个个抓取`／`禁目标停顿在路边不动`／`禁把吸附场画成实体光束或激光`。

**车体外镜头禁用"固定镜头"**：载具飞驰段的机位运动必须是"与车同速前进/横移/后拉/前推"，否则动静错位。

## 镜头编译（CAM-01）

每个镜头至少包含：镜头编号/时间 / 是否连续镜头 / 摄影机相对人物位置 / 高度 / 焦段镜头观感 / 景别 / 人物画框位置 / 世界方向 / 人物动作 / 摄影机运动 / 摄影机运动触发原因 / 镜头结束状态与动作切点。

摄影机运动应由声音、视线、人物运动、特效范围或注意力变化触发。避免无意义横移、环绕、旋转、随机推拉。连续镜头允许阶段变化，但原则上一个镜头只有一个主要摄影行为。

## POV（POV-01）

- 切入 POV 时写："普通切镜。切镜后的第一帧已经是XX双眼所见的第一人称画面。"
- 禁止表现摄影机进入眼睛、瞳孔穿越或客观镜头逐渐变 POV。
- POV 中摄影机主人自己的脸、头部和完整身体不得入画。手臂出现必须与身体连接。摄影机高度必须匹配站立/跪地/躺倒状态。

## 失败模式警告 + 负面约束（NEG-*）

预判 Seedance 会错的地方。用 ⚠️ 标重要、⚠️⚠️⚠️ 标关键（模板见 PROMPT_PATTERNS.md §3.8）。

### NEG-01 固定负面项（每段必含）
不要字幕 / 不要旁白文字 / 不要logo / 不要水印 / 不要UI；默认不要BGM（除非用户明确要求配乐）；用户未要求慢动作时加"不要慢动作"。

### NEG-02 重点锁定清单
负面约束重点锁当前最容易失败的内容：数量、左右方向、轴线、POV、伤势、接触先后、武器复制、特效替代、镜头数量、慢动作、错误人物行为、场景复原、参考图错误继承。关键规则可正向写一次，再反向锁一次。

### NEG-03 镜头数量表述（禁止写死锁）
**不要**写"严格包含N个镜头——禁止增加或减少"这类死锁措辞。它会把镜头数焊死，导致后续想加镜、或发现某个镜头不合理要替换时，反而被自己写的提示词捆住。
正确写法：把镜头数声明为**参考节奏**，并显式授予 AI 有限自由——
`⚠️本段共N个镜头（参考节奏，非强制）。允许在不改变剧情走向、对白内容与人物形象的前提下，根据实际生成效果灵活拆分、合并或替换镜头。特别地——当某句台词过长、或画面内容过于呆板缺乏变化时，鼓励自行增补反应镜、特写或过渡镜，让节奏更自然；若某个镜头不合理，可直接用更合适的机位与构图替代。硬性限制只有一条：总时长不得超过本段标注的时长，且不得删改台词与系统面板文字。`

**授权边界（必须同时锁死）**：① 总时长不可超本段标注值；② 台词与系统面板文字不可删改；③ 人物形象/身份不可漂移；④ 不得改变剧情走向与空间关系。
（`scripts/validate_prompt.mjs` 的 P6 会校验"声明的参考镜头数"与 `【镜头N】` 块数一致；若正文实际增删镜头，应同步更新该数字或直接删去该句。）

### NEG-04 天体光源词禁令（硬性）
- 描述能量/效果光时禁用"月光/阳光/日光"等天体光源名词——模型会把光源实体化，画面平白多出月亮或太阳。效果光一律写自发光："银白色光晕／冷白微光／金色辉光"。
- 场景确需真实天体入画时，直接写天体本体（"满月悬空"）；环境照明写"清辉洒落"，且不得把该清辉再用作能量来源的喻体。
