# 规则模块 R2 — 估时与拆段

> 总控在 Stage S1/S2 读本文件。规则编号 TIME-*。计算类工作优先用脚本 `scripts/estimate_timeline.mjs`，AI 只做复核与创意调整。

## TIME-01 估时公式（按管线语言口径）

**按表演+台词估时，不是按剧本段落硬塞。** 先逐镜估算：

```
单镜时长 ≈ 表演动作量（每个动作约 1-2 秒）
         + 台词（P1-P3 中文：字数 ÷ 中文语速；P4 英文：词数 ÷ 2.5 词/秒）
         + 空间移动 + 停顿
```

**中文语速基准（P1-P3）**：

| 管线 | 语速 | 说明 |
|---|---|---|
| P1 下沉中老年 | **3.5 字/秒** | 节奏慢、情绪重、留停顿，观众需要消化时间 |
| P2 女频恋爱 | **4.0 字/秒** | 正常偏舒缓，留氛围 |
| P3 女频恐怖 | **4.0 字/秒** | 惊吓前可提速到 5 字/秒制造压迫 |
| P4 海外英文 | 2.5 词/秒 | 沿用原出厂值 |

内容需要多久就估多久，禁止为了"填满上限"把整段剧本压缩进去。

### 脚本用法（首选）

```powershell
# P1-P3 国内管线（2.0 / 段上限 15s）
node <技能目录>\scripts\estimate_timeline.mjs {剧本目录}\pipeline\01_拍点表.json --model 2.0 --out {剧本目录}\pipeline\02_时间轴.json

# P4 海外管线（2.5 / 段上限 30s）
node <技能目录>\scripts\estimate_timeline.mjs {剧本目录}\pipeline\01_拍点表.json --model 2.5 --out {剧本目录}\pipeline\02_时间轴.json
```

- **段上限由 `--model` 决定，不要传 `--max-seconds`**（脚本 `parseArgs` 只认 `--model` / `--out`，多传参数直接 `ERROR: unexpected argument`）。2.0 → 15s，2.5 → 30s（30–31s 可压缩）。
- **估时口径按台词语言自动二选一**（脚本原生支持，无需改造字段）：
  - 有 `dialogueEn` → 词数 ÷ `defaults.speechRateWps`（默认 2.5 词/秒），`unit` 输出 `words`。
  - 只有 `dialogueZh` → 汉字数 ÷ `defaults.speechRateCps`（P1 3.5 / P2-P3 4.0 字/秒），`unit` 输出 `chars`。标点、空白、英文字母不计入汉字数。
  - 两者都有时**英文优先**。
  - `defaults.speechRateCps` 默认值 3.5；英文与中文语速可在同一份 `defaults` 里并存，互不干扰。
- `hardBreakAfter` 里给出的拍点必定成段，可用它强制段落落在剧情断点上。

输入 `01_拍点表.json` 结构（AI 在 S0 解析后生成）：

```json
{
  "defaults": { "speechRateWps": 2.5, "speechRateCps": 3.5, "actionSeconds": 1.5 },
  "beats": [
    {
      "id": "b01",
      "speaker": "姥姥",
      "dialogueEn": "Don't thank me. You were supposed to be there.",
      "dialogueZh": "不用道谢，你本来就该在那。",
      "actions":  [{ "desc": "撑地起身", "seconds": 1.5 }],
      "moves":    [{ "desc": "穿过客厅", "seconds": 3 }],
      "pauses":   [{ "desc": "迟疑", "seconds": 1 }]
    }
  ],
  "hardBreakAfter": ["b03"]
}
```

- 每拍秒数 = 词数÷语速 + Σ动作 + Σ移动 + Σ停顿，四舍五入到 0.1s。
- `hardBreakAfter` = 剧情自然断点（强制在此拍后切分段落）。
- 输出 `02_时间轴.json`：分段结果、每段估算/计费秒数、是否需收尾镜、超限警告。
- **脚本是初稿**：AI 必须复核分段点是否落在剧情断点上、动作量估计是否合理；创意性调整直接改拍点表后重跑脚本，不手改时间轴 JSON。

## TIME-02 段上限（硬性，按管线 PP-01）

| 管线 | 模型 | 段上限 | 目标区间 |
|---|---|---|---|
| P1 / P2 / P3 | 2.0 | **≤15 秒** | **12–15 秒（硬性，PP-01）** |
| P4 | 2.5 | ≤30 秒 | 估算 30–31 秒可压缩进 30 秒算一段；超过 31 秒才按剧情自然断点拆成多个 ≤30s 独立段，每段各自估时、各自 ≤30s |

- 国内管线：**每段必须落在 12–15 秒**，无例外（含过场段）。不要故意逼近 15 秒上限——在区间内选"内容刚好说完"的秒数，宁可 13 秒干净收尾，不要 14.9 秒拖沓。
- 若中文台词量算出来超过 15 秒 → 按剧情断点拆段，不要压缩语速硬塞（下沉市场观众听不清 = 流失）。
- 段数由**内容量**决定，不由"某段该给几秒"决定：`段数 ∈ [ceil(总内容量/15), floor(总内容量/12)]`（详见 TIME-02b）。**不存在"过场段可以低于 12 秒"的做法**（旧表述已废弃）。

## TIME-02b 每段必须落在 12–15 秒（硬性）＋ 内容量决定**段数**

**用户长期硬要求（最高优先级，覆盖本文件其他时长表述）**：

> **每个分镜组（每段提示词）的时长必须落在 12–15 秒之间。**

这条要求**高于**"时长匹配内容量"的直觉。内容量不是用来决定"某段给几秒"的，而是用来决定**整集切几段**的：

```
段数下限 = ceil(总内容量 / 15)      段数上限 = floor(总内容量 / 12)
```

例：第10集总内容量 170.7 秒 → 段数 ∈ [12, 14] → 取 13 段，每段 12–15 秒自然成立。

**事故教训（2026-09-10，《我，编剧，灵气复苏》第10集，两轮）**

- **第一轮（摊派）**：17 段一律填到 12–14.5 秒，导致剧本只有一句话的过场段拿到 3 镜 12.5 秒，核心捕捉戏反被挤压。
- **第二轮（过度压缩，用户直接纠错）**：为把整集压进"两分钟"，把过场段砍到 5 秒、7 秒，**违反 12 秒下限**。用户原话：

> 「你又忘了我的要求，每个分镜组应该在12秒到15秒之间」

**正确做法（强制）**

1. **每段 12–15 秒，无例外**——包括过场段。"过场段可以压到 4–6 秒"是**错误做法，已废弃**。
2. **段数由内容量决定**，公式见上。内容量不够支撑足够段数时，**是去补内容（拆大拍点、细写动作与面板），而不是把段压短**。
3. **禁止为凑总时长而削减动作秒数**。动作秒数必须反映真实表演量（2–4 秒/拍），不能为了"总时长达标"被砍到 1 秒——这会把内容量算假，进而逼出错误分区。
4. **台词与动作是并发关系，不是串行**：一个角色"边说边走位/边做动作"时，该拍时长 = `max(台词时长, 动作时长)`，**不是相加**。相加会把"边说边做"重复计时，整集虚增（第10集虚增约 45 秒）。
5. **面板文字每条至少 0.6 秒可读时间**，且**一条都不能删**。用户指定总时长上限时，先砍过场铺陈的文字密度，最后才动台词与面板。

**自检问题（定稿前逐段问一遍）**

- 这一段是不是 12–15 秒？不是就重排，别交。
- 整集段数是否等于 `round(总内容量 / 13.5)` 左右？差太多说明切分粒度不对。
- 我的动作秒数有没有为了"好看的总时长"被人为压小？

## TIME-02c 段数不可行时的处理顺序（禁止偷偷越界）

装箱求解（`build_split.mjs` / `pack*.mjs`）返回"无解"时，**必须按以下顺序处理**，不得直接把段压到 12 秒以下：

1. **调拍点粒度**——把跨不过去的长拍点按语义断点拆细（这是 90% 无解的根因：某拍 8–12 秒，既不能单独成段，又加不上任何邻居）。
2. **合并过短拍点**——把 <3 秒的碎拍并进相邻同情绪拍点。
3. **微调动作秒数**——在真实表演量范围内（±1 秒）修正个别拍的时长，使窗口闭合。
4. **最后**才考虑与用户确认是否放宽区间。

**跨场次禁并段（RT-07-3）优先于"凑满 12 秒"**：如果某场次内容量不足 12 秒，必须与用户确认该场是否独立成段，**不得为了满足 12 秒下限而把两场不同空间的戏并进一段**。

## TIME-03 禁止硬塞 / 禁止注水

- 不要用镜头数量直接推时长。时长由动作量、对白、空间移动、停顿和模型可读性决定。
- 如果有效动作不足以占满目标时长，模型可能用慢动作、重复、无意义停顿或延长运镜填充。宁可先选略紧凑的合理时长，不要为了"电影感"盲目拉长。
- 用户未要求慢动作时：风格段写"正常速度"，负面约束写"不要慢动作"（见 shots-action.md NEG-01）。

## TIME-04 时间码粒度

- 2.5 默认使用：`镜头XX｜起始—结束秒`。时间码是节奏约束，不是动画关键帧表。
- 只有高风险连续镜头才进一步写内部时间段。

## TIME-05 拆多段的连带义务

拆段决定定稿前必须同步确认：
1. 每段写清所有仍出画人物的站位（continuity-state.md SPLIT-01）；
2. 每段各自以可切点收口（continuity-state.md LINK-02）；
3. 以台词结尾的段各自配独立收尾镜（continuity-state.md CLOSE-01，脚本已自动标记 `needsClosingShot` 并预留 0.75s 缓冲）；
4. **每段 ≥5 秒的镜头按 `**0-2秒：**/**2-5秒：**/...` 时间窗切分**——见 `camera-motion.md` CAM-08 时序分段编排，单段不超过 3 个时间窗，标签与本段时长包络一致（P1-P3 每段 ≤15s、P4 每段 ≤30s）。

## TIME-05b 台词守恒（硬性，防漏台词）

**事故教训（2026-09-10，《我，编剧，灵气复苏》第10集）**：拍点 `10-1-b10`（宋末：「天亮了。」）在并合进段落时，其 `actions.desc`（"宋末身形飘进房间"）被写进拆段表 beats，但 `dialogueZh` **本体被覆盖丢失**——台词既没进拆段表、也没进提示词配音指令与台词表；连带 `endsWithDialogue` 误判为 `false`，该段漏配 CLOSE-01 收尾镜。**这是不可接受的交付事故。**

**两条硬性规则**：

1. **拍点并合时，`dialogueZh` 与 `actions.desc` 必须都保留**。拆段表的 beats 数组里，凡拍点有台词的，必须出现该台词的文本（可加 `台词：`/`台词（角色）：` 前缀），**禁止只留动作描述而丢掉台词**。一个拍点既有动作又有台词时，写成"动作，台词：xxx"或拆成两条 beats，但台词不得消失。
2. **`endsWithDialogue` 必须与实际台词位置一致**：段落最后一条 beats 是台词时必为 `true`，否则 CLOSE-01 不会触发，段尾会缺收尾镜。

**强制校验（S2 出口与 S5 出口各一次）**：

```powershell
node <技能目录>\scripts\check_dialogue_coverage.mjs ^
  --beats {剧本目录}\pipeline\01_拍点表.json ^
  --split {剧本目录}\pipeline\03_拆段表.json ^
  --prompts {剧本目录}\outputs
```

- **门1（S2 出口）**：拍点表所有非空 `dialogueZh` 必须 100% 出现在拆段表 beats 中。缺失即停，禁止进入 S3。
- **门2（S5 出口）**：每条台词必须出现在归属段提示词的 `【配音指令】` 中（**只认配音指令块，不认动作描述里的重复文本**——否则删掉配音指令也会误判为已覆盖）。
- **配音指令是"块"不是"行"**：`【配音指令】角色｜音色｜状态｜语气：` 只是标题行，真正的台词在**下一行** `台词：xxx`（OS 为 `【内心独白】台词：xxx`）。脚本按块提取（标题行 + 紧随的台词行）；只看标题行会导致门2 全量假阴性——2026-09-10 踩过。
- 退出码 0 才算通过；1 = 有遗漏，按报告补齐后重跑。
- 长台词被合法拆给多段/多镜时脚本按窗口命中率判定（阈值 70%）+ 断点容忍，不会误报；整条丢失则命中率≈0，必然抓出。
- **交付前必须做一次"删除回归"**：随便删掉一条配音指令的台词行，确认脚本报错；若仍显示通过，说明匹配逻辑被旁路（例如动作描述里有相同文本），是假阴性，必须修脚本。

## TIME-06 每段镜头密度参考

**国内管线（P1-P3，12-15s 段，PP-01）**：

| 镜头数 / 15s | 类型 | 适用 |
|---|---|---|
| 1 | 长镜头一镜到底 | 情绪戏、对峙、独白 |
| 2–3 | 标准覆盖 | **P1/P2 主力密度**（下沉市场看得清） |
| 4–5 | 快速切换 | 冲突升级、高潮前置 |
| 6+ | 蒙太奇 | 转场、信息压缩（P1 慎用，下沉观众跟不上） |

**P4 海外管线（30s 段）**：
- 1 shot / 30s：single-shot long take（Lubezki-style immersion）
- 2-3 shots / 30s：standard scene coverage
- 4-6 shots / 30s prompt：rapid action / climax sequence
- 7+ shots / 30s prompt：montage / explosive sequence

**镜头密度的下限换算**：上表按 15 秒标定；国内管线最短段为 12 秒（PP-01/TIME-02b），按比例折算仍是 **2–3 镜**（P1/P2 主力密度）。不要因"内容少"把段压到 1 镜或堆到 5 镜以上——过场段镜头越多，每镜越碎、越像"素材堆积"。

## TIME-07 拆段与并段的对偶（TIME-02b 的配套操作）

TIME-02b 要求"时长匹配内容量"，落地手段有两个方向：**拆**（内容多、超上限）与**并**（内容少、碎段多）。

**RT-07-1 何时拆**：台词量按字/秒算出来超 15 秒 → 按语义断点拆。长台词优先按"换气点 / 信息层级"拆成两段（如 94 字台词拆成"试探 45 字 + 央求 37 字"），**不要按字数机械对半**。

**RT-07-2 何时并**：多个相邻拍点各自都很短（<6 秒）、且属于同一场戏同一情绪线时，应并成一段。碎段并合的好处：
- 少一次段间转场、少一次收尾镜 0.75 秒缓冲，**整集时长直接下降**；
- 情绪不被硬切打断（同一场戏连说三句话，切三段会让观众感觉"卡"）。

**RT-07-3 并段不是并拍**：并段后段内镜头数会增加（4–6 镜），此时必须按 CAM-08 时间窗切分，每个镜头写清 `｜起始—结束秒`。**禁止把两场不同空间的戏并进一段**——空间一变必须切开（continuity-state.md SPLIT-01）。

**RT-07-4 并段的时长核算**：并段后按"段内所有拍点秒数之和"重新估时，若超过 15 秒则只能保留其中一部分——**先砍该段里的过场动作秒数**（把"铺陈"改写成"一句带过"），台词与面板文字一律不动。
