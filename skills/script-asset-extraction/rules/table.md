# 规则模块 R5 — 表格结构 / ID体系 / 连镜评级

> 总控在 S2/S3 读本文件。规则编号 TBL-*。本模块是 assets.json 与 xlsx 的唯一 schema 定义（单一事实源）。

## TBL-01 资产ID体系（硬性）
格式 `<类型前缀>-nn`，类型前缀固定四种：`CHAR-nn` 角色｜`PROP-nn` 道具｜`SCENE-nn` 场景｜`FX-nn` 特效。nn 为两位序号，从 01 起，按登场先后排序。派生行的 ID 在主体后加后缀：
- 角色状态：`CHAR-01-S2`（S=state，基础形象永远占 S1 位或不设后缀的基础行）；
- 道具状态：`PROP-03-S1`；
- 场景视角/状态：`SCENE-02-V1`（V=view，含机位区域与阶段性状态两种拆分）。
ID 一经交付永不复用；Mode 2 废止的行保留 ID 加 status:"废弃"。正例 `SCENE-07-V3`；反例 `场景7-门口`（无前缀无序号，禁止）。

## TBL-02 总表列结构（硬性）
《资产总表》sheet 固定 13 列，顺序不得变动：
`资产ID｜类型｜名称｜状态/视角｜外观描述｜与基础态差异点｜出现场次｜出现次数｜时段氛围｜连镜风险｜需独立参考图｜音色关联｜备注`
- 类型枚举：`角色`/`角色状态`/`道具`/`道具状态`/`场景`/`场景视角`/`特效`。
- 基础行也占一行（角色的"基础形象"、道具/场景的完整描述），派生行的"外观描述"写该状态的完整可见形象，"差异点"只写与基础态的不同处。
- "出现场次"用 集-场 格式顿号连接，如 `2-1、2-3、3-1`；闪回场次标 `14-1a(闪回)`。
- 第二个 sheet 固定为《说明》：字段释义 + 统计 + 使用建议（TBL-08）。

## TBL-03 连镜风险评级（硬性）
- **高**：跨集复用，或同一连续动作段内多场切换（如追逐、隔墙互动），或存在文字/图案特写需要前后一致——变来变去会被观众察觉。
- **中**：同集内 2~3 场复用，或跨集但每次只有远景/背影等低辨识度露出。
- **低**：仅单场出现；或虽多次出现但每次都可作为新画面处理（如通用群演的整体氛围）。
评级对象是"该行若在视频生成中不一致，观众是否可感知"。所有"高"行必须 `需独立参考图=是`。

## TBL-04 参考图判定（重要）
`需独立参考图` 取值：`是`/`否`/`建议`。
- 是：连镜风险高，或主角/核心道具/主场景的基础形象（即使首秀只有一场，如男主开场重伤态）。
- 建议：中等风险或美术上影响风格统一（如信物类小件特写）。
- 否：低风险一次性元素，交给视频 AI 现场生成即可。
判定顺序：先按 TBL-03 评级，再套本条；两者冲突时从严。

## TBL-05 出现次数口径（重要)
按"场次"计数而非镜头数：该行资产在多少个 场次号 中出现（同一场内多个镜头算 1）。流水账（01_出场流水.md）是唯一计数依据，禁止凭印象填数。

## TBL-06 assets.json Schema（硬性）
顶层字段：`drama`(剧名)、`source`(源文件名)、`generated`(ISO日期)、`episodes`(总集数)、四数组 `characters` / `props` / `scenes` / `fx`。
- characters 元素：`{id,name,role,voiceRef,baseLook,eps[],count,risk,needRef,note,states[]}`；states 元素 `{sid,state,diff,look,eps[],count,time,risk,needRef,note}`。
- props 元素：`{id,name,owner,baseLook,eps[],count,risk,needRef,note,states[]}`（states 同上，sid 前缀 PROP）。
- scenes 元素：`{id,name,baseLook,eps[],count,risk,needRef,note,views[]}`；views 元素 `{vid,view,look,eps[],count,time,risk,needRef,note}`。
- fx 元素：`{id,name,carrier,look,eps[],count,risk,needRef,note}`（特效不再拆状态，强度/颜色变化写在 look 内分号列举；确需拆分时复制整行并在 note 说明差异）。
- 可选字段 `status`（Mode 2 废止标记）。省略的字段由出表脚本置空，禁止发明 schema 外字段。

## TBL-07 可解析校验（硬性）
S2 通过条件 = `node -e "JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'))" pipeline\assets.json` exit 0，且四数组均非空。脚本化验证，不接受人工声称。

## TBL-08 说明sheet内容（重要）
《说明》sheet 必含三块：①13 个字段逐一释义；②统计表（各类型行数、needRef=是的行数、风险高中低分布——由 build_xlsx.mjs 自动计算）；③使用建议 ≥3 条（参考图生成顺序、视频 AI 锁定用法、豁免行怎么处理）。

## TBL-09 英文名词·称呼对照表联动（硬性）
面向海外发行的剧，S2 必须同步维护术语称呼表：
- **位置与命名固定**：剧本目录根部，《剧名》-英文名词与称呼对照.txt。
- **已存在 → 整表读入**：所有角色名/称号/势力/地名/道具/事件/能力专名逐字符复用，禁止另起译名；本技能只做"补齐缺失词条"，不改既有译名（改译名属用户决策，须全局替换并登记版本）。
- **不存在 → 依据 assets.json 生成初版**：至少含六节（主要角色/种族阶位术语/势力地名/道具信物/事件仪式/能力特效），外加"统一拼写禁例速查"和"新增词登记处"；命名要求本土化自然英语（参考目标市场同类类型片的母语用词），禁止生硬直译。
- **同步义务**：assets.json 每一处新增/修改/废止的行（尤其 Mode 2），必须同步审查对照表——新增词条、修订词条、废止词条加 `[废弃]` 标注保留。
- **下游约束**：character-voice-design（DLG 规则）与 cinematic-seedance-director（DLG-04）均以该表为唯一命名事实源；本表即全项目命名圣经。
