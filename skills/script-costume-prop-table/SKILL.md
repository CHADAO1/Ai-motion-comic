# 剧本逐场资产分配表（服装 / 道具）

把「谁在第几集穿什么」或「哪件道具在第几场出现」变成一张**可被下游引用的表**。核心价值不在罗列，在于**与现有资产对撞后找出的冲突与遗漏**。

## 0. 输入三件套（缺一不可）

| 输入 | 哪里拿 | 用途 |
|---|---|---|
| **剧本全文** | docx / txt / md | 抽场次骨架、逐场人物与道具 |
| **现有资产文档** | 角色提示词 / 道具提示词 | 已有的变体与编号（对撞基准） |
| **场次编号对照表** | 如 `03_场景提示词/01_编号与场次对照表.md` | 给每场配 `LOC-xx-Y`，道具/服装表要写场景 LOC 列 |

**docx 免依赖提取**：
```python
import zipfile, re
d = zipfile.ZipFile(path).read('word/document.xml').decode('utf-8')
paras = re.findall(r'<w:p[ >].*?</w:p>|<w:p/>', d, re.S)
txt = [''.join(re.findall(r'<w:t[^>]*>(.*?)</w:t>', p, re.S)) for p in paras]
```

## 1. 四步法

1. **抽场次骨架**：逐集拿到「场次号 + 日/夜 + 内/外 + 场景名 + 人物行 + 正文」。**每集开头的「人物：」行是判断角色是否出场的权威依据**——不在人物表＝该集不换装。
2. **建连续段**：同一天 + 同一场活动 ＝ 同一段，只出一套。时间跳跃信号词：`字幕：三年后`、`次日`、`深夜`、`数日后`。⚠️ 剧本常把一场戏拆到两集（41-2/42-1、43-3/44-1），这类**续场是换装误判重灾区**。
3. **对现有资产**：把剧本场次与资产覆盖列表做**双向差集**——资产有剧本无 ＝ 冗余；剧本有资产无 ＝ 缺口。
4. **分类打标**：连续／单独／特殊（见 §2）。

## 2. 三类判定口径

| 类别 | 判定 | 生产含义 |
|---|---|---|
| **连续** | 跨 ≥2 场／≥2 集复用的常规资产 | 只出一份提示词，多场调用 |
| **单独** | 单场专属、仅出现一次 | 一场一份，用完不再复用 |
| **特殊** | 有**合规红线**或**状态变体**需求 | 无论频次一律单列，附专项约束 |

**服装的纳入标准 ＝ 服装本身是否改变**（跨项目通用，用户已拍板）：
- 只换形态（光翼）、或生理／情绪状态（反噬、失态、蚀痕、焦痕、受鞭）→ **不占服装编号**，归文末「§附录 非服装层」，逐集表里写 `状态·反噬`／`形态·光翼`，**不留编号**（避免孤儿 ID）。
- 判据一句话：**同一个人、同一场戏，换不换衣服**。不换＝叠加层，换＝服装。
- ⚠️ 别按名字里有没有「态」字判——`浴室湿身态`／`负伤湿发态`／`寝态` 带「态」但是真实换装（浴后、卧床），必须保留为服装。

**道具的纳入标准 ＝ 能不能被人拿起／放下／递出／损毁**：
- 能 ＝ 道具；固定在场景里的陈设（王座、书桌）→ 场景层；能量与光学现象（符文、水镜、蚀痕）→ 特效层；织物 → 服装层。

## 3. 编号体系

- 服装用 `角色码-序号`：`IVY-11`、`LUC-04`、`OLI-03`（角色码取 3 字母缩写，19 个角色的码表在项目记忆里）。
- 道具的**前缀随项目而定，必须以该项目 `00_资产整合文档.md` 为准**，不要跨项目套用：CHM009 是 `P1–P8`，CHM010 是 `PROP-01~06` ＋独立的 `VFX-01~04`。新增一律从既有最大号顺延。
- **已有编号一律保留、不重排**；新增顺延，**留空号优于重编号**——任何已存在的下游引用都不会被打断。
- 特效（VFX-）独立成体系，**占 VFX 编号、不占道具条数**，在附录里交叉引用即可。
- 分镜段头「绑定资产」行写 `服装 IVY-11` / `道具 P12`，**不写中文名**。

## 4. 输出结构（8 章）

1. 题头（管线 / 画幅 / 体裁 / 基准剧本 / 套数统计）
2. 编号体系与三类判定口径（含「什么不算」的分界说明）
3. **分组总表**：编号 ｜ 名称 ｜ 类型 ｜ 覆盖集-场 ｜ 场景 LOC ｜ 剧情功能 ｜ 现有资产（按功能分组：信物情感／文件凭证／器具仪式／食物餐桌／现代器物／产业商品／危险约束／载具场装）
4. **逐集对照表**：集-场 ｜ 场景 LOC ｜ 出场编号 ｜ 备注（空场景一并保留以便核对）
5. **连续链路**：同一条资产在多场必须同形的路径＋硬要求（这是最易穿帮处）
6. **冲突、缺口与合规**：带编号，分「硬伤／口径／缺口／合规」四型，每条给说明＋处置建议
7. **§附录 非服装层／非道具层**：明确写着「不占编号、不单独出立绘、不计入条数」
8. 页脚：总数（连续 X ｜ 单独 Y ｜ 特殊 Z）＋ 已有／待立

**剧情功能列写法**：不要写"这是重要的道具"。写成**动作链**——`7-1 递给（父亲笨拙的守护）→8-1 捏碎召父`，把它在剧情里"做了什么"串起来。这是这张表最值钱的一列。

## 5. 冲突检查清单（对撞时才产出的价值）

- [ ] **起始点错位**：资产的起点场次与正文实际首次出现不符
- [ ] **母题索引绑定漂移**：索引登记的场次在修订版正文里已改（本次实际发生：P1 月光石索引写 `11-3｜23-2`，正文两场都没有）
- [ ] **同场次被拆到两集**：续场有没有当成换装点
- [ ] **角色不在人物表却给了服装**：该集应写「不出场」
- [ ] **同色词复用**：多处"蓝色西装""灰色休闲装"必须靠编号＋剪裁区分，否则模型渲成同一套
- [ ] **跨大场连续**：同一夜跨多场（宴会 16-1→24-1）不能按集区间推
- [ ] **区间写法**：用户习惯写「1 集到 6 集」，但角色常中间不出场 → 必须改成按场次列
- [ ] **归口冲突**：如角色册写「不持手杖」而正文三处持杖 —— 通常两者不冲突（立绘不带、分镜必带），按 CVC「双手无手持物」解释并加交叉引用
- [ ] **覆盖区间整体错位**（比「起始点错位」更严重，等于整条资产挂在错的场次上）：如 CHM010 VFX-01 登记「1-2、5-6」，而实际开火是 1-1／2-1／3-1／6-1，**5-1 压根没有开火**。→ 逐场重扫，整段改正
- [ ] **提及型缺口**：**简介、台词或旁白提到、但全剧从未在画面上出现**的道具（CHM010：Mia「伪造的信物」只写在故事简介里，从不出镜，导致 9-1 的揭穿戏缺视觉伏笔）。→ 这一类最隐蔽，必须专门扫一遍简介与关键台词
- [ ] **同动作两件相似道具必须做反差**：同剧出现两枚钻戒／两份礼盒／两套制服时，造型要刻意拉开（虚荣用大克拉亮金托 / 克制用简约素圈），否则模型渲成同一件，两次戏的情绪都塌
- [ ] **合规·武器与危险品**：一律单列「特殊」并写死约束——不见血、不见创口、**不出现击发的正脸、枪口不对真人**；中弹用身体反应＋布料褶皱＋旁人侧脸替换
- [ ] **合规·文字承载类**（纸质文件／屏幕／标识），是长剧本里量最大的一类，必须写死三段口径：
  - **纸面**——可读但虚构，不出现真实机构名、编号、网址、真实商标
  - **屏幕**——结构清晰（人物轮廓、曲线、色块），但正文一律色块化，不出现可读文字
  - **文件名与金额**——以字形色块代替，一个字都不写
  - 特例：剧情必须出现「企业标识」时（身份暴露类桥段），设计一个**纯几何、无字母、无真实品牌相似度**的虚构标识，全剧统一复用
- [ ] **合规·婴幼儿与孕产**：婴儿床／襁褓／孕肚一律**只作日常陈设与抱持**，不进任何受害叙事；并核对约束覆盖的场景编号是否与实际出现范围一致（CHM010：原写「仅 LOC-04-C」，实际 39-1 在 LOC-04-A 也被搬进客厅）

## 6. 交付

- **双版**：`{名称}表_CHMxxx.md`（纯文本速查，可整段复制）＋ `.html`（版式表，供人读）。
- HTML 排版**必须走 `html-report-layout` 技能**：`colgroup` + `table-layout:fixed` 锁列宽、场次串 chip 化、`.mono` 不带 nowrap、统计卡数字由数据源算出、headless Chrome 截图自检。
- **数据驱动**：一份 Python dict 作唯一数据源同时渲染 MD 与 HTML，杜绝"改了总数忘改分项"。
- 落盘到项目资产目录（如 `2.资产\02_资产提示词\`），**UNC 同步后必须回读大小校验**。

## 7. 环境坑（本工作区）

- Bash 工具缺 coreutils（`ls`/`mkdir`/`head` 全废）→ 一律 PowerShell 或内联 python（绝对路径）。
- 网盘 UNC 复制用 `[System.IO.File]::Copy($s,$d,$true)`；`Copy-Item -Force` 可能静默失败。
- **PowerShell 变量名不区分大小写**：`$d = Join-Path $D $f` 会直接覆盖 `$D`，第二轮循环路径变成 `…\服装表_CHM009.html\服装表_CHM009.md` 报「未能找到路径的一部分」。**大小写不同 ≠ 不同变量**，必须换名（用 `$srcDir`/`$dstDir` 这类全名）。
- 路径含中文时，截图前先复制到英文临时目录，`file:///` URL 用正斜杠。
- 临时截图目录用完即删。

## 8. 资产回填核对（成品立绘／道具图上传后反查）

建表时那列「现有资产」记的是**提示词变体名**；等美工把立绘传进 `2.资产\N.角色\` 之类的目录后，要再做一轮**回填**：把「现有资产」列改成「**现有立绘**」列，直接指向成品图文件名。触发语通常是「资产上传了，根据 X 表核对更新 X 表」。

**输入**：成品图目录（文件名往往就是服装名）＋ 上一版表。

### 8.1 对位方法（别靠猜文件名）

1. **张数配平验证**——先把图按角色聚类，数「该角色有几套服装图」，与该角色在表里的编号数对比。**张数对上即映射成立**，比逐个猜名可靠。
   - 例：塞西莉亚图库正好 4 张服装图（大典礼服／资格审核官／导师袍／囚服）= 表里 CEC-01~04；艾薇 10 套设计 = IVY-02~13 十号。
2. **全量缩略拼图一次过目**（最省 context 的一步，2026-09-23 HDM028 62 张实证）——把**整个**图库用 PIL 缩成「4 列 × 4 行／页」、每格约 300×420、底部压上文件名，**62 张只生成 4 张拼图，一次读入即可看清全部图的服装款式、颜色与年龄**。相比逐张开原图（单张 2~5MB），context 约省 1/10。
   - **现成脚本**：`scripts/make_contact_sheet.py <图目录> <输出目录>`（可选 `--cols/--rows/--cell`），自动分页并压文件名。拿到图库后先跑它，再 Read 出来的 `sheet*.jpg`。
   - 脚本要点：`im.thumbnail((CW-12, CH-12), Image.LANCZOS)` 后居中贴；文件名用 `ImageFont.truetype("C:/Windows/Fonts/msyh.ttc", 18)` 画——**路径含中文时字体必须显式指定，否则中文全是方块**；图片先 `[System.IO.File]::Copy` 拉到本地再拼（UNC 直读很慢）。
   - 有疑问的再出**放大拼图**（500×700／格、一次 4 格）复核细节。HDM028 靠这一步才发现「李耀祖居家断手版」的**空袖管根本不可辨**（M1 定位标记缺失）——缩略图里看着"还行"，放大才露馅。
   - 判据始终是**开图看**，不是猜文件名：文件名只写用途（`火车上换衣服`），图里才有真实款式。一张图也可能同时覆盖两个编号（实测：`1艾薇外出装+休闲装.jpg` = IVY-06 与 IVY-08 共用）。
   - **成品图本身可能违规**：HDM028 图库里 3 组共 9 张是真实儿童／襁褓婴儿，与项目硬约束（成年演员出演、无婴幼儿）直接冲突——**只有开图才看得出来**，光扫文件名会全部漏掉。
3. **群像／头部参考单独归口**——大头、特写、群像（众贵族夫人、军务大臣、卫队…）**不进服装编号**，另开一节约「附录 B · 群像与配角立绘」，分镜绑定写 `群像：军务大臣`。

### 8.2 回填时要输出的六件事

| # | 输出 | 说明 |
|---|---|---|
| 1 | 逐条「资产图名」列 | 写**磁盘上的真实文件名**（含扩展名，逐字不改）；仍缺的保留 `缺立绘` 红标。**别只渲染一个状态徽章（`有图·复用`）就交差**——用户拿到表的第一件事是照名取图，看不见文件名这张表就是废的（2026-09-23 HDM028 V3.0 犯过，被迫出 V3.1） |
| 2 | 缺口收敛表 | 「上一版点名的 N 条缺口 → 本次核对结果」逐条给 ✅已补齐／⚠可复用／❌仍缺，**并写明仍缺的优先级** |
| 3 | 新增条目 | 出了表里没立号的新服装 → **立新编号**（顺延留空号），并改逐集表绑定与换装标记 |
| 4 | 色彩母题校正 | **实际出图常与初设不符**（实测：塞西莉亚初设「四套全墨绿」，实拍成酒红金／黑米白金／墨绿／无色；埃莉丝「月白织银」实拍成深蓝金星 → 与主角净化礼深蓝撞色）。这一类**必须单列警告**，是美术手册级的冲突 |
| 5 | 命名异常清单 | 图库里命名无意义的文件（如 `图像生成节点-45.png`）→ 列出请人工确认后改名。同类：错别字（`李耀租` 应为 `李耀祖`）、括号未闭合（`刘银娥（张明远母亲大头.jpg`）、文件名夹空格、同一角色两种写法（`王桂芳` vs `王桂芬`）、无后缀的大头图 |
| 6 | **成品图合规核验**（最易漏、优先级最高） | 逐张开图核验成品图**本身**是否违反硬约束——真实儿童／婴幼儿／襁褓／孕妇／血迹／可读文字。HDM028 查出 9 张违规（张宝珠被出成红衣幼童、李招娣 3 岁与 10 岁两档为真实儿童、李耀租为襁褓婴儿）。**这类图无论多好看都必须停用重出**，单列为「P0 合规红线」章节放表首 |

### 8.3 改表：小改走行级脚本，大改重建数据源

**只有「补一列 / 改几条绑定」才用行级脚本**（下例）。若表结构本身要动——同时加列、加节、改判定口径、立新编号——直接**重建唯一数据源再整表渲染**更干净：一份 Python dict 同时产出 MD 与 HTML，统计卡与表格在结构上不可能对不上（2026-09-23 HDM028 服装表 V2.0 实证，65 条编号 + 71 场全部重建，一次跑通）。

行级脚本示例（小改场景）：

```python
lines = html.split("\n")
for i, ln in enumerate(lines):
    m = re.match(r'<tr><td class="mono">([A-Z]{3}-\d\d)</td>', ln)
    if not m or m.group(1) not in ASSET: continue
    k, t = ASSET[m.group(1)]
    newtd = f'<td><span class="bd bd-{k}">{t}</span></td>'
    j = ln.rfind('<td>')                      # 末列才是资产列
    lines[i] = ln[:j] + newtd + '</tr>'
```

- 统计卡的数字（总数／连续／单独／特殊／缺口）**必须一起改**，否则出现「总数 51 但分项加起来 50」这种自相矛盾。
- ⚠️ 同一次 replace 的命中数会**大于编号数**——因为冲突节／缺口表里也有同编号行。无副作用，但**缺口表要在同批里整体重写**，别让它被替换成半截状态。
- 改完必查：唯一编号数、统计卡分项加总、标签平衡（`<table>/<tr>/<td>` 开闭数）、headless Chrome 分段截图。

### 8.4 「资产图名 ↔ 编号」双向对位（用户问「把资产图名称对应上」时做这四步）

用户说「资产图名称对应上」，通常是**表里只有编号、没有图名**，或**图名和磁盘实际文件对不上**。做这四件事：

1. **以磁盘为准取名字，不靠手输**。用 `os.listdir(图目录)` 拿到真实文件名（过滤 `Thumbs.db`），然后**用真实名去反查表格字段**（`if name in field`），而不是自己拼名字——手输会漏掉「`张宝珠大头 .png`（扩展名前多一个空格）」「`刘银娥（张明远母亲全身.jpg`（括号没闭合）」这种。
2. **解析资产列不能按分隔符切**。数据源里同一列可能混用 ` / `（前后带空格）与 `）` 紧跟 `/ ` 两种写法，`split(" / ")` 会静默漏切、把两条合并成一条（HDM028 WD-ZD01 就这样被切成 1 段，输出成 4 个错条目）。**正确做法：找出所有真实文件名在字段中的位置，按位置排序，每个文件名的备注 = 它到下一个文件名起点之间的文本**（去掉 `/`、空格与全角括号）。
3. **归属审计（必跑）**——建 `文件 → 归属` 反查表，输出三件事：**未归属**（磁盘有、表里没引用）、**重复归属**（同时被算作服装立绘 + 面锚 + 群像）、**每条有图行的图名数**。目标是「磁盘 N 张全部有归属、0 张漏配」。
   - ⚠️ **分类计数必须按优先级去重**：一张群像图可能同时是某编号的代用立绘（`执法人员.png` 既是 WD-PJ06 又是群像），一张大头图可能既作立绘又作面锚（`张宝珠大头 .png`）。HDM028 曾误报「服装立绘 36 + 面锚 22 + 群像 5 = 63」（相加看似平账，实际靠 4 张重复计入），真实划分是 **40 可用作立绘（含 4 张双用途）+ 2 纯群像 + 21 纯面锚 = 63**。
4. **逐场表也补图名**。只给编号不够用：按集速查的每场加一列「可用资产图」，列出该场涉及的编号对应的真实文件名。分镜/出图的人看这一列就能直接取图。

**渲染注意**：MD 用 `文件名（备注）` 文本，HTML 用等宽 chip；`出现场次` 这类长字段（某行可能 15 场）**用紧凑小字而不是 chip**，否则行高炸裂、整表难读。

### 8.5 缺图清单 → 提示词（用户问「把缺的服装提供提示词」时）

拿到「仍缺立绘 N 条」清单后，**不要直接从头写 N 条提示词**——先和项目已有的角色提示词文档对撞，通常能省掉一半工作量。分三类：

| 类别 | 判定 | 处理 |
|---|---|---|
| **直接复用** | 该编号的服装就是某角色**原始外观**，或已写好的某个变体的服装 | 逐字复用已有块，只给「＝已有『XX』」的指向，不重写 |
| **需微调** | 与已有块只差一处（多半是**换包 / 换内搭 / 加围巾 / 长袖改短袖**） | 复制已有块，只改「变更」段那一句，并在说明里写明差什么 |
| **全新** | 前面都不命中 | 完整新写五段结构 |

- HDM028 实测：29 条缺图 → **7 条直接复用 + 4 条微调 + 18 条全新**（复用率 38%）。命中的都是「原始外观」或已出变体：ZD04＝招娣-高中、ZD07＝招娣-青年、YZ06＝耀祖-青年、YZ08＝耀祖-义肢、NN01＝玉珍-原始、WZ03＝王招娣-原始、MY01＝明远-原始。
- 微调的典型是**同一套衣服的两种穿法**（下摆扎进 vs 放出、加一件外套）——这类**可以共用一张立绘**，交付时明确写出来，别让美工白出一张。
- **配角与群像没有参考图，走 T2I 一次性出图**（不做变体）；群像一次出 3-5 人，分镜绑定写「群像：XX」。

### 8.6 交付前的否定式扫描（必跑，两道）

规范是**内容段只写正面可见的东西，否定词只出现在固定负面 FN 里**。检查分两步，缺一不可：

1. **固定禁词表**（快筛）：`无血迹 / 无创口 / 无疤痕 / 看不到 / 不出现 / 禁止 / 无文字 / 无可读 / 无花纹 / 无字`。
2. **全量正则**（兜底）：把内容段（剥掉首行前缀与末两行后缀、负面）用 `[^，。；、（）]{0,14}[无不没禁][^，。；、（）]{0,14}` 全扫一遍，再人工剔除两类**误报**：
   - 固定画面控制语：**「中性灰无缝背景」**（不是否定式，逐字复用，保留）
   - 描述画面内状态的叙事句：**「神情不耐」「姿态各自不同」「眼神不散」**（规范明确允许，保留）

⚠️ HDM028 实测：只跑第 1 步抓到 7 条，跑第 2 步扫出 **33 处**，剔除误报后还有 **8 处真违规**（`廓形简洁无蕾丝堆叠`、`布面无文字`、`头戴一顶无字草编草帽`、`外观是朴素医疗辅具无科技感` …）。**只跑禁词表必漏。**

正向改写词库（把否定改成正面可见的描述）：
`无可读文字 → 素色封面 / 素面纸 / 素色平纹布`｜`无字草帽 → 素色草编草帽`｜`无蕾丝堆叠 → 廓形简洁平整`｜`无发光元件无科技感 → 哑光外壳表面平整素净、朴素的医疗康复辅具造型`｜`看不到创口断端 → （直接删掉，只写）袖管空荡垂落、袖口向内折起并用别针别住、布料干净平整`

### 8.7 顺手清扫已有文档的否定式残留

给新资产写提示词时，**顺手扫一遍项目里已有的提示词文档**——旧稿常留有早期写的否定式句子（HDM028 的 `01_角色资产提示词.md` 查出 3 处：伤后变体、断指角色、义肢特写）。这类句子会被模型反向执行，必须改。改前**先备份到 `_bak-<日期>\`**，改完复扫确认命中归零，并在回复里逐条列出「原文 → 改为」，让用户知道动了什么。

### 8.8 幽灵图名与「新到图」——回填必跑的双向存在性核查

**只做「磁盘 → 表」单方向核对一定会翻车。必须双向跑。** HDM028 的 V3→V4 返工，三类错全靠这一步才暴露：

| 错法 | 症状 | 后果 |
|---|---|---|
| **幽灵图名** | 表里引用 `图像生成节点-26/-30/-35.png`，**磁盘上根本没有这三个文件**（真实文件是 `护士.png`） | 分镜照名取不到图；作废的两张（村民群像、全家福合影）实为缺口，却被当成「已有」漏掉 |
| **新到图未纳编** | 期间美工往图目录新传了 12 张图，表没跟 | **10 条**编号被误判「缺立绘」，还白出了一批提示词 |
| **可复用未标** | 同款不同穿法的编号被当成缺图 | 又白出 3 条 |

**做法**：跑一段约 30 行的核查脚本，输出四张清单——

```python
disk = [f for f in os.listdir(ASSET) if f.lower().endswith((".jpg",".png"))]  # 当下快照
# ① 引用存在性：抓幽灵图名
for rid, art in ROWS_ID_ART:                       # (编号, 资产字段)
    hits = [n for n in disk if n in art]           # 按真实文件名定位，不切分隔符
    if art and not hits: print("幽灵图名", rid, art)
# ② 漏配：抓新到图
cited = {n for ...}                                # 所有被编号/面锚/群像引用的名字
print("漏配", [f for f in disk if f not in cited])
# ③ 跨类：同一张图兼立绘/面锚/群像
# ④ 计数平账
assert sum(ST.values()) == len(ROWS)
assert len(CLOTHES) + len(GROUPS_ONLY) + len(ANCHORS_ONLY) == len(disk)
```

四条硬规矩：
- **表里每一个文件名都必须在磁盘上真实存在**。手输或凭记忆写的名字一律不可信——`图像生成节点-NN` 这类「当时好像见过」的名字最容易变成幽灵。
- **回填不是一次性动作**：图目录会持续长图。**任何一次重出表都以当下磁盘快照为准重跑核查**，绝不沿用上一次的清单。
- **每次把「磁盘图数」打印出来**：HDM028 从 62 → 74 张，数字一跳就该警觉（本次就是靠这个发现的）。
- **漏配的图要当场判归属**，别只报数。HDM028 那 14 张漏配图，逐张开缩略图后分别落到 ZD03/ZD04/ZD07/ZD11/ZD12、YZ04/YZ06、MC02/MC04、GF02/GF04、PJ08 与 1 张面锚、1 张群像——**开图比猜名可靠**（文件名 `年轻夏日日常装` 到底对 YZ04 还是 YZ05，只能看图里的季节着装判）。

⚠️ 反过来说：**用户质问「某某明明缺了」时，先别急着解释，先重扫磁盘**。HDM028 用户问「怎么缺了大伯娘、赵大哥、奶奶」，重扫后发现真相比预想复杂——大伯娘/赵大哥确有图（只是没进缺图提示词文档），而奶奶确实缺；同时揪出 12 张新到图与 3 个幽灵图名。
