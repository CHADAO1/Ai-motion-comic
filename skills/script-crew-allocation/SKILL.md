# 剧本 → N 人分工方案

把一部剧本切成 N 段，交给 N 个人，且每一段的制作成本尽量接近、叙事线尽量完整。

## 核心判断：不要按集数均分

新手最容易犯的错是「47 集 ÷ 6 人 = 每人 7.8 集，那就 1-8 / 9-16 / …」。这是错的，原因有三：

1. **集数 ≠ 工作量**。一集纯对话戏（医院诊室，动作行 2-4）和一集追逃戏（楼道，动作行 12-13），制作量差 3-4 倍。
2. **场景资产要集中**。同一处景分给两个人，就要交接资产、统一提示词，否则画面必漂。
3. **叙事块要完整**。一个人吃透一段情绪线，光影母题和表演基调才统一；为了凑数字把一条线劈开，交接成本远大于省下的工时。

## 工作流

### S1 提取剧本正文（不装依赖）

docx 就是 zip，用标准库直接抓 `word/document.xml`，**不要 pip install python-docx**：

```python
import zipfile, re
z = zipfile.ZipFile(src)
xml = z.read("word/document.xml").decode("utf-8", "ignore")
blocks = re.split(r'(?=<w:tbl[ >])|(?=<w:p[ >])', xml)
# 段落文本
txt = "".join(re.findall(r"<w:t[^>]*>(.*?)</w:t>", p, re.S))
# 表格逐行 cells
for row in re.findall(r"<w:tr[ >].*?</w:tr>", tbl, re.S):
    cells = [" / ".join(para_text(x) for x in re.findall(r"<w:p[ >].*?</w:p>", c, re.S))
             for c in re.findall(r"<w:tc[ >].*?</w:tc>", row, re.S)]
```
输出到本地 txt，后续统计都读它。

### S2 逐集统计（关键）

按 `第X集` 切集，按 `^\d+-\d+\s*[日夜]\s*[内外]` 切场。每集算五个数：

| 指标 | 含义 |
|---|---|
| 场数 | 空间切换次数 |
| **台词行** | 配音 + 口型成本 |
| **动作行**（`△` 开头） | ≈ 镜头量、生成成本 |
| 正文字数 | 整体体量 |
| 角色 / 场景集合 | 判断资产集中度 |

**成本指数 = 动作行 × 1.5 + 台词行**。动作行权重更高，因为 AI 生成里一个动作就是一次出图/出片。

⚠️ 两个必踩的坑：
- 场头有两种格式：`1-1日 内 李招娣家人物：李招娣 张宝珠`（人物同行）和 `1-2 日 内 李满仓家` + 换行 + `人物：…`（人物在下一行）。**两种都要处理**，否则统计出来角色全空。
- 角色名带 `（10岁）`、`同学1（女）`、`乘客若干` 等后缀，先正则剥掉再归一化。

### S3 找叙事块边界（候选断点）

扫一遍剧本，列出**叙事可断点**：时间跳跃、场景群切换、钩子落地处。典型如：

```
6|7    揭晓 → 新冲突
13|14  被追 → 周旋
19|20  换场景群
24|25  脱身 → 新危机
29|30  重大事件 → 后果处理
35|36  事件结束 → 新阶段
40|41  毕业 → 婚礼（时间跳跃）
43|44  段落收束
```

### S4 分配：先按块切，再用枚举验均衡

1. **按叙事块切出 N 段**（这是主推方案，块要完整）。
2. 再**枚举**候选断点里所有 C(候选数, N-1) 种切法，算极差最小的那一组，作为**备选均衡版**。
3. 两版都给用户，说明各自的代价。通常主推版叙事更顺、备选版数字更平。

贪心/枚举用 `itertools.combinations`，N≤8、候选≤12 时直接暴力枚举，秒出。

### S5 配平的真正手段：给轻的人派「资产统一」的活

剧本的块天然不均（开篇建置段和结尾温情段一定比中段高潮轻）。**不要为了数字把线切碎**，正确做法是：

- 最轻的人 → 兼任**共用场景资产总控**（跨人复用的场景，如贯穿 10 集的火车车厢）
- 次轻的人 → 兼任**角色年龄版本资产总控**（幼年组、少年组形象一次建齐）
- 这两块工作量不体现在集数上，但必须有人兜

### S6 强制检查清单（交付前必过）

- [ ] **付费卡点集**：免费末集 / 付费首集是全剧质量最优先，建议同一人承接、全组会审
- [ ] **合规红线集**：血 / 断肢 / 暴力 / 婴幼儿等，标红并指定经验最丰富者 + 单独走合规审核
- [ ] **跨人共用场景**：列清单，指定资产总控人（否则画面必漂）
- [ ] **角色年龄版本**：同一版本尽量同一人；闪回必须复用已有资产
- [ ] **剧本是否注明「N 集后需改动」**：有则只锁前 N 集排产，后面等定稿
- [ ] **群演集**：围观群众、同学、乘客等同框多的集，标注需提前备群演资产包

### S7 输出 HTML 方案

按 `html-report-layout` 技能规范写：浅色主题、`colgroup` + `table-layout:fixed`、场次**必须 chip 化**（`<span class="ep">1-1</span>`，否则 `1-1｜1-2｜…` 长串一定溢出）、统计卡数字由同一份数据结构渲染。

章节：① 剧本结构（叙事块 + 每块场数/台词/动作/难度）② 推荐分组（人员·集段·覆盖场次 chips·核心内容·角色场景版本）③ 负荷对照（成本指数条形图 + 相对均值 %）④ 必须提前定的事 ⑤ 备选均衡版 + 代价说明。

## 环境坑（本机实测）

- **Bash 工具缺 coreutils**（`ls`/`head`/`dirname` 全废）→ 一律用 PowerShell 或绝对路径 python
- **PowerShell 控制台回显经常为空** → 结果写文件再 Read
- **headless Chrome 必须加 `--no-sandbox --user-data-dir=<temp>`**，否则静默失败、不生成截图
- 负 margin 分段截图时，**HTML 文件名必须与截图引用名一致**（生成 `s1450.html` 却去截 `s1400.png` 会得到 ERR_FILE_NOT_FOUND 空图）
- python 的 `DeprecationWarning` 会让 `$LASTEXITCODE` 变 1，别误判为失败

## 交付

一份 HTML（`<项目名>_N人分配方案.html`） + 对话内一段 SVG 甘特式总览图 + 结论要点。
