# script-draft-forge — 使用指南

**这是什么**：纯编剧服务的初稿锻造流水线。给素材（小说/对标剧/题材想法），产出**可挑选的专业剧本初稿包**——每集多版、结构差异化、钩子可验收、烂稿机器杀。专业度来自编剧知识层（CR 三层方法论），平台/题材适配来自可插拔模块。

**一句话理解**：它是一个不知疲倦的编剧助理团队——懂 21 节编剧方法论，按你的需求出多版初稿，自己先过一遍质检，把能用的和不能用的分开摆好，你只做最后的选择和精修。

---

## 一、七种典型用法（照抄即用）

### 场景 1：从零开始（最常用）

```
你：（粘贴素材：小说片段/对标剧简介/题材想法）
    帮我出个初稿包，20集，每集1分半，投红果，男频都市逆袭
```
→ 走 Mode 1 六步。S0 会先和你确认需求表（没说的维度会用默认值问你），然后一路到交付。
**你会拿到**：`outputs\` 下的初稿包——每集 2-3 版（文件名 `ep001_A_v1.md` 这种）+ 《初稿包索引》（每集版本清单+判定+推荐排序）+ 《体检报告》（每版过/杀及证据）。

### 场景 2：自带钩子需求（你的方法论你做主）

```
你：出初稿包，钩子要身份揭露型的，每集双卡点，其他你定
```
→ 钩子预算来源记为"自定义"，只按你的要求配额；你没说的维度走默认折算。**不再有任何强制数字**。

### 场景 3：不挂平台，纯定制

```
你：别管平台规则，按我自己的节奏来，重点做人物弧光
```
→ 不挂平台模块，通用默认出稿。分级推荐会把"讲人物"的版本排前面。

### 场景 4：某集不满意，重出

```
你：第 5 集重出几版，上一版卡点太弱
```
→ Mode 2。上轮死因会作为负面约束注入（不会再犯同样的错）；只重出第 5 集，其他集不动。

### 场景 5：即兴需求，下次还想用

```
你：按武侠宗门套路来一版
```
→ 首次即兴执行；同时这个需求会被落成 `modules/genre/wuxia-zongmen.md` 模块登记。下次说"挂武侠模块"直接复用。**一次即兴，永久资产**。

### 场景 6：小说原文 + 编剧大纲/细纲 → 按纲出初稿（Mode 3）

```
你：这是小说原文（给它 .txt/.md/.docx 文件，或整目录），这是编剧大纲和细纲
    （.md/.docx/.xlsx 都行），按这个纲出初稿，20集，每集90秒
```

→ 走 `workflows/source-outline-draft.md`。先跑 N0 入库：原文按章切片（长文本**不会整本塞进上下文**）、细纲逐条编号 `EP001-B01`，给每集打一个 `pipeline\packets\ep001.md` 生成包（本集细纲 + 本集原文切片 + 人物/术语/前情 + 钩子预算）。
→ **结构听细纲、事实听原文**：细纲已拍板的事件顺序不许模型"优化"，同集多版只在呈现层差异化（切入点/调度/台词密度/卡点）；原文人名、设定、金手指条款不许改。
→ 出稿后多跑一份覆盖验收：**必留细纲条目没落地 → 直接判杀**，不靠"这一集都写到了"的自报。
→ 你会额外拿到 `12_纲解析报告.md` 和 `01_体检报告_纲源.md`；推定分配的章节、无原文依据的细纲条目、原文与纲冲突、疑似新增事件会列进挑稿决策点清单等你拍板。

格式不会写？跑一句 `python scripts/source_outline.py init-template <目录>` 拿模板。细纲里写 `原文第3-5章` 能精确指定本集用哪几章；写 `锚点：宁清和|手表` 能让覆盖校验更准。只给大纲不给细纲也能跑（事件锁定，不锁逐场结构）。

### 场景 7：六档位自动混跑（MR-08，要脱离会话模型批量跑时用）

```
你：这批 10 集按六档位自动跑，用调度引擎
```

→ 前置：`~/.config/opencode/models.json` 的六个端点已配齐（MR-07）且配置已加载。
→ 命令链（在项目目录里跑）：

```
python scripts/engine_dispatch.py init-config <剧本目录>
python scripts/engine_dispatch.py plan --project <剧本目录> --episodes 1-10 --versions 2
python scripts/engine_dispatch.py run --project <剧本目录>          # 演练，零调用零费用
python scripts/engine_dispatch.py run --project <剧本目录> --live    # 真跑，产生 DMXAPI 计费
python scripts/engine_dispatch.py status --project <剧本目录>
python scripts/engine_dispatch.py verify --project <剧本目录>
```

→ 自动排任务：骨架档写预算 → 定调档只写每卷首集 → 批量档写其余集与版本 → 挑稿档比较排序；满 10 集自动排卷级回顾，加 `--dialogue-pass` 才有台词精修档。产物头照样标引擎和差异轴。
→ **默认演练稿带占位标记，`verify` 会拒绝验收**；只有 `--live` 的产物能进闸门A。中断后重跑会跳过 done 任务，失败任务不写产物、下游自动 blocked（`--retry-failed` 重跑）。
→ 成本报告只报 token 用量；想看金额，在 `pipeline\dispatch-config.json` 的 `price_per_1k` 填单价，**未填不编造金额**。报告只汇总成功任务的 `usage`，重试若已计费不计入，实际账单可能略高。
→ **LIVE 实跑注意事项（2026-11-04）**：`disable_thinking` 默认开启——推理型档位在长编剧 prompt 下会把整段 `max_tokens` 花在思考上导致正文为空，关思考后正常出稿。聚合网关偶发 404、读超时会自动重试；要保留思考链做质量对照才显式设 `false`。中断后用 `run --live --retry-failed` 只补失败与被阻断的任务，已 done 的不重复计费。
→ 它只换「谁来生成」，不替你挑稿、不合并、不改稿、不出终稿。

## 二、你说话的最佳姿势（需求表达指南)

| 维度 | 你可以说 | 不说会怎样 |
|---|---|---|
| 集数/单集时长 | "20集，每集90秒" | S0 会问，不猜 |
| 目标平台 | "投红果" / "不挂平台" | 不挂平台包，走通用默认 |
| 题材/风格 | "男频都市逆袭，热血爽感" | 从素材推断后需你确认 |
| 钩子 | "身份揭露型"/"每集双卡点"/"20句" | 按平台折算默认配额 |
| 版本数 | "每集给我3版" | 默认 2-3 版（Mode 3 默认 2） |
| 模块 | "挂情绪热力图" / "看看市场" | 情绪热力图默认建议挂 |
| 原文/纲（Mode 3） | "小说原文在这，细纲按这个出" | 不给文件就走 Mode 1 |
| 细纲约束（Mode 3） | "细纲仅供参考，重新结构" | 默认**锁定结构**，版本只在呈现层差异化 |
| 引擎/调度（MR-08） | "六档位自动混跑" / "按档位自动调模型" | 走会话默认模型，分批手动切选择器 |

**核心习惯：先说需求，再丢素材**——需求登记表在流水线最前面，前面说得越清楚，后面返工越少。

## 三、拿到初稿包之后怎么挑（3 步）

1. **先看索引**：`00_初稿包索引.md` 有每集版本清单、闸门A判定、三档分级（讲故事/讲人物/讲情怀——一流标注的版本优先看）。
2. **只在过关版里挑**：被杀的版本带着死因记录（"情理门挂：能力越界"这种），**不要试图精修救活烂稿**——这是铁律 1，修烂稿的时间成本远高于重出一版。
3. **不满意就点名重跑**："第 N 集重出，要 XX 版型"——比模糊的"再改改"快十倍。

挑完之后：合并精修你自己做（或点名会话模型："帮我把 ep005 的 A 版和 C 版合并"）——技能边界到初稿包为止，不越界。

## 四、它替你把了哪五道关（体检报告看什么）

| 关 | 查什么 | 对应你的哪条经验 |
|---|---|---|
| 情理门 | 行为匹配能力、反应匹配情境（逐场） | "普通高中生弹指弹飞霸王龙=杀" |
| 钩子回提 | 覆盖率/类型轮换/强度/兑现台账 四维 | 钩子预算花没花完、有没有疲劳 |
| 台词抽检 | 盲还原测试：抽3句台词还原角色，还原不回=杀 | 台词匹配人设×场景 |
| 情绪 lint | 纯情绪名称词无行为支撑=杀 | "脸色一变不是情绪" |
| 一致性 | 人物言行对小传、术语表零变体 | 防第40集忘设定 |

**每个判定都有证据**（行号/原文引用/数值），不是"感觉不错"。

**Mode 3 再加三道**：细纲逐条覆盖（漏一条必留条目即杀）、原文人名/术语忠实、大纲外新增事件预警。这三道由脚本出数值与行号，**禁止模型自报覆盖**；但锚点命中不等于语义覆盖，逐条语义判定仍带行号证据写进体检报告。

## 五、模块系统：想扩展就挂

| 内置模块 | 作用 | 挂载时机 |
|---|---|---|
| 平台结构包 ST | 六平台结构模板（红果三段式/抖音共鸣流/盐选双层反转等） | 说目标平台时 |
| 题材探测 MS | 联网查题材稀缺度，沉淀进本地库 | "看看市场"/选平台时 |
| 情绪热力图 EH | 逐场情绪标注+走势条，转折点沉淀自有库 | 默认建议挂 |

**自建模块**：说一句"按 XX 套路来"，它落成 `modules/` 里的文件登记复用。四类扩展位：platform（平台）/ genre（题材）/ style（风格）/ process（流程）。规范见 `modules/_registry.md`。

## 七、边界与纪律（一句话版）

- **只出初稿**：挑稿合并精修是你（或你点名的模型）的事
- **杀稿不修稿**：被杀版本别救，点名重跑更快
- **需求不明会问你**：不猜——宁可多问一句，不出一万字废稿
- **演练稿不算交付**：DRY-RUN 占位文件 `verify` 一律拒绝，必须 `--live` 才出真稿
- **改技能先读 MAINTENANCE.md**：变更全记 CHANGELOG，lint 过了才算改完

## 附：新手第一次跑的建议

拿一个小目标试：**5 集短剧 + 明确平台 + 一种题材**，全流程走一遍（约 10-20 分钟），看懂索引和体检报告的结构，再上正片。第一次跑完，你就知道哪些维度值得在需求表达里说死了。

想试六档位调度，先跑 `python scripts/engine_dispatch.py selftest`（离线零调用、27 项断言），再拿 `plan → run`（演练）练手，确认报告结构后再决定要不要 `--live`。
