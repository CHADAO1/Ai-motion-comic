# 模块注册表 — 自定义模块规范

> 本文件定义 modules/ 的游戏规则：什么算模块、怎么写、怎么挂载、怎么登记。核心规则（CR/HK/DR/MR）永不放模块里。

## 1. 模块是什么

独立可插拔的规则包，挂载到流水线的固定插槽。**平台适配、题材套路、风格腔调、特殊流程**等一切扩展都做成模块——核心技能保持纯编剧服务，扩展随用随插。

## 2. 模块文件规范（硬性）

- **位置**：`modules/<类型>/<模块名>.md`，类型四选一：
  - `platform` 平台包（目标平台的结构/节奏/卡点细则）
  - `genre` 题材包（题材套路、情绪配方、人设模板）
  - `style` 风格包（台词腔调、画面风格、叙事偏好）
  - `process` 流程包（特殊环节的工序约束）
- **文件头两行声明**（复制即用格式）：
  ```
  # 模块 — <中文名>
  > 类型：<platform|genre|style|process> · 挂载点：<S0 选择 | S3 生成 | S4 附加验收 | 全程> · 编号前缀：<两个大写字母>-
  ```
- 规则逐条带唯一编号（前缀-01 起），正反例各 ≤1；一条规则一节。
- **一个模块只做一件事**；模块内禁止引用其他模块的编号（跨模块只引用核心 CR/HK/DR/MR）。
- 新增/修改模块**不改核心规则文件**，只登记本表。

## 3. 挂载与卸载

- **挂载时机**：S0 需求登记时确认。用户声明目标平台 → 挂对应 platform 包；声明题材套路 → 挂 genre 包；只说"随便出几版" → 可不挂任何模块（通用默认），manifest 的 `modules_loaded` 记空数组。
- **挂载效果**：S3 生成时模块规则注入提示词；S4 验收时模块附加验收项生效。
- **即兴需求沉淀**：用户在对话中提出的新需求（如"按武侠宗门套路来"）→ 先按规范落成模块文件并登记 → 再挂载执行。一次即兴，永久复用。

## 5. 质量门槛

新模块登记前自检：文件头两行声明齐全；规则有编号有例子；不引用其他模块编号；不影响核心铁律。跑 `node scripts/lint_skill.mjs` 通过后才算登记完成。
