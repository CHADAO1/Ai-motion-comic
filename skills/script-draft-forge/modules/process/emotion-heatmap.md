# 模块 — 情绪热力图
> 类型：process · 挂载点：S3 生成 + S4 附加验收 · 编号前缀：EH-

> 对标缺口：创一AI 的 3000+ 爆款情绪转折点数据库与实时情绪热力图。本模块用"逐场标注+自有沉淀库"补位——库是通用的，这个库长在你自己的赛道上。
> 挂载条件：默认建议挂载（情绪颗粒度是当代剧本采购硬标准）；用户明确不要可视化时可卸。

## EH-01 逐场情绪标注（硬性）

每场标注三件：**情绪类型 + 强度 1-5 + 转折点（有/无）**。类型必须具体到可感知——"爽"不算（拆成扬眉吐气/释然/复仇快感），"难受"不算（拆成屈辱/愤怒/绝望）。与 CR-17 联动：每个标注的情绪必须有场内行为/台词支撑，纯名称词标注无效。

## EH-02 热力图产物（硬性）

每集一张表落进体检报告：`| 场次 | 情绪类型 | 强度 | 转折 |`，并在表下画强度走势行（`▁▃▅█` 字符条）。验收联动 HK-06：全 ≤2 无峰 = 拖；全 ≥4 无呼吸 = 麻——两判合并，一处挂即挂。

## EH-03 转折点沉淀库（硬性）

闸门A**过关版本**的情绪转折点追加到 `reference/emotion-turns.md`，每条四字段：`场次 + 触发事件 + 情绪转换方向（如 愤怒→震惊）+ 强度差`。按题材分节。用户给对标剧拆解时同样入库（标注来源）。只沉淀过关版本——库的准入标准是闸门A，垃圾转折点不进库。

## EH-04 生成注入（建议）

S3 生成指令附沉淀库中**同题材最近 3 条转折点样例**，让引擎学习你验证过的情绪节奏，而不是通用套路。库空（首次使用）时跳过本条，不阻塞。取样例统一走 `python scripts/emotion_library.py query --genre X --limit 3`，脚本自动排除「实测错误案例」。

## EH-05 库校验与准入（硬性，2026-11-04 新增）

唯一事实源改为 `reference/emotion-turns.jsonl`（每行一 JSON），由 `scripts/emotion_library.py` 管理；`reference/emotion-turns.md` 是库说明与索引。

- 准入仍是 EH-03：**只收闸门A 过关版**；对标拆解、方法论派生、错误案例必须分别标注 `source_type`，不得混入实测数。
- 每条必须可指回出处（`source`）+ 日期（`date`）+ 强度差（-5~5）+ 触发/转换方向；`verify` 不 PASS 的导入不写盘。
- 去重键 = 触发事件 + 转换方向；重复条目跳过，不靠人工肉眼判。
- 错误案例（如「系统无触发源自动结算」）保留作反面教材，但 `query` 不注入生成。

## EH-06 批量导入与增长（硬性）

- 历史项目导出 JSONL / CSV → `python scripts/emotion_library.py import --file ... --source-type 项目导入`，自动编号去重。
- `stats` 每次交付公开当前真实条数与来源构成，**禁止把派生条目算成实测、禁止一次性批量造数凑规模**。
- 目标 3000+ 是累积目标，不是初始状态。竞品的 3000+ 来自真实项目库；本模块的补位是「自有赛道 + 闸门A 准入 + 可指回出处」，规模随项目增长。
- 每轮闸门A 结束后把过关版转折点 `append` 入库，这是库变厚的唯一常规来源。

## 与 SaaS 竞品的差距（如实记录）

创一 AI 的 3000+ 情绪转折点库是数据壁垒，本模块起步只有 20 条带出处的种子条目。
不伪造、不夸大，靠 EH-05/06 把每轮验证过的转折点沉淀成自有资产。
