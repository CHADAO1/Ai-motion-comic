# 模块 — 分集规划三要素
> 类型：process · 挂载点：S1 产出 + S3 注入 + S4 合并验收 · 编号前缀：EP-

> 为什么有这个模块：技能原本是**倒着走**的——Mode 3 的 `ingest` 吃外部给的细纲，技能只负责切片锁定，从不产出分集大纲；钩子预算表有四级钩位、类型轮换、台账，却**没有「本集核心事件」「本集信息增量」字段**。结果细纲里的事实错误会被原样继承到每一版，且「冲突／信息增量／尾钩」三者从没被一起判过（HK-09 只回提钩子四维）。本模块把这一环补成**技能自己产出的表 + 自己的门**。

## EP-01 分集规划表是 S1 必产物（硬性）

`01_钩子预算表.md` 的四级钩位配额与台账之外，**必须另附《逐集三要素表》**（也可单独落 `pipeline/01_分集规划表.md`），表头固定：

```
| 集 | 本集核心事件 | 明确冲突 | 本集信息增量 | 尾钩 | 出处 |
```

模板由 `python scripts/check_episode_plan.py init-template` 生成。集号须连续、集数与需求登记表一致；素材不足用 `___` 占位并进缺口清单，**禁止编造素材里没有的事件**（沿用 HK-09 的填空纪律）。

## EP-02 三要素字段定义（硬性）

| 字段 | 写什么 | 不写什么 |
|---|---|---|
| 本集核心事件 | 一集只写一件主事件，动词明确 | 不写「主角继续成长」这类无事件概述 |
| 明确冲突 | 谁和谁、争什么、这一集没解决 | 不写情绪形容词、不写「氛围紧张」 |
| 本集信息增量 | **观众／剧中人本集新知道的事实**（身份、因果、规则、关系、物证） | 不写钩子复述、不写「爽点升级」、不写上一集已知信息 |
| 尾钩 | 集尾停在哪一秒、卡矛盾还是卡情绪（HK-05 三条件） | 不写「留悬念」三个字 |
| 出处 | 原文 CH/章节号或细纲条目编号 | 不写「据大纲精神」 |

正例：`明确冲突＝李承泽要查纪谨案，陈郡谢氏压着卷宗不给；本集信息增量＝观众新知道：凶手是谢风，且府衙早已备好替罪羊`。
反例：`本集信息增量＝反转再升级，观众更想看下一集`——这是效果描述，不是事实。

## EP-03 信息增量必须是「新增事实」（硬性）

判据：这句话回答得了「看完这一集，比上一集多知道了什么」。机检给两类告警：与同集核心事件／尾钩连续汉字重合 ≥8 字 → **INFO 候选**（可能是复述，人工判）；与相邻集信息增量逐字相同 → **FAIL**（等于这一集没有增量）。

信息增量允许「观众新知道」与「剧中人新知道」不同步（HK-02 的信息差三模式），但表里必须写清是**谁知道**；只写「知道了真相」不写主体，判字段不合格。

## EP-04 相邻集不重复，且不得靠删场换增量（硬性）

相邻两集的信息增量不得逐字相同；连续 ≥3 集用同一类增量（都是「又来一个反派」）进 INFO 提示，交人工判是否套路化。

**禁止用删铺垫、删场景的方式制造「信息密度」增量**——增量来自原文事实的释放顺序，不是靠砍戏。这与 HK-09「卡点强度不得靠删铺垫来换」同源。

## EP-05 出处回指（硬性）

每条核心事件与信息增量须回指原文行号／章节 ID 或细纲条目编号。缺出处不自动判杀，列 **INFO 待人工核对**；但**禁止脚本把「出处缺失」当成「已核对」**。理由：纲源本身可能有事实错误，回指只是把证据摆出来，不替用户拍板冲突。

## EP-06 S4 合并门：三要素缺一即杀（硬性）

闸门A 在 HK-09 钩子四维之外，并列加一条合并门，跑 `python scripts/check_episode_plan.py check --plan pipeline/01_分集规划表.md --episodes <集数或区间> --out outputs/01_分集规划检查.md`（口径见 EP-08）：

- 三要素（明确冲突／本集信息增量／尾钩）任一为空或占位 → 该集 **FAIL**，对应初稿版本不得写「通过」；
- 齐备率 < 100% → 不得写「HK-09 通过」；
- 脚本报告落盘，逐集给齐备数与缺项清单。**逐句语义仍由闸门A 人工判**，脚本只查字段与明显重复，不判「这一集好不好看」。

## EP-07 生成期注入（硬性）

`source_outline.py refresh` 打生成包时，把本集三要素行注入 `packets/ep{NNN}.md` 的「需求与预算」段。**只放进验收表、不进生成上下文，等于这一环没落地**——模型看不到「本集信息增量」，写出来自然还是只顾钩子和情绪。

## EP-08 集数口径：全剧 vs 中间批次（硬性）

`--episodes` 有两种口径，**不得混用**：纯数字 N ＝**全剧集数**（要求 1..N 齐备，向后兼容）；区间 `10-12` / 逗号列表 `10,11,12` ＝**中间批次**（只要求这批齐备）；不给则只查表内集号连续。口径写进 `episode_scope` 并随报告与 JSON 落盘 —— 「只跑第 10–12 集」的批次被按全剧口径判「缺 1..9 集」是口径错误，不是素材缺口。

`init-template --episodes 10-12` 直接生成第 10/11/12 三行，不必先生成 12 行再手改集号。**三要素表可单独成文件**：此时 `source_outline.py refresh` 会在生成包的「本集钩子预算行」明确标注「尾钩取自三要素表、与下方三要素行同源」，不再谎报「S1 尚未产出本集预算行」；两者都没有时才提示补 S1。

## 命令

```bash
python scripts/check_episode_plan.py init-template pipeline/01_分集规划表.md --episodes 10-12
python scripts/check_episode_plan.py check --plan pipeline/01_分集规划表.md --episodes 10-12 \
    --out outputs/01_分集规划检查.md --json outputs/01_分集规划检查.json
# 全剧口径（要求 1..8 齐备）：--episodes 8；只查连续性：不带 --episodes
python scripts/source_outline.py refresh --pipeline pipeline/   # 注入三要素行 + 钩子预算同源派生
```
