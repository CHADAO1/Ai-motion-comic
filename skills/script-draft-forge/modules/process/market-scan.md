# 模块 — 题材探测（市场速查）
> 类型：process · 挂载点：S0 选择 · 编号前缀：MS-

> 对标缺口：创一AI 的实时稀缺题材探测。本模块用"联网检索+本地沉淀"补位——起步不如 SaaS 的数据积累，但每次检索都沉淀在本地，越用越厚，数据是自己的。
> 挂载条件：用户想确认题材竞争力 / 选平台 / 看市场时挂载；纯创作不管市场可不挂。

## MS-01 联网检索（硬性）

S0 挂载本模块时联网检索目标平台近 90 天三样：①新增题材分布与播放增量（DataEye 月报等公开数据源）②平台热榜题材构成 ③题材相关监管动态。每条结论注明来源与采集日期；无日期的数据视为未完成，不得引用。

## MS-02 稀缺度速查表（硬性）

产出格式：`| 题材 | 近期供给量 | 热度信号 | 稀缺判定 | 依据+日期 |`。判定只许三档：**饱和 / 常温 / 稀缺**；证据不充分的标"证据不足"，禁止拍脑袋给判定。

## MS-03 数据沉淀（硬性）

每次检索结果**追加**到 `reference/market-baseline.md`（按平台分节、每条带日期）。季度复核时旧数据标 `[过期]` 保留不删——数据积累本身就是本模块的价值，历史轨迹能看出题材兴衰周期。

## MS-04 与 S0 的接口（硬性）

速查表结论写进 `pipeline\00_需求与体检.md` 的题材行：
- 稀缺 → 建议主攻，注明依据
- 饱和 → 提示差异化（建议挂 ST-06 奇兵版型）或换平台，交用户决策
- 证据不足 → 如实告知，**不阻塞创作**（市场探测是参谋不是门卫）

## MS-05 时效闸门（硬性，2026-11-04 新增）

`scripts/topic_radar.py` 是 MS-02/03 的可执行补位，挂载本模块时**先跑** `python scripts/topic_radar.py check`：

- 数据 ≤90 天 = 新鲜；91-180 天 = 需复核（只可提示，不可作稀缺判定依据）；>180 天或无采集日期 = 过期。
- `query` 命中过期/无日期依据时直接退出码 1；**过期数据禁止写进报告结论**。
- 本快照是「二手汇编 + 本地沉淀」，**不是实时 API**。每次做市场判断仍须按 MS-01 联网复核，报告写明「数据采集日期 + 来源」。
- 与 script-market-audit 的 PL-06 时效自查一致：复核结果与本地记载冲突时以复核为准，并注明「原记载已过期，实际为 X」。

## MS-06 快照刷新与沉淀纪律（硬性）

- 复核后的新数据写成 `{"entries":[...]}` JSON，跑 `python scripts/topic_radar.py refresh --input 新快照.json`；脚本自动给旧同题材条目标 `[过期]` 并保留，新条目重新编号，符合「只追加不删改」。
- 新条目必须带 `collected_at` 与 `source`；缺来源的由脚本标注「待补」，交付前必须补齐。
- 人读索引 `reference/market-baseline.md` 与机器源 `reference/topic-snapshot.json` 同步维护；季度复核在索引 §4 追加一行。
- **禁止把快照数字当实时结论**，禁止为凑结论把「证据不足」硬判为稀缺；也禁止虚构数据源名称或采集日期。

## 与 SaaS 竞品的差距（如实记录）

创一 AI 的题材探测器接实时榜单数据流，本模块没有。补位是「MS-01 联网检索 + 带日期快照 + MS-05 时效闸门 + 越用越厚的自有沉淀」；
起步数据薄是事实，每次检索都沉淀在本地，长期价值在数据所有权而不在首日规模。
