# 模块 — 净稿（原文清洗）
> 类型：process · 挂载点：N0 原文入库 + S0 素材体检 + S5 交付留痕 · 编号前缀：SH-

> 为什么有这个模块：小说转剧本链路的第一环是原文净稿——番外／作者附言／转载站广告／乱码行没有规则时，带着脏原文入库，后面所有「事实以原文为准」的验收都会拿广告行当事实。
> **授权模块（原前两节）已于 2026-11-09 剥离删除**；为避免连锁改号，SH-03~07 编号保持不变，原前两节编号永久弃用。

## SH-03 净稿副本原则：原文件不改，删除逐条登记（硬性）

`ingest` 只读原始文件，清洗结果另写 `pipeline/原文纯文本.txt`（唯一入上下文的原文基准），并在 `pipeline/00_净稿报告.md` 逐条列出：**源文件 / 原始行号 / 原句全文 / 命中规则 ID / 删除理由**。禁止默删、禁止只报「已清洗 N 行」。

`source-index.json` 增 `cleaning` 字段记录删除数、标记数、净稿 sha1；`10_原文索引.md` 附净稿小节。**原文件 sha1 必须保留**，用于回溯「这一句被删之前在哪」。

## SH-04 剔除类别与置信分层（硬性）

默认词表 `reference/source_clean.rules.json` 分三类，`exclude-patterns` 可追加项目专属规则：

| 类别 | 典型内容 | 默认动作 |
|---|---|---|
| 整行噪声 | 未完待续／点击下一页／求订阅求月票／网站地图／转载请注明／版权页广告／上一本推荐／**本站所有小说为转载作品…整行免责声明** | **remove**（高置信：整行精确匹配，不碰正文） |
| 板块头 | 番外／番外篇／作者有话说／上架感言／完本感言 | **flag**（默认只标记；整段剔除须显式开启，见 SH-06） |
| 疑似脏行 | 替换符 U+FFFD／锟斤拷／方框乱码／非汉字占比过高 | **flag**（只标记，见 SH-05） |

正例：`（未完待续，请点击下一页继续阅读）` 整行命中 remove，登记后从净稿剔除。
反例：把含「作者」二字的正文章节标题当作者附言整段删掉——板块头默认只标记，就是为了防这个。

`SH-L01~05` 为 v1.0 原有规则；**`SH-L06`（v1.1 新增）**专删「本站所有小说为转载作品，所有章节均由网友上传…」整行免责声明——第 10–12 集回归实测这 3 行曾漏进生成包。疑似脏行的标记 ID 为 `SH-G01`（v1.1 由 `SH-L06` 改号），与整行噪声规则不共用编号，避免删除登记里分不清「删了」还是「只标了」。

## SH-05 乱码行只标记不自动删（硬性）

乱码行可能是转码问题，也可能是正文里的方言／拟声／外文，机检分不清。一律进报告的「待人工确认」清单，由人决定删、修还是留。**脚本不得因为「看不懂」就删正文**——这与 CR-18「事实以原文为准」直接冲突。

## SH-06 章节级板块剔除须显式开启（硬性）

`番外`／`作者有话说` 这类板块头之后的整段，默认**不删**。只有配置 `apply_sections=true` 或显式 `--apply-sections` 才按「板块头 → 下一个章节标题」切片剔除，且每段的起止行号与字数必须登记。理由：番外里可能含正片要用的设定，一刀切会连事实一起删掉。

安全上限：删除字符数占原文比例超过 `max_removed_ratio`（默认 0.05）时，整体降级为「只标记不删除」并告警，防止规则写宽了把正文清空。

## SH-07 验收门与产物（硬性）

S0 通过条件新增一项：`00_净稿报告.md` 已落盘且待确认清单有人处置，缺一不得进 S1。

S5 交付时该文件随初稿包一起呈现。报告只陈述删除／标记事实，**不写「环节 1 已完成」之外的合规性结论**——净稿覆盖不了授权与法律效力，那不是本模块的职责。

## 命令

```bash
python scripts/source_outline.py ingest --source <原文> --outline <纲> --pipeline pipeline/
# 项目专属追加规则：--exclude-patterns <正则> --exclude-patterns <正则>
# 关闭清洗：--no-clean ；整段剔除番外/作者附言：--apply-sections
```
