# 模块 — 按纲改编（小说原文 + 编剧大纲/细纲 → 初稿）
> 类型：process · 挂载点：S0 选择 + S3 生成 + S4 附加验收 · 编号前缀：SO-

> 对标缺口：Mode 1 只收「素材」（简介/对标/想法），遇到整本小说 + 编剧已定细纲时会出两个错——
> 全文塞进上下文必然爆窗，且模型会自作主张改结构。本模块把「按纲改编」独立成 Mode 3：
> **结构听细纲、事实听原文、差异化只在呈现层、逐条落地由脚本验收**。
> 挂载条件：用户给出小说原文 + 大纲或细纲并要「出初稿」时自动挂载（Mode 3）；Mode 1/2 不挂。

## SO-01 输入契约与优先级（硬性）

三件套：**小说原文**（必需）、**细纲**（推荐）、**大纲**（可选）。细纲与大纲至少给一份；只给大纲时按「事件锁定」执行（不锁逐场结构，仍锁事件）。同一份文件可用 `# 大纲` / `# 细纲` 分节，也可分文件都传给 `--outline`。支持 `.txt/.md/.docx`（原文与纲）、`.csv/.tsv/.xlsx`（表格细纲）、整目录。

优先级只有两句，冲突时不再问第二遍：

| 判断对象 | 以谁为准 | 说明 |
|---|---|---|
| 事件、顺序、卡点、场次结构 | **细纲 > 大纲 > 原文** | 细纲是编剧已经拍过的板，模型不得「优化结构」 |
| 人名、称谓、背景、世界观、金手指条款、既定事实 | **原文 > 细纲 > 大纲** | 细纲写错名字或与原文设定冲突，按 SO-06 登记，不静默跟随 |

改编剧走 CR-18 三策（好 IP 不画蛇添足 / 部分好则补强 / 删凑字），毒点按 CR-19 砍，但**砍与不砍的最终决定权在用户**（SO-06）。

## SO-02 原文入库与按集切片（硬性）

整本原文**禁止整体入上下文**。先跑 N0 入库，切成带稳定 ID 的章节（`CH001`…），再按细纲的章节引用把「本集原文切片」打包进生成包。

- 细纲写显式引用：`原文第3-5章` / `原文第2集` / `对应@CH003-CH005` → 切片作准。
- 未写引用：脚本按左右邻居的显式引用插值**推定**分配，并在纲解析报告里逐集列「推定分配」告警；全剧无引用时按篇幅均分并单独告警。
- 单集切片超 `--packet-max-chars`（默认 16000 字符）**显式截断并标注**，禁止偷偷把全文另塞一份进上下文；要更多内容就细纲写显式引用 + 分批跑（CC-03）。
- 从 docx 复制出来残留 `<w:t>` 片段的脏文本会自动清洗并反转义；章节标题不认可用 `--chapter-pattern` 自定义正则。
- 人名/术语只出**候选表**（频次 + 出处），不是事实；S0 五维拆解（CR-01）与 S2 建档（DR-02/04）必须回原文核对后才算既定事实。

## SO-03 细纲锁定结构（硬性，铁律 6 的唯一例外）

Mode 3 下**事件结构锁定**：细纲条目必须逐条落地、顺序不得重排、不得新增大纲外大事件。用户明确说「细纲仅供参考 / 按原文重新结构」才恢复 Mode 1 的结构差异化。

同集多版差异化降级到**呈现层**，且每版要在文件头声明差异轴，四选一以上：

| 差异轴 | 可改 | 不可改 |
|---|---|---|
| 切入点 | 本集第一场从哪个瞬间起 | 事件集合与顺序 |
| 场面调度 | 画面呈现、快剪分法、信息交代方式（CR-12） | 细纲条目 |
| 台词密度 | 台词轮次、留白、OS 比例（CR-13） | 人物底色与既定事实 |
| 卡点切法 | 断在哪一句/哪个动作（CR-15 / HK-05） | 卡的是哪个矛盾 |

版本头部（MR-06）必须多写一行：`结构：细纲锁定 · 差异轴：{切入点/调度/台词密度/卡点}`。索引里每集标「结构锁定」，A7 的「结构差异化」判定改判「呈现层差异化」。

## SO-04 逐条落地与编号（硬性）

细纲每条自动编号 `EP{NNN}-B{NN}`，写「可选」的条目不参与判杀，其余一律**必留**。生成包第五节就是覆盖清单，生成时逐条对照。

- 细纲没覆盖的集**禁止出稿**（脚本 GA-06 直接判杀）；要加集先补细纲。
- 创作时不得把两条细纲并成一条、不得把一条拆成两集、不得调换顺序。
- 每集生成前注入：本集细纲原文 + 本集原文切片 + DR-01 四件套 + 本集钩子预算行（HK-01）+ 前序集细纲摘要。**衔接靠读生成包，不靠模型记忆**（DR-01）。

## SO-05 无原文依据条目与新增事件（硬性）

纲解析报告标「未在原文切片中找到锚点」的条目、`12_纲解析报告.md` 的推定分配告警、`01_体检报告_纲源.md` 的 GA-08 疑似新增事件，全部是**编剧的改编决定，不是错误**：

- 不擅自删、不擅自改、不擅自当原文事实写进剧本；
- 逐条进 S5 **挑稿决策点清单**，格式：`编号｜细纲原文｜原文依据（有/无）｜需用户确认什么`；
- 用户确认「就是新增的」→ 记入前情提要，后续集按新增事实执行（DR-01）；用户确认「写错了」→ 回 N1 改细纲再重跑，不精修已出稿。

## SO-06 原文与细纲冲突登记（硬性）

冲突三类：人名/称谓不一致、设定/金手指边界不一致（DR-03）、事件因果与原文既定事实矛盾（CR-10 情理门）。处理方式：

1. 脚本只做锚点提示，**不自动判谁对**；在纲解析报告与体检报告里列证据（行号 + 原文切片 + 细纲编号）。
2. 按 SO-01 优先级给出建议，但**改动决定由用户拍板**；拍板结果写进 `pipeline/13_改编决策.md`，并在 S5 决策点清单里回应。
3. 毒点按 CR-19 评估「砍前段还是砍整条线」，同样不替用户决定。

## SO-07 覆盖验收脚本化（硬性，闸门A 附加项）

Mode 3 的 S4 除 preflight 全清单 + GA-01~05 外，必须再跑 `scripts/source_outline.py check`，产出 `outputs\01_体检报告_纲源.md`（GA-06~08），两份脚本报告都随交付落盘。

- **GA-06 细纲覆盖**：必留条目锚点在初稿中零命中 → FAIL 判杀；无锚点条目退化为内容词预警 + INFO 人工核对。
- **GA-07 原文忠实**：说话人不在原文人名候选表 / 细纲人物标签里 → INFO 列行号，回原文核对（DR-02/04）。
- **GA-08 新增事件**：命中重大事件词且不落在本集任何细纲锚点上的行 → INFO 列原文，定性归 SO-05。
- **禁止模型自报覆盖**：「这一集细纲都写到了」不算交付，只认脚本的命中数 / 覆盖率 / 行号。锚点命中不等于语义覆盖，逐条语义判定仍要带行号证据写进体检报告。

## SO-08 生成包与断点续跑（硬性）

- `pipeline\packets\ep{NNN}.md` 是**每集唯一可入上下文的输入包**，落盘可复查。
- S1 钩子预算 / S2 锚点建档完成后，跑一次 `refresh` 重打生成包，把预算行与四件套注入；不带 `--source/--outline` 即读缓存，不重解析原文。
- 改原文或改细纲 → 回 N0 重新 `ingest`；只改预算/锚点 → `refresh`；只重出某集 → Mode 2 补版，覆盖验收只复验该集。
- manifest.json 增记 `mode: "3"`、`modules_loaded: ["process/source-outline"]`；中断从第一个非 done 的 N 阶段续跑。

## 输入格式速查（照抄即用）

```markdown
# 大纲
## 第1集
落水获救，摸清处境，系统首次触发。

# 细纲
## 第1集｜落水获救｜原文第1-2章｜钩子：身份揭露
- 宁清和落水，谢知予救他上岸｜人物：宁清和、谢知予｜锚点：宁清和|谢知予|落水
- 系统触发，宁清和得到手表｜锚点：系统|手表
- （可选）围观群众议论，补气氛

## 第2集｜原文第3章
- ...
```

行内标签：`原文第X-Y章` / `原文第N集` / `@CH00X-CH00Y`（切片）、`人物：` / `锚点：a|b`（覆盖验收）、`钩子：`（预算）、`可选`（不判杀）。模板用 `python scripts/source_outline.py init-template <目录>` 生成，也支持表格 `.csv/.xlsx`，列名 `集号,场次,内容,原文范围,钩子,人物,锚点`。

## 诚实边界（如实记录）

- 脚本**不判断语义**：锚点命中只证明词出现；「细纲真的落地了」仍需闸门A 带行号证据逐条判定。
- 章节自动分配是**推定**，人名/术语是**候选**，都不是事实；不写显式引用就要人工确认。
- 没有自动解决原文与细纲冲突的能力，只能把证据摆出来，决定权在用户（SO-06）。
- 本模块不生成图片/视频/终稿，产物止于初稿包（铁律 1 / S5）。
