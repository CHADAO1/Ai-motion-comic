# 市场基线沉淀库（market-baseline）

> 题材探测模块（MS-03）的沉淀文件。每条必带日期；季度复核旧数据标 `[过期]` 保留不删。
> 机器可读的唯一事实源 = `reference/topic-snapshot.json`；本文件是**人读索引与历史轨迹**，两者由 `scripts/topic_radar.py` 同步。
> 归档 2026-11-02 创建，2026-11-04 填入首批快照。

## 0. 先读这句

**本库不是实时题材探测器，也不冒充。** SaaS 竞品接的是实时榜单数据流；本技能给的是
「带采集日期的本地快照 + 强制时效闸门 + 越用越厚的自有数据」。实时性由 MS-01 联网检索补齐，
脚本负责：沉淀（MS-03）、到期提醒（MS-05）、禁止引用过期数据、复核后刷新（MS-06）。

```bash
python scripts/topic_radar.py --at-date YYYY-MM-DD check      # 时效体检
python scripts/topic_radar.py query --topic 穿越 --platform 红果
python scripts/topic_radar.py refresh --input 新快照.json      # MS-01 复核后导入
```

## 1. 使用约定

- 按平台分节追加，newest 在上。
- 格式：`| 日期 | 题材 | 供给信号 | 热度信号 | 稀缺判定 | 来源 |`
- 稀缺判定只许三档 **饱和 / 常温 / 稀缺**，证据不足写「证据不足」（MS-02），禁止拍脑袋。
- 只追加不删改；被复核推翻的旧条目标 `[过期]` 并保留，历史轨迹能看出题材兴衰周期。
- 引用本文件任何数字，报告里必须写「数据采集日期：YYYY-MM-DD｜来源：___」。

## 3. 读法（别照着数字抄）

- **饱和的是套路，不是题材**：同素材「资助贫困生被反咬」原版进不了 TOP10，换「女本位+搞钱」视角冲榜三。
- **平台选择先于模型选择**：同题材投错平台成绩天差地别；S0 素材体检必须先定目标平台。
- **强时效项**（付费机制、监管）每次判断前按 PL-06 / MS-01 联网复核，与本地记载冲突时以复核为准。
- 「证据不足」是有效结论，不许为了给建议硬判稀缺（MS-02）。
