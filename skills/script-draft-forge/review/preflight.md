# 审查模块 C1 — 闸门A验收清单（Preflight）

> 总控在 S4 读本文件。对每个初稿版本逐项过，任一 ❌ 该版本判杀并记死因。

## 使用原则

1. 完整性以要素计数为准，禁止最低字数标准——短而全即合格。
2. 每个 ✅/❌ 必须附可核查证据：行号/台词原文/数值/名单；"已检查""无问题"按未检查处理。
3. 多集任务附《逐集验收表》落盘 pipeline/。

## S0 净稿门与 S4 合并门（SH-03~07 / EP-01~07，2026-11-06 补）

> 这些条款来自「小说转剧本 7 环节」核查：环节 1「净稿」此前全库空白（原「授权登记/字段核对」两节已于 2026-11-09 剥离删除），环节 3「季/集规划」的「信息增量」无字段、三者从没一起判过。S0 不过不得进 S1；S4 不过不得写「HK-09 通过」。
>
> 编号索引：SH-03 净稿副本与不默删 / SH-04 剔除类别置信分层 / SH-05 乱码只标记 / SH-06 板块剔除须显式开启 / SH-07 验收门；EP-01 表为 S1 必产物 / EP-02 三要素字段定义 / EP-03 信息增量＝新增事实 / EP-04 相邻集不重复 / EP-05 出处回指 / EP-06 S4 合并门 / EP-07 生成期注入 packets / EP-08 集数口径（全剧 vs 中间批次）。

- [ ] **净稿门（SH-03~07，硬性）**：`ingest` 已产出 `pipeline/00_净稿报告.md`；删除项逐条有「原始行号／原句／规则 ID／理由」，乱码行与番外板块头在「待人工确认」清单里有人处置。**报告落盘且待确认清单有人处置才得进 S1**。报告行号（清洗前）与索引表行号（净稿）是两套口径，不得混用。
- [ ] **分集规划合并门（EP-06/08，硬性）**：跑 `python scripts/check_episode_plan.py check --plan pipeline/01_分集规划表.md --episodes <集数> --out outputs/01_分集规划检查.md`；**三要素（明确冲突／本集信息增量／尾钩）齐备率 100% 才准写「HK-09 通过」**，缺一即该集 FAIL、对应初稿版本不得判过。**`--episodes` 两种口径**：纯数字 N＝全剧（要求 1..N 齐备）；`10-12`／`10,11,12`＝中间批次（只要求这批齐备，不再误报缺 1..9）；不给＝只查表内集号连续。报告与 JSON 的 `episode_scope` 写明本次口径。脚本只查字段与明显重复，逐句语义仍由闸门A 带证据判。
- [ ] **报告不入验收分母（硬性）**：`--out` 写进 `outputs/` 时，三个脚本会自动排除报告／索引／登记类文件（`_text_util.is_draft_candidate()`：编号前缀 + 名称关键词 + 首部标题双层判定）。`check_adapt.py --files` 用 glob 时同样过滤并打印 SKIP；确需验收报告类文件用 `--no-filter`。**不得用「报告被算进分母后的一堆 FAIL」当验收结论**。

## 脚本化硬指标（GA-01~12，硬性）

> 写作极限测试与挑稿测试实测：轮次、字数这类硬指标靠模型自己数不可靠；闸门A 还缺「人设逐场核对」「系统条款不新增」。以下前五项由 `scripts/check_gate_a.py` 承担，脚本只报数值与证据，不评好坏。
> GA-12 是**稿件形态门**（只判有没有戏，不判好坏、不设字数下限），默认启用；不达标写「不予验收」，不等于内容违规。
> GA-09~11 为 2026-11-06 补入，对应 `modules/process/dialogue-pass.md`：小说转剧本链路里「对白二次调整」返工率最高，此前既无独立工序也无机检项，导致叙述腔直搬旁白、书面语长句、A/B 逐字同旁白漏到人工挑稿才被发现。

- **GA-01 轮次/字数脚本核对（硬性）**：台词轮次、汉字数、段落字数一律取脚本输出；配置未给范围时只报数不判杀，避免误杀。退出码 1 = 有 FAIL。
- **GA-02 人设逐场核对（硬性）**：逐场说话人名单与小传比对；等长一字之差的人名判疑似混用（如 宁清河/宁清禾）；`name_aliases` 旧名命中即挂；固定特征可按需强制全数出现。
- **GA-03 系统条款不新增（硬性）**：扫描「系统/金手指 + 自动|新增|升级|结算|每月|到账」等新条款句式，未命中 `system_rules` 白名单即挂；无白名单时只列行号交人工逐条核对，不阻塞。
- **GA-04 情绪名称词 lint（硬性）**：纯情绪名称词无行为支撑、AI 套话（瞳孔骤缩/眼底/冷笑等）即挂，复用 CR-17。
- **GA-05 术语零变体（硬性）**：`term_aliases` 命中的旧写法即挂，复用 DR-04。

配置模板用 `python scripts/check_gate_a.py --init-config pipeline/gate_a_config.json` 生成；脚本自检用 `--selftest`。

### 对白二次调整三项（GA-09~11，挂载 DP 模块时为硬门）

> 与 `scripts/adapt_gate.py` 的 G9 共用 `scripts/_text_util.py`，正文边界、汉字归一、旁白行、最长公共子串四处口径必须一致，否则同一份稿会出现两种结论。
> **未挂载 DP 模块时 `enforce_dialogue=false` 只报数不判杀**；GA-10 未给 `--source` 原文切片时降级 INFO 并提示跳过，不假装检查过。

- **GA-09 单句 8–15 字（按超长句占比判，硬性）**：依 DP-02 把人物台词按句末标点切句，数汉字（不含角色名、标点、括号动作）。**判杀分子只有 `>15 字` 的超长句**，其占比 > `dialogue_max_ratio`（默认 0.20）才 FAIL；`<8 字` 的短节奏句合法，登记例外、不计入分子（实测 v3 两版短句占 33%／42%，按「区间外总占比」判会挂上即全杀）。逐句判杀同样误杀「滚。」「我不！」。例外（专有名词／数字读法／有意长台词）写进 `pipeline/04_对白调整登记.md`，不删信息、不新增台词。书面连接词与叙述腔评价的替换口径依 DP-03，人物声口仍受 CR-13 约束。附三个只报数不判杀的顺口候选：连续标点、一行内 ≥2 组括号插入、单句 >25 字（DP-04）。动作括号里的冒号（如「特写：」）不计为说话人。
- **GA-10 旁白与原文连续重合（硬性）**：旁白与原文切片连续汉字重合 ≥ `lift_min`（默认 8 字，经验值）→ 判叙述腔直搬（DP-06：概述句／时间跨度／叙述者调侃须转一场戏、一次剪切或直接删）。逐字重合抓不到**改写型解说旁白**，那部分由 adapt_gate 的 G9 与 DP-05 人工判。
- **GA-11 A/B 同一旁白逐字相同（硬性）**：跨文件比对同集两版旁白，逐字相同即挂（DP-07：事实层一致靠共用事实台账，不靠共用解说词）。

### 稿件形态门（GA-12，默认启用）

> 2026-11-06 第 10–12 集回归实测：12 份 DRY 演练占位稿（0 场、0 句人物对白）被两个验收入口全判「验收通过」。门只查「有没有违规」，不查「有没有戏」，和「16/16 全绿」是同一类病。**GA-12 与 DP 模块挂载无关，默认启用；不设字数下限**（禁止最低字数），不判语义、不判质量。
> 与 `scripts/check_adapt.py` 共用 `_text_util.draft_shape()`；场次宽松识别 `【场1｜…】`／`## 场1`／`第1场`／`1-1　日　外　…`，避免把「格式不同」误判成「没有戏」。

- **GA-12 稿件形态（硬性，不予验收）**：演练/占位标记（DRY-RUN）、人物对白句为 0、场次标记为 0，任一命中即 FAIL。结论写「**不予验收**」而不是「违规判杀」，与 GA-01~11 分开陈述；补正文后复跑。`config.skip_shape_gate=true` / `check_adapt.py --skip-shape` 只关判杀、数值仍留痕，**仅用于兼容存量异格式稿，不得当验收结论**。
- 正例：一场一句「甲：滚。」→ 形态达标（不因字数少被杀）；`1-1　日　外　国营饭店门口` 格式的真稿 → 场次数正常，达标。
- 反例：DRY 演练占位稿、只有旁白没有人物台词的空稿 → 不予验收。
- **退出码**：`check_gate_a.py` 与 `check_adapt.py` 均在有 FAIL／未通过／不予验收时返回 1，全部通过才返回 0；命令链与 CI 不得只看文案。

自检：`python scripts/check_gate_a.py --selftest`、`python scripts/adapt_gate.py --selftest`、`python scripts/check_adapt.py --selftest`、`python scripts/_text_util.py`；配置模板 `python scripts/adapt_gate.py --init-config pipeline/adapt_gate_config.json`。

## 按纲改编附加硬指标（GA-06~08，硬性，仅 Mode 3）

> 由 `scripts/source_outline.py check` 承担，报告 `outputs\01_体检报告_纲源.md`。
> 规则依据 `modules/process/source-outline.md`（SO-04/05/07）。**锚点命中只证明词出现，不证明语义覆盖**——
> 脚本给数值与行号，逐条语义判定仍由闸门A 写进体检报告；禁止用「这一集细纲都写到了」替代脚本输出。

- **GA-06 细纲覆盖（硬性，可判杀）**：每条必留细纲条目 `EP{NNN}-B{NN}` 的锚点在初稿中零命中 → FAIL 判杀；细纲未给锚点时退化为内容词漏项预警并标 INFO 人工核对。细纲未覆盖的集直接 FAIL（SO-04）。报告给每版命中数 / 覆盖率。
- **GA-07 原文忠实（硬性，INFO）**：说话人不在原文人名候选表 / 细纲人物标签 / `gate_a_config.json` 白名单 → 列行号，回原文核对是否新增角色或异写（DR-02/04）。人名候选表为空时整体降级为 INFO，不误杀。
- **GA-08 大纲外新增事件（硬性，INFO）**：命中重大事件词（死亡/结婚/身世揭露/系统升级…）且不落在本集任何细纲锚点上的行 → 列原文与行号，是否属新增按 SO-05 交用户拍板，脚本不定性。

自检：`python scripts/source_outline.py selftest`；输入模板：`python scripts/source_outline.py init-template <目录>`。
