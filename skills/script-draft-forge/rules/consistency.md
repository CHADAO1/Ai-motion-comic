# 规则模块 — 一致性注入（DR）

> 总控在 S2（建档）、S3（每次生成前注入）读本文件。前缀 DR-*。
> 病根实证：长线生成"忘设定"（第 40 集人物关系开始乱、第 3 集孤儿第 30 集冒出妈）——解法是注入不是换模型。

## DR-01 一致性注入强制（硬性）

**每次生成调用必须注入四件套**，缺一不得出稿：
1. 人物小传（S2 产物，按本场出场角色筛选注入）
2. 金手指卡（CR-04 登记，主角相关场次必注）
3. 前情提要（此前集数的剧情摘要 + 未回收伏笔清单，来自钩子台账 HK-07）
4. 术语表（S2 产物，按需注入涉及条目）

注入方式：拼进生成提示词的上下文区，声明"以下是既定事实，不得改动"。禁止依赖引擎的对话记忆跨集衔接——**衔接靠读文件，不靠记忆**。

## DR-02 人物小传（硬性）

每个主要角色一张卡，**固定特征 ≥5 项**（外貌、着装、口头禅、行为习惯、性格底色等——特征是可复述的具体细节，不是形容词堆砌）。人设卡同时服务下游：台词双重约束（CR-13）的对照基准。写重大决策前对照人设卡自问"以他的性格会这么做吗"。

## DR-03 金手指登记（硬性）

S2 必须为主角登记金手指（CR-04 宽定义），卡片三行：**是什么 / 边界在哪 / 何时升级**。边界行是情理门（CR-10）的判据——超出边界的能力使用即不合情理。金手指中途变化必须记入前情提要。

## DR-04 术语表全剧唯一（硬性）

人名、称呼（A 叫 B 什么）、地名、专有名词、力量体系等级——**一次定稿，全剧唯一**。生成中发现引擎用了变体写法（如"李总/李董事长"混用），以术语表为准纠正并记入生成记录。新术语出现 → 先入表再使用。
