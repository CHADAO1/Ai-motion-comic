# 规则模块 — 引擎路由（MR）

> 总控在 S3（多版初稿分配引擎）、S5（交付标注）读本文件。前缀 MR-*。
> 原则：**规则层（CR/HK/DR）永不绑模型名**；引擎只承载语言质感与结构执行力，专业度来自规则层。
>
> **宿主优先级（OpenCode）**：本文件 MR-03 的静态引擎表是历史推荐快照；在 OpenCode 宿主下，
> `rules/opencode-adapter.md` 的 **OC-\*** 优先——OC-01 用 `tools.opencode.models` 实时探测可用模型建路由表，
> OC-03 用 `subagent` 显式指定模型做真派发。本文件只在「需要外部端点逐档直调」时作为
> MR-07 / MR-08（`scripts/engine_dispatch.py`）的依据。禁止把 MR-03 的榜单名当作当前可用模型。

## MR-01 规则层模型无关（硬性）

rules/ 与 modules/ 中除本文件外禁止出现具体模型名；引擎变更只改本文件 MR-03 表，不动其他任何文件。

## MR-02 引擎分工（按能力路由，不点名）

| 职责 | 能力要求 |
|---|---|
| 骨架/大纲/反转节点 | 逻辑推演强、结构感 |
| 台词填肉 | 口语感、语气词停顿潜台词、中文网感 |
| 通用初稿 | 中文叙事均衡、性价比 |
| 挑稿评估/多稿合并/终审排序 | 长文理解、审美判断、跨稿整合 |

## MR-03 默认引擎表（2026-11-04 复核：四基准 + 两轮实测；快照见 reference/benchmark-snapshot-2026-11.md）

**长文本剧本不按「一个模型写到底」路由，按六个岗位分工。** 这是长文本工作流与单集写作的本质区别——单集拼语言，长文本拼分工与记忆。

| 档位 | 职责 | 默认引擎 | 何时用 |
|---|---|---|---|
| **骨架档** | 大纲、反转节点、卡点设计 | DeepSeek 系 | S1 |
| **定调档** | 第 1 集（或每卷首集）定语气基准 | Claude Opus 5.5，effort high | 每卷仅 1 集 |
| **台词档** | 台词重写、口语化、人物声口 | Kimi K3.1 Pro（内置） | S3 台词精修 |
| **批量档** | 第 2–40 集正文 | GLM-5.3 Flash 或会话默认 | S3 批量出稿 |
| **挑稿档** | A/B 择优、合并、终审排序 | 混元 Hy4（内置）；备选 Claude Opus 5.5 | S4 / S5 |
| **回顾档** | 每 10 集卷级回顾、长线钩对账 | Claude Opus 5.5 | 每 10 集一次 |

各档依据：

- **骨架档**：反转逻辑最硬（假希望→打脸→更大悬念三层递进）。其人物关系因果是弱项、中文创意写作实测偏弱——骨架可用，**台词位禁用**，情理门验收不可省。
- **定调档**：长篇八章 17.53 第 1、Arena 创意写作 1534.4 第 1、NC Bench 作者工作流 96.43% 第 1。后续所有集以它为语气基准。
- **台词档**：EQ-Bench rubric 16.63 中文创作最高、NC Bench 96.26% 第 2；口语质感优于定调档且价格约 1/6。
- **批量档**：中文叙事前段班、单稿成本极低，适合多版并行。**这是省钱位，不是质量位。**
- **挑稿档**：2026-11-04 挑稿卷 40/40 第 1（5 条核心硬伤 + 2 条加分全中，卡点翻出「父亲遗物」新账）；Claude 39 并列第二。注意该卷只测「按规则挑错」，测不到开放创作力。
- **回顾档**：1M 上下文可一次装下十集，做全局情绪强度曲线与长线钩兑现对账；这是其他档位替代不了的位。

### 分工纪律（MR-03 附则，硬性）

1. **按「集」切，不按「场」切。** 同一集只能由一个引擎写完；换引擎只能发生在集与集之间。跨引擎写同一集，声音会在接缝处断裂——这是混合开发最常翻的车。
2. **定调只做一次。** 每卷首集用定调档一次成型，后续集照它抄口音；禁止每集重新定调，也禁止中途换定调引擎。
3. **一致性靠外置记忆，不靠模型。** DR-01 四件套 + HK-07 钩子台账 + CC-03 前情压缩 + 卷级回顾；禁止用「换更强的模型」代替记忆注入——40 集不漂移靠架构，不靠单价。
4. **最强引擎不写全程。** 定调档、回顾档是低频高价值位；批量档必须用便宜档位（见 CC-02）。定调档全程写 40 集＝240–400 元且会撞上下文天花板。
5. **验收线不随引擎浮动。** 闸门A标准与引擎无关，换便宜引擎不降验收标准。

### 两套预设组合

| 预设 | 组合 | 40 集成本 |
|---|---|---|
| **质量优先**（推荐） | 定调/回顾＝Claude Opus 5.5；台词/批量＝Kimi K3.1 Pro；挑稿＝混元 Hy4；骨架＝DeepSeek | 约 10–15 元（外部） |

## MR-04 多版多引擎（硬性）

每集多版优先分给不同引擎（或同引擎不同结构参数）——**版本差异 = 结构差异（挂载模块组合）+ 引擎差异**，两个维度至少占一个。全部版本同引擎同结构 = 假多版，S4 直接判杀。

## MR-05 降级（硬性）

无可路由的外部引擎时，全部职责降级为当前会话模型执行，流程照常不阻塞；交付说明注明"降级：会话默认模型"。

## MR-06 产物可追溯（硬性）

每个初稿版本文件头部标注：`版本：ep{NNN}_{版型}_v{n} · 引擎：{名} · 挂载模块：{…} · {日期}`。换引擎后可用同一素材重跑对比引擎质量（产物头部即对照依据）。

## MR-07 本机端点映射（2026-11-04 实机验证）

> 本条只记录「档位 ↔ 选择器条目 ↔ API `model` id」的对应关系，**不改 MR-03 的分工与验收线**。配置文件为 `~/.config/opencode/models.json`；保存后自动重载（必要时 /reload）。

| 档位（MR-03） | 选择器显示名 | API `model` id | 用途 |
|---|---|---|---|
| 定调 / 回顾 / 挑稿备选 | Claude Opus 5.5 (DMXAPI·挑稿评估) | `claude-opus-5-5` | 每卷首集定调、每 10 集回顾、A/B 终审 |
| 骨架 | 骨架档 · DeepSeek V4.1 Flash (DMXAPI) | `deepseek-v4.1-flash` | S1 大纲、反转节点、卡点设计 |
| 骨架备选 | 骨架备选 · DeepSeek V4 Pro (DMXAPI) | `deepseek-v4-pro` | 复杂反转结构、逻辑推演吃紧时 |
| 台词 | 台词档 · Kimi K3.1 Pro (DMXAPI) | `kimi-k3.1-pro` | S3 台词精修、口语化、人物声口 |
| 批量 | 批量档 · GLM-5.3 Flash (DMXAPI) | `glm-5.3-flash` | S3 第 2–40 集正文（省钱位） |
| 挑稿 | 挑稿档 · 混元 Hy4 (DMXAPI) | `hy4` | S4 / S5 择优、合并、终审排序 |

**验证口径（2026-11-04）**：6 条端点全部经 `/chat/completions` 实机调用返回 200，且逐条通过 function calling 实测（返回 `tool_calls`）；配置 `supportsToolCall=true` 有依据。以上模型原生返回 `reasoning_content`，但 `supportsReasoning` 保守设 `false`（不向端点发送 reasoning 参数），实测不影响正文。

**思考预算实测（重要）**：推理模型先消耗 `reasoning_content`，`max_tokens` 给小时 `content` 会是空字符串——给 80 时 6 条中 3 条空，给 200 时 `glm-5.3-flash` / `hy4` 仍空，给 400 / 800 时全部正常。**这不是端点故障，别把空正文误判为不可用**；会话默认生成预算通常远高于此，但走外部编排层直调时必须给足 `max_tokens`。直调可选加 `enable_thinking:false`（GLM 系实测思考 588→21 字符、completion tokens 137→9）或 `thinking:{"type":"disabled"}`（hy4 实测思考归零、tokens 2）降本；这两个是 API 侧开关，会话默认调用不会发送，故不影响本表配置。

**LIVE 实跑修正（2026-11-04，覆盖上段的短 prompt 结论）**：上面「400 以上全部正常」只对短测试 prompt 成立。真实 3096 字符编剧生成包下，`glm-5.3-flash` 即使 `max_tokens=4500` 仍把预算全花在 `reasoning_content`（11620 字符）而正文为空；加 `enable_thinking:false` 后 1109 token 即出 1463 字正文。**长任务不能靠「给足预算」解决，必须关思考**（MR-08 硬约束 5 已据此改为默认开启）。另实测聚合网关偶发 `404 Invalid URL (GET /v1/chat/completions)` 与 kimi 台词档读超时，均属瞬时故障，重试即可恢复，不是端点下线。

附则：

1. `id` 必须严格等于 API 请求体的 `model` 字符串，改显示名只动 `name`（依据 `opencode-custom-model` 技能）。端点清单以 `/v1/models` 返回为准，禁止凭印象写 id。
2. **零成本预设不走这些端点**：MR-03 的「零成本」组合仍用内置模型或会话默认；选中上述任一端点即产生 DMXAPI 计费。
3. 端点不可用（欠费 / 限流 / 下线）时按 MR-05 降级为会话模型，**禁止因降级放松闸门A标准**。
4. 换 key / 换聚合商只改配置文件的 `url` + `apiKey` 并重新实机验证，不动 MR-03 分工表；原配置备份 `~/.config/opencode/models.json.bak-20261104`。
5. **端点补齐 ≠ 自动分档**：OpenCode 一个主会话只使用一个模型，技能不会在单次会话里自动换引擎。六档位混跑有三条落地路径：① 按 `rules/opencode-adapter.md` OC-01/OC-03 用实时模型清单 + `subagent` 显式指定模型派发（OpenCode 原生，推荐）；② 由 `scripts/engine_dispatch.py` 按本表的 id 逐档直调端点 API（MR-08，需 `--live` 且产生外部计费）；③ 手动分批切换会话模型（配合 `manifest.json` 断点续跑）。**只配好端点就宣称「六档位已自动生效」属于虚假交付。**

## MR-08 六档位自动调度（2026-11-04，可选执行层）

> 前置：MR-07 端点已配齐且配置已加载。执行器 `scripts/engine_dispatch.py`（纯标准库）是**附加在任一 Mode 之上的可选执行层**，把 MR-07 附则 5 的第二条路径落地；不改变 MR-03 的分工与验收线，不替代会话内编排。

```
init-config <项目目录>
plan   --project <项目目录> --episodes 1-10 [--versions 2] [--dialogue-pass]
run    --project <项目目录>            # 默认演练，零 API 调用
run    --project <项目目录> --live     # 真实逐档调用，产生 DMXAPI 计费
status / verify --project <项目目录>  ｜  selftest（离线，零调用）
```

| 环节 | 落到哪条规则 |
|---|---|
| 排任务 | MR-03 分工 + CC-02 便宜档打底 + CC-03 每批 ≤10 集、满 10 集排卷级回顾 |
| 定调档 | MR-03 附则 2：每卷首集仅 1 次 |
| 版本差异 | MR-04；Mode 3 按 SO-03 降级到呈现层四轴，产物头声明差异轴 |
| 产物头 | MR-06：版本 / 引擎 / 模块 / 差异轴 / 日期 |
| 验收 | 铁律 8：只认 `check_gate_a.py`、`check_adapt.py`（挂 DP 时）与（Mode 3）`source_outline.py check` 的脚本输出 |

硬约束：

1. **默认演练、显式计费**：不带 `--live` 零调用；演练产物带 `DRY_MARK` 占位，`verify` 一律拒绝验收。禁止把演练稿当作初稿交付或计入 S5 结果可见三件套。
2. **端点缺档直接停机**：`plan` 按 MR-07 校验六个 id，缺失即报错（除非 `--allow-missing` 生成待补计划）；禁止静默把某档换成别的模型还宣称「六档位已跑」。
3. **断点续跑**：`manifest.dispatch.tasks` 逐任务记录，done 跳过；失败不写产物、不标 done，下游依赖自动 blocked，`--retry-failed` 重跑 failed + blocked。
4. **只验不改**：`verify` 调双脚本后只出报告；退出码 1 = 判杀（验收正常执行），≥2 = 执行异常（数据不完整 / 脚本报错），两者不得混为一谈。
5. **成本诚实**：未配 `price_per_1k` 只报 token 用量，不编造金额（CC-04）；规则文件不整读，只注入精简硬约束 + 本集生成包（CC-01）。**`disable_thinking` 默认开启**（2026-11-04 LIVE 实跑修正：GLM 在 3096 字符编剧 prompt 下把 4500 token 全花在 `reasoning_content` 导致正文为空，关思考后 1109 token 即出 1463 字正文；原「默认关闭以保质量」口径作废）。需要保留思考链做质量对照时显式设 `false`，但必须给足 `max_tokens`（≥2500）并接受空正文重试成本；引擎遇空正文会自动强制关思考 + 抬高预算重试，不原样白烧三次。`404 Invalid URL` 与读超时属聚合网关瞬时故障，纳入重试；重试仍失败即停机不写产物。成本报告只汇总成功任务的 `usage`，实际账单可能略高。
6. **凭据零外泄**：apiKey 只在内存，任何产物 / 日志 / 报告都不得出现；selftest 含零外泄断言。
7. **降级按 MR-05**：端点失效时停机，由用户在 GUI 切内置模型重跑并注明「降级：会话默认模型」；脚本不假装成功，禁止因此放松闸门A。
8. **不越权**：调度器不挑稿拍板、不合并版本、不改稿、不出终稿；S5 仍须按铁律 8 由人确认。
