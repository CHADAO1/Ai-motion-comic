# 规则模块 — OpenCode 适配层（OC）

> 本文件是**宿主适配层**：在 OpenCode 宿主下，本文件优先于 `rules/model-routing.md` 的静态引擎表（MR-03）。
> 宿主无关的核心（CR/HK/DR 与 MR 的原则）不动；只替换三件事：**引擎怎么选、上下文怎么省、交付怎么呈现**。
> 前缀 OC-*。触发：S0（建路由表）、S3（派发生成）、S5（交付呈现）必读。

## OC-01 实时模型探测（硬性）

S0 与每次 S3 开始前，必须读取**宿主实时模型清单**（OpenCode：`tools.opencode.models`），以返回结果建立本剧路由表。

- 禁止沿用 MR-03 表里的历史模型名，禁止把"推荐/实测榜"当成可用性依据。
- 记录每个候选的 `provider/model`、状态、输入/输出单价；状态非 `active` 的直接排除。
- 可用且不同质的模型 <2 个 → 直接按 MR-05 降级，并在交付说明首行标注"降级：会话默认模型"。

产物：`pipeline\05_引擎路由表.md`

```
| 职责 | 采用模型（provider/model） | 能力依据 | 成本档 | 探测时间 |
|---|---|---|---|---|
```

## OC-02 职责到模型的路由（硬性）

只按能力映射，不按品牌：

| 职责 | 能力要求 | 选择顺序 |
|---|---|---|
| 骨架/大纲/反转节点 | 逻辑推演、结构感 | 用户点名 > 同能力档最低成本 > 会话默认 |
| 台词填肉 | 中文口语感、潜台词 | 同上 |
| 通用初稿/多版并行 | 中文叙事均衡、性价比 | 同上 |
| 挑稿/合并/排序 | 长文理解、审美判断 | 同上 |

- 一次任务内路由不得反复变更；确需变更 → 重写 `05_引擎路由表.md` 并在交付说明注明变更原因。
- 能力判断没有实测依据时，写"未实测，按会话默认"，**不编造评测结论**。

## OC-03 真派发：子会话生成（硬性）

S3 的每集每版，用**独立子会话**生成（OpenCode：`subagent`，`model` 显式指定），禁止在主会话里串行写完所有版本。

- 子会话提示词必须自带：DR-01 四件套（出场角色小传切片 + 金手指卡 + 前情提要 + 术语表切片）+ 本集钩子预算行 + 版型结构要求 + 上轮死因负面约束 + 输出文件路径。
- 主会话只接收：**产物路径 + ≤200 字摘要 + 闸门A结论**；正文留在文件里，需要摘录时用 `read` 的 `offset/limit` 或 `grep` 定向取。
- 子会话不可用、模型不可达、或用户明确要求单模型 → 主会话直接生成该版并标记"降级"，不阻塞流程。

## OC-04 上下文预算（硬性）

- **分阶段只读当前阶段必读文件**；已读文件不重复整篇读，改动处用 `grep` 定位。
- `reference/screenwriting-theory.md` 是事实源备份：仅在规则语义冲突时按小节 `grep` 检索，**禁止整篇载入**（31 KB / 21 节）。
- 每集生成完立即落盘；主会话不保留历史集正文。跨集状态写入 `pipeline\04_上下文摘要.md`（≤800 字：人物现状 / 未回收钩子 / 已用设定 / 下一集约束），下一集只注入摘要 + 相关小传切片。
- 主会话同时持有的正文上限 = **当前集 + 上一集**；超出先落盘再继续。
- S4 验收**按集分批**：读一集 → 写判定 → 释放，再读下一集；禁止把全部版本一次读入再统一判定（冒烟测试实测：7 版一次性读入是主会话最大上下文峰值）。
- 长任务按 **5 集一批**推进，批末输出阶段小结并落盘 manifest，防上下文耗尽丢失进度。
- 交付后如需重跑，按 manifest 与文件读档，不靠对话记忆复盘。

## OC-05 结果可见（铁律 7 的宿主实现）

铁律 7 的"文件呈现工具"在 OpenCode 映射为 **`browser.preview`**（Review 面板展示文件）。

- S5 依次 preview：本集全部版本文本 → `00_初稿包索引.md` → `01_体检报告.md`。
- 回复内仍必须贴每集推荐版正文摘录 + 挑稿决策点清单；`review/audit.md` 的 A10 判定不变（路径-only = ❌）。
- preview 失败时退化为回复内嵌正文片段，并在交付说明注明"呈现工具不可用"。
- **规模化（版本数 >10）**："打开全部版本"改为 preview **索引 + 体检报告 + 每集推荐版**；索引里必须给出全部文件路径清单。禁止用 40 个 tab 代替可读交付。

## OC-06 路由可追溯（硬性）

每个版本文件头除 MR-06 字段外，追加：

```
宿主：OpenCode · 实际模型：{provider/model} · 路由依据：OC-02
```

交付说明必须能回答三件事：**这版是谁写的、为什么选它、花了多少**——缺一即视为路由不可追溯（闸门A附加判杀项）。

## OC-07 成本闸门（硬性）

- 批量初稿默认走**零成本/最低成本档**；付费强模型只用于挑稿/合并/终审。
- 单次任务累计预估成本超过用户给定上限（未给则默认 ¥20）时，先说明预估再询问，不先跑后报。
- 禁止为了"多引擎"让同一版本重复调用多个模型；多引擎只体现在**不同版本之间**（MR-04）。
- 交付说明附一行成本口径：`模型调用：N 次 · 计费档：… · 预估：…`。

## OC-08 运行中故障转移（硬性）

模型在批量中途不可用（限流 / 鉴权失败 / 超时 / 上下文超限）时：

1. 立即标记该模型不可用，切同能力档下一顺位（OC-02 选择顺序）。
2. 无同档可用 → 切**会话默认模型**，不阻塞批次。
3. 重写 `05_引擎路由表.md` 的"实际使用"列，记 `{原模型}→{新模型}（原因）`。
4. 交付说明首行标注"引擎降级"；版本头写**实际**模型，不写计划模型。
5. 禁止静默换模型，禁止把降级版当作原计划引擎的产物。

> 实测：20 集压测中途免费额度耗尽、付费 key 失效，靠本条从"计划双引擎"降级为单引擎跑完剩余 28 版；若无线内故障转移，批次会整体中断。
