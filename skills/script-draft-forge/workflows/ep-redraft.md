# 工作流 — Mode 2：单集重跑

> 触发：用户点名某集（"第 5 集重出几版""这集不行再来"）。前提：已有 Mode 1 的 pipeline/ 产物（预算表、锚点、台账）；没有则先回 Mode 1 跑 S0-S2。

## 步骤

1. **读档**：manifest.json + 01_钩子预算表 + 02_人物小传 + 03_术语表 + 该集现有版本与死因（体检报告）。
2. **确认重跑参数**（用户说了的跳过，没说的带着默认问一句）：
   - 重跑哪些版型：原版型重试 / 换新版型 / 两者都要
   - 死因是否要规避：上轮被杀版本的死因清单（如"情理门挂：能力越界"）作为本轮生成的显式负面约束
   - 预算是否调整：钩子预算通常不动；用户要求变（如"这集要更强的卡点"）则先改 S1 该集行再生成
3. **注入生成**：同 S3 规范——DR-01 四件套 + 本集预算行 + 版型结构 + 死因负面约束。
4. **复验**：只对新版本跑闸门A（preflight 清单），旧版本结论不重算（除非用户要求全集复验）。
5. **更新产物**：初稿包索引（该集版本清单替换/追加 + 新判定）、体检报告追加本轮记录；manifest 更新 updated。
6. 交付：按铁律7"结果可见"三件套执行——呈现全部新版本文本、贴每版卡点/关键段摘录、给决策点清单。不越界精修。

## 铁律

- 只补被杀/被点名的版本，不趁机重出全部（用户明说"整部重来"除外——那等于回 Mode 1）。
- 死因不改尺子：如果连续两轮同一集全员死于同一规则（如情理门），先提示用户该集素材本身有问题，而不是无限重跑。
