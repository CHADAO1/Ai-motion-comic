# 工作流 — Mode 1：完整初稿包（六步）

> 总控 SKILL.md §3 的展开。每步开始先更新 manifest.json 对应 stage 为 doing，结束为 done。

## S0 需求登记 + 素材体检

1. **需求登记表**（先于素材分析，逐项确认，未声明项问用户或走默认）：
   `| 维度 | 用户声明 | 默认 |`，维度：集数 / 单集时长 / 题材 / 风格基调 / 钩子自定义（数量/类型/强度，→HK-01）/ 挂载模块（平台包？题材包？不挂？）/ 其他特殊要求。
2. **素材五维拆解**（CR-01，改编剧走 CR-18 分支）：人物 / 题材创意 / 金手指（CR-04 宽定义）/ 背景 / 立意（CR-05），各 ≥1 条结论 + 素材原文出处。
3. **对标归因**（CR-11）：若素材含对标作品，注明它靠什么起作用，不只看结果。
4. **模块挂载确认**：按需求表挂载 modules/（目标平台→platform 包；题材套路→genre 包；不挂也要显式写"不挂载"）。`source-hygiene`（SH）与 `episode-plan`（EP）为全部 Mode 默认挂载。
5. **原文净稿（SH-03~07）**：Mode 3 走 `ingest`（默认启用 `reference\source_clean.rules.json`，项目专属广告行用 `--exclude-patterns` 追加）；Mode 1/2 若素材为网文转载文本，也须先跑一次 cleaning 并落 `00_净稿报告.md`。删除逐条有原句与规则 ID，乱码行/番外板块头默认只标记待人工确认。
6. 产物：`pipeline\00_需求与体检.md`、`00_净稿报告.md`。通过：需求表填全 + 五维各 ≥1 条 + 模块确认 + 净稿待确认清单有人处置。

## S1 钩子预算

1. 按 HK-01 定预算来源（自定义优先 → 折算默认/模块折算），预算表首行注明来源。
2. 从素材提取钩子素材，排入四级钩位（开头锁人/节拍/卡点/长线，HK-04），建钩子台账（HK-07：埋设集/类型/信息差/强度/预计兑现集/状态）。
3. 长线钩按"纹身式"选（可反复出现、意义延迟揭晓的实物/约定/身世）。
4. 素材钩子不足 → 填空模板 `___` + 缺口清单，禁止编造。
5. **逐集三要素表（EP-01~05/08，硬性）**：每集写「本集核心事件／明确冲突／本集信息增量／尾钩／出处」。信息增量是**观众或剧中人本集新知道的事实**，不是钩子复述、不是「爽点升级」；相邻集不得逐字相同；出处回指原文 CH/行号或细纲条目。模板 `python scripts/check_episode_plan.py init-template pipeline/01_分集规划表.md --episodes <集数或区间>`，可并入预算表作一节。**只跑中间批次时用 `--episodes 10-12`（批次口径），不要用纯数字 12（全剧口径，会误报缺 1..9 集）**；三要素表单独成文件时，生成包的钩子预算行会标注尾钩同源派生。
6. 产物：`pipeline\01_钩子预算表.md`、`01_分集规划表.md`。通过：每集四级钩位齐 + 台账完整 + **三要素齐备率 100%**。齐备率不足不得进 S3。

## S2 锚点建档

1. 人物小传（DR-02：主要角色每张固定特征 ≥5 项）。
2. 金手指卡（DR-03：是什么/边界/何时升级）。
3. 术语表（DR-04）+ 前情提要卡（首集为空，后续集生成时滚动更新）。
4. 产物：`pipeline\02_人物小传.md`、`03_术语表.md`。通过：小传齐 + 金手指已登记。

## S3 多版初稿

1. 版型组合：挂载模块给组合策略（如 platform 包 ST-07）；未挂载时用通用差异化（同素材不同结构参数：强冲突版/悬念倒叙版/情绪流版）。
2. 引擎分配按 MR-04（结构差异+引擎差异至少占一）。
3. **每次生成注入 DR-01 四件套**（出场角色小传+金手指卡+前情提要+术语表），声明"既定事实不得改动"。
4. 生成指令含：本集钩子预算（S1 行）+ 版型结构要求 + CR 呈现层约束（画面思维/台词双重约束/卡点选择）。
5. 单版失败只重跑该版，不阻塞他版。产物：`outputs\ep{NNN}_{版型}_v{n}.md`（头部按 MR-06 标注）。

## S4 闸门A验收

按 review/preflight.md 全清单逐版判定（过/杀 + 证据）：
- 钩子回提四维（HK-09：覆盖/轮换/强度/台账）
- **情理门**（CR-10：行为能力匹配、反应情境匹配，逐场）
- 台词双重约束抽检（CR-13）、情绪名称词 lint（CR-17）
- 挂载模块附加验收（如 platform 包节拍表）
- 分级标注（CR-05：本版讲故事/讲人物/讲情怀哪一档）
- **分集规划合并门（EP-06）**：跑 `check_episode_plan.py check`；三要素缺一即该集 FAIL，齐备率 <100% 不得写「HK-09 通过」
- **S0 净稿留痕复核（SH-07）**：净稿报告在交付包内，删除/标记待确认清单有人处置
- **稿件形态门（GA-12，默认启用）**：`check_gate_a.py` / `check_adapt.py` 先判「有没有戏」；演练占位标记／人物对白句 0／场次标记 0 任一命中 → 写「**不予验收**」（不是内容违规），补正文后复跑。只量形态、不设字数下限；`--skip-shape` 只关判杀不关报数，不得当验收结论

全杀 → 回 S1 复核预算是否过苛（先修尺子再重跑，不直接重跑）。产物：`outputs\00_初稿包索引.md`、`01_体检报告.md`、`01_分集规划检查.md`。

## S5 交付

1. **结果可见（铁律7，硬性三件套）**：
   - 用文件呈现工具打开**全部版本文本** + 《初稿包索引》+《体检报告》——用户不点开就要能看到正文，禁止只报文件路径
   - 回复中贴**每集推荐版本的正文摘录**（至少卡点/最强段落，A/B 双版都给）
   - 给出**挑稿决策点清单**（需用户拍板的事项，如新增设定是否入设定库）
2. 输出交付说明：每集版本清单（含分级推荐排序）+ 体检报告摘要 + 杀稿清单及死因。
3. 使用指引（写给用户）：怎么挑（先看分级与体检）、怎么补跑（点名集+版型触发 Mode 2）、精修建议（人工或点名会话模型）。
4. review/audit.md 清单全 ✅ 才算交付；**初稿包即终点**，不指路下游、不越界精修。
