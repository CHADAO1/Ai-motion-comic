# 安装与使用说明 — script-draft-forge v1.1.3

> 编剧初稿锻造技能 · 分享版 · 出品：银时（南昌）· 2026-11-04
> 收到这个包的人：按下面三步装完即可用，全程 5 分钟，零依赖。

## 一、这是什么

给素材（小说 / 对标剧 / 题材想法），产出**可挑选的专业剧本初稿包**：每集多版、结构差异化、钩子可验收、烂稿机器杀。内置 21 节编剧方法论（CR 三层）、五层钩子系统（HK）、一致性注入（DR）、多引擎路由（MR），支持 platform/genre/style/process 四类自定义模块。

- 纯编剧服务：只出初稿不精修，挑稿合并由你完成
- 零依赖：纯标准库，不需要 pip install 任何东西
- 模型无关：规则层不绑模型，换引擎不改规则
- 可选执行层：六档位自动调度引擎（MR-08），按端点逐档直调 API

## 二、安装（三步）

### 第 1 步：解压

把 `script-draft-forge.zip` 解压，得到 `script-draft-forge/` 目录（内含 SKILL.md 等 20+ 文件）。

### 第 2 步：放入技能目录（按你的宿主选一个）

| 宿主 | 安装位置 |
|---|---|
| OpenCode（全局用户级） | `C:\Users\<你的用户名>\.config\opencode\skills\script-draft-forge\` |
| OpenCode（项目级） | `<项目根>\.opencode\skills\script-draft-forge\` |
| 项目级（仅当前项目） | `<项目根>\.opencode\skills\script-draft-forge\` |

⚠️ 注意：目录层级必须是一层——`技能根\script-draft-forge\SKILL.md`。SKILL.md 直接在 script-draft-forge 目录下，不能再套一层文件夹。

### 第 3 步：重启 + 冒烟测试

1. 保存后自动重载（必要时 /reload 刷新技能列表）
2. 打开技能/能力列表，确认出现 **script-draft-forge**
3. 对话里说一句：**"帮我出个初稿包"** —— 能进入流水线即为安装成功
4. 可选：`python scripts/engine_dispatch.py selftest` —— 37 项离线断言全过即调度引擎可用（零 API 调用）

装完先读包内两份文档：
- `README.md` —— 日常使用指南（七种场景照抄即用，含 Mode 3 按纲改编、场景 7 六档位自动调度）
- `图解使用指南.html` —— 浏览器打开，全流程图解版

## 三、快速上手

**万能公式：先说需求，再丢素材**

```
帮我出个初稿包，20集，每集90秒，投红果，男频都市逆袭
+（粘贴素材）
```

常用指令：
- 「第 N 集重出几版」—— 单集重跑（上轮死因自动变禁令）
- 「钩子要身份揭露型，每集双卡点」—— 钩子自定义，零强制数字
- 「按武侠宗门套路来」—— 即兴需求自动沉淀为模块，永久复用
- 「看看市场」—— 挂题材探测模块联网查
- **「小说原文在这（文件），编剧大纲/细纲在这，按这个纲出初稿」—— Mode 3 按纲改编**
- **「这批按六档位自动混跑」—— MR-08 自动调度（需先配齐端点）**

### Mode 3 三步（给整本小说 + 编剧已定细纲时用）

1. 生成模板（首次）：`python scripts/source_outline.py init-template <目录>`，照 `细纲模板.md` / `细纲模板.csv` 填。
2. 对话里说「按这个纲出初稿」并给出原文、大纲、细纲文件（`.txt/.md/.docx`，细纲也吃 `.csv/.xlsx`）。技能自动入库切片、逐条编号、打每集生成包。
   - 手动执行同样可跑：`python scripts/source_outline.py ingest --source 小说.txt --outline 细纲.md --outline 大纲.md --pipeline <剧本目录>/pipeline`
   - S1/S2 建档后：`python scripts/source_outline.py refresh --pipeline <剧本目录>/pipeline`
   - 出稿后验收：`python scripts/source_outline.py check --draft <剧本目录>/outputs --pipeline <剧本目录>/pipeline --out <剧本目录>/outputs/01_体检报告_纲源.md`
3. 交付时除了初稿包，会多给 `12_纲解析报告.md` 与 `01_体检报告_纲源.md`。**必留细纲条目没落地直接判杀**；推定分配的章节、无原文依据的细纲条目、原文与纲冲突、疑似新增事件会列进挑稿决策点清单等你拍板。

细则见 `workflows/source-outline-draft.md`，规则在 `modules/process/source-outline.md`（SO-01~08）。

### MR-08 四步（要脱离会话模型、按档位自动批量跑时用）

前置：`~\.config\opencode\models.json` 六个端点已配齐（MR-07）且配置已加载；端点缺档时 `plan` 会直接报错，不静默降级。

```
python scripts/engine_dispatch.py init-config <剧本目录>
python scripts/engine_dispatch.py plan --project <剧本目录> --episodes 1-10 --versions 2
python scripts/engine_dispatch.py run --project <剧本目录>          # 演练，零调用零费用
python scripts/engine_dispatch.py run --project <剧本目录> --live    # 真跑，产生计费
python scripts/engine_dispatch.py status --project <剧本目录>
python scripts/engine_dispatch.py verify --project <剧本目录>
```

**默认演练稿带占位标记、`verify` 会拒绝验收**；只有 `--live` 的产物能进闸门A。中断后重跑跳过 done 任务；失败任务不写产物、下游自动 blocked（`--retry-failed` 重跑）。成本报告只报 token 用量，未填单价不编造金额。调度器不挑稿、不合并、不改稿、不出终稿。规则见 `rules/model-routing.md` MR-08。

拿到初稿包后：先看 `outputs\00_初稿包索引.md`（三档分级推荐），只在过关版本里挑，被杀版本别救。

## 四、使用什么大模型

### 4.1 先说结论

- **不配外部模型也能完整跑通**（降级用当前会话模型，MR-05），下面是"要配的话怎么配"。
- **不要一个模型打天下**——本技能各环节能力要求差异极大，按职责分工配。
- 六档位分工与实测依据以 `rules/model-routing.md` MR-03（2026-11-04 复核）为准，本表不重复罗列可能过时的榜单数字。

### 4.2 六档位分工（摘要）

| 档位 | 职责 | 何时用 |
|---|---|---|
| 骨架档 | 大纲、反转节点、卡点设计 | S1 |
| 定调档 | 每卷首集定语气基准 | 每卷仅 1 集 |
| 台词档 | 台词重写、口语化、人物声口 | S3 台词精修 |
| 批量档 | 其余集正文 | S3 批量出稿（省钱位） |
| 挑稿档 | A/B 择优、终审排序 | S4 / S5 |
| 回顾档 | 每 10 集卷级回顾、长线钩对账 | 每 10 集一次 |

分工纪律（MR-03 附则）：按「集」切不按「场」切；定调只做一次；一致性靠外置记忆不靠换模型；最强引擎不写全程；验收线不随引擎浮动。

### 4.3 明确不推荐（有实测反证）

- **DeepSeek 做情理/逻辑审核主力**：人物关系因果是其慢板，正好撞本技能闸门A的情理门
- **Gemini 做写作/改写主力**：长视频脚本写作基准仅中游；强项在长流程工程，不是写作
- **任何模型跑 max 思考档**：成本 4 倍换 <1% 分数，全流程多轮调用下是纯浪费
- **一个档位写满 40 集**：定调/回顾是低频高价值位，全程用最贵引擎会撞上下文天花板

### 4.4 接入方式

1. **零配置**：什么都不做，全流程用会话默认模型（MR-05 降级），质量可用、成本为零
2. **按职责配**：用 OpenAI 兼容聚合站（一个 key 通吃多家模型，先小额试充验证），把端点写进宿主模型配置：
   - OpenCode：`~\.config\opencode\models.json`（OpenAI 兼容端点清单，供 engine_dispatch.py 直调）
   - ⚠️ Anthropic 官方 API 不是 OpenAI 兼容协议，models.json 直连走不通——须经 OpenAI 兼容网关
   - ⚠️ `id` 必须严格等于 API 请求体的 `model` 字段：先拉 `/v1/models` 拿准确 ID，**不要猜**
3. **接入后验证**：逐条 curl 测 200 + 中文正文 + function calling；推理模型短 `max_tokens` 会返回空正文（思考预算被吃掉），不是端点故障，见 MR-07
4. **自动调度**：端点配齐后可用 MR-08 的 `engine_dispatch.py` 逐档直调；**OpenCode 一个会话只使用一个模型**，不配端点也能手动分批切换，但那不是自动混跑

### 4.5 成本口径

`dispatch-cost.md` 只统计 token 用量；金额需在 `pipeline\dispatch-config.json` 的 `price_per_1k` 填单价后才计算，**未填不编造金额**。默认演练零调用零费用，`--live` 才产生外部计费。成本控制细则见 `rules/cost-control.md`（CC-01~04）。

### 4.6 可信度声明

MR-03 的依据采集自 2026-11-04 的公开实测与两轮本地测试（详见 `reference/benchmark-snapshot-2026-11.md`），**非单一厂商自报**。模型迭代极快，本表每季度复核一次，以复核实测为准；厂商软文中的「效率 30 倍 / 首稿可用率」一类数字不作为依据。

## 五、注意事项（三条铁律先知道）

1. **杀稿不修稿**：验收不过的版本直接淘汰（死因写在体检报告里），别试图精修救活——重跑比救快十倍
2. **需求不明它会问你**：不猜。S0 需求登记表会逐项确认，未声明维度走默认
3. **改编喂素材的量**：至少喂到"金手指揭示"之后，否则五维拆解不完整会导致情理门误杀
4. **演练稿不算交付**：DRY-RUN 占位文件 `verify` 一律拒绝，必须 `--live` 才出真稿
