# script-market-audit — 短剧剧本市场解读与开头痛点优化

判断一份短剧剧本在**当下**（红果/抖音）的市场竞争力，并把最不可返工的开头三句改到能打。

一句话定位：**把"这个本子还有没有机会"从感觉变成可复核的数字和改写方案。**

---

## 1. 触发方式

| 模式 | 中文触发短语 | 英文触发短语 |
|---|---|---|
| MODE 1 完整解读 | 「分析一下这个剧本」「还有没有竞争力」「能不能投红果」「是不是太套路」「市场还有机会吗」「一集拖几场」「爆点埋在第几集」「灌水」 | `analyze this screenplay`、`is it still competitive`、`red fruit market`、`douyin short drama market`、`too formulaic`、`pacing review` |
| MODE 2 仅钩子 | 「开头三句话怎么优化」「优化开头」「钩子怎么改」「前3秒不行」「开篇钩子」 | `optimize the opening`、`rewrite the hook`、`first 3 seconds` |

也适用于：投哪个平台、卡点怎么设、片名过审风险、版本增量鉴定（补字数版本）。

**不负责**：内容红线扫描、因果逻辑审核。这两项请用专门的审核技能。

---

## 2. 使用方法

把剧本文档（docx / doc / txt / md）给 AI，说一句上述触发语即可。
不需要手动跑脚本——技能会自己调用。

### 手动运行（可选）

```bash
# 1. 抽正文（只读原文件，不改动）
python scripts/extract_docx.py 剧本.docx pipeline/script.txt

# 2. 结构体检
python scripts/analyze_script.py pipeline/script.txt -o pipeline/

# 3. 若存在另一个集数版本（鉴定是否为补字数灌水）
python scripts/analyze_script.py pipeline/新版.txt --vs pipeline/旧版.txt -o pipeline/
```

脚本仅依赖 Python 标准库，无需安装任何包。

## 4. 在其他工具中使用

本技能的规则与工作流是纯文本，**不依赖特定宿主**。按对方能力分三档降级：

### 档一 · 全能型（能读文件、能写文件）

直接把 `SKILL.md` + `workflows/` + `rules/` 交给它，让它按总控调度执行。
产物目录约定不变（`pipeline/` + `outputs/`）。

### 档二 · 只能读文件

- 让它读 `SKILL.md`（总控）→ 按阶段表读对应 `rules/*.md`
- 脚本无法执行时，让它**照着 `rules/structure.md` 的口径人工统计**，
  并在报告中注明「数字为人工统计，未经脚本校验」

### 档三 · 只能贴文本

- 贴 `SKILL.md` + 当前阶段对应的那一个 `rules/` 文件（如做钩子只需 `rules/hook.md`）
- 让它先输出诊断，你确认后再输出优化版

**三档共享同一套产物目录约定**，产物可互相移交。

## 6. 最易踩的坑 TOP 8

1. **钩子取错了位置** —— 拿了简介或人物小传当钩子。真实钩子在第一集的
   VO / 音画同步行里。
2. **凭印象下结论** —— 说"集数偏多""铺垫太长"却拿不出数字。必须引用
   `01_结构体检.json` 的字段。
3. **基尼系数误用** —— 字数基尼高**不等于**注水，也可能说明信息量集中在
   高潮集。必须与同场景连拍、版本对比联读。
4. **同场景用编号判** —— 每集场景编号都从 1-1 重算，编号相同不代表同一地点。
   要看场景名。
5. **漏掉版本对比** —— 目录里常有另一个集数版本。不跑 `--vs` 就无法发现
   "补字数版本"和"新版其实没改开头"。
6. **改写凭空编造** —— 钩子里塞入本剧第 20 集才出现的道具，第 1 集拍不到，
   等于挖坑。
7. **市场数据无日期** —— 平台机制半年一变。写"市场数据显示"却不给日期，
   等于没给依据。
8. **只拆不建** —— 只列问题不给可保留资产，用户拿不到下一步动作。
