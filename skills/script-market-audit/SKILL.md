# 短剧剧本市场解读与开头痛点优化 — 总控

判断一份短剧剧本在**当下**（红果/抖音）的市场竞争力，并把最不可返工的开头三句改到能打。
**本文件只做调度**：执行到某阶段才读对应模块，禁止凭记忆复述规则跳过读取。

## 0. 全局铁律

1. **数先于断。** 任何结构类结论必须引用 `01_结构体检.json` 的字段名与数值。
   「集数偏多」「前面铺垫太长」这类印象式判断一律无效。
2. **结论前置。** 报告第一句必须是判断，不是剧本摘要（MK-03）。
3. **数据带日期。** 引用市场数据必标采集日期；无日期的「市场数据显示」视为未完成（MK-02）。
4. **对标绑定。** 任何竞争力判断必须指名对标作品及其市场成绩（MK-01）。
5. **改写只用本剧素材。** 素材不足时给填空模板（`___`），**不得凭空编造本剧没有的情节**（HK-05）。
6. **只解读不改写。** 除钩子外不擅自动用户原剧本；要改写需另行确认。
7. **时效自查。** 每次做市场判断前按 PL-06 联网复核平台机制与监管动态，
   与本技能记载冲突时**以复核结果为准**并注明。

## 1. 模式触发

| 模式 | 触发短语 | 入口 |
|---|---|---|
| MODE 1 完整解读 | 「还有没有竞争力」「能不能投」「分析一下这个剧本」「市场还有机会吗」「是不是太套路」 | `workflows/full-review.md` |
| MODE 2 仅钩子 | 「开头三句话怎么优化」「优化开头」「钩子怎么改」「前3秒不行」 | `workflows/hook-only.md` |

MODE 1 的产物含钩子优化；用户只要钩子时走 MODE 2 即可跳到 S4。

## 2. 产物与目录约定

```
{工作目录}\
├── pipeline\
│   ├── script.txt            提取的正文
│   ├── 01_结构体检.json      全部指标（机器读，结论须引用其字段名）
│   ├── 01_结构体检.md        可读体检表（直接贴进报告）
│   ├── 02_逐段验收表.md      逐单元即时验收记录
│   └── manifest.json
└── outputs\
    └── 剧本解读报告.md
```

`manifest.json`：`{ "stages": { "s0": {"status":"pending|done","output":""} }, "updated": "" }`

## 3. 流水线

| Stage | 做什么 | 必读文件 | 输出 | 通过条件 | 失败回退 |
|---|---|---|---|---|---|
| S0 | 建目录、初始化 manifest | — | `pipeline\`、`outputs\`、`manifest.json` | 两者存在且 manifest 已写 | 重做 S0 |
| S1 | 取稿 + 抽正文 | `scripts/extract_docx.py` | `pipeline\script.txt` | 字符数 >2000 且无 `[WARN]` | 换提取方式；禁止带空文本继续 |
| S2 | 结构量化体检 | `scripts/analyze_script.py`、`rules/structure.md` | `01_结构体检.json` + `.md` | 两文件生成，关键数字已向用户复述 | 重跑脚本；集数异常先查错字集号 |
| S2b | 版本增量鉴定（**存在其他集数版本时必做**） | `rules/structure.md` SC-02 | 体检表第八段 | `--vs` 已跑，结论量化到集 | 找到另一版本后回 S1 |
| S3 | 通读 + 集段梳理 | `full-review.md` S3 | 集段表、矛盾点、最优片段 | 集段表覆盖全部集段 | 重读全文，**禁止用搜索代替通读** |
| S4 | 市场与平台解读 | `rules/platform-market.md` | 对标、视角判断、保留资产 | 每条结论有对标 + 采集日期 | 删除无证据结论重做 |
| S5 | 钩子诊断与改写 | `rules/hook.md` | 四段式改写 + HK-10 自检表 | 四段齐全、自检 7 项已附 | 素材不足则改填空模板 |
| S6 | 报告 + 双门审查 | `review/preflight.md`、`review/audit.md` | `outputs\剧本解读报告.md` + 审查表 | Preflight 与 Audit 全 ✅ | 补执行后重跑受影响 stage |

## 4. 断点续跑与回退

开始先读 `manifest.json` → 跳过 `status=done` 的 stage → 从第一个非 done 继续。
**S2/S3 之后剧本若有改动，S2 起全部重跑**（数字会变，旧结论失效）。
任一审查 ❌ → 当场补执行 → 受影响 stage 置回 pending。

## 6. 维护约定

修改前读 `MAINTENANCE.md`；每条变更记 `CHANGELOG.md`；
改完跑 `node scripts/lint_skill.mjs`，必须 exit 0。
新增规则须同步登记到 `review/preflight.md` 对应分组，否则视为死规则。
