# reference — 对外分享前检查清单

本技能包设计为**可对外分享**（同行编剧、编剧工作室、外部合作方）。
分享前逐项过，任一项不过不得发出。

## 一、脱敏（最重要）

本技能在实战中处理过内部稿件，检查以下泄露点：

- [ ] **内网地址**：任何 `\\192.168.x.x`、`\\10.x.x.x` 形式的共享路径
- [ ] **本机绝对路径**：`C:\Users\...`、用户名、机器名
- [ ] **其他项目代号**：内部立项号（如 HDM/CHM 编号）、客户代号
- [ ] **他人稿件原文**：报告中引用的对白、场次描述——若来自他人未公开稿件，
      须改为泛化描述或删除
- [ ] **平台账号信息**：任何登录态、账号、渠道号
- [ ] **云盘/网盘链接**：分享链接通常带提取码，等同密码

**自检方法**：
```bash
grep -rEn "192\.168\.|10\.[0-9]+\.[0-9]+\.[0-9]+|C:\\\\Users|HDM[0-9]|CHM[0-9]" .
```
命中即处理。Windows Git Bash 下用此命令；其他环境用等效全文搜索。

## 二、数据与合规

- [ ] `reference/market-baseline.md` 的采集日期已更新（或明确标注「请自行复核」）
- [ ] 平台日活、热度值、排名等数据已标注来源与日期
- [ ] 未把任何平台的**非公开数据**（后台报表、内部榜单）写入包内
- [ ] 监管条款的表述为公开信息，未做法律解读断言

## 三、文件卫生

- [ ] 无临时文件（`__pycache__/`、`*.pyc`、`.DS_Store`、测试残留）
- [ ] 无本地调试脚本、无个人笔记
- [ ] `scripts/*.py` 在标准库下可运行（无第三方依赖）
- [ ] 跑 `python scripts/analyze_script.py --help` 与
      `python scripts/extract_docx.py` 确认可执行
- [ ] `node scripts/lint_skill.mjs` exit 0

## 四、可读性（给外部读者）

- [ ] `README.md` 说明了**如何在对方的工具里用**（不能假设对方也有本工作流）
- [ ] 规则文件里的反例已去掉内部人名/项目名
- [ ] 脚本注释里的「实战踩坑」描述不暴露具体项目
- [ ] 未暗示「本方法来自某内部团队/某公司」

## 五、打包

对外分享建议打 zip，结构即技能文件夹本身：

```
script-market-audit.zip
└── script-market-audit/
    ├── SKILL.md          ← 对方只需先读这个
    ├── README.md
    ├── workflows/ rules/ review/ scripts/ reference/
    └── MAINTENANCE.md CHANGELOG.md
```

对方的使用门槛是：把文件夹放进其技能目录（OpenCode 全局为 `~/.config/opencode/skills/`），
即可被识别。`SKILL.md` 的 frontmatter 已按通用格式书写。
