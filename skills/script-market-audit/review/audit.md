# 审查模块 C2 — Audit 执行审查（硬性）

## 使用原则

审的是**步骤有没有真执行**（与 Preflight 的「产物对不对」分开）。
两门都过才可交付。**审查报告缺失 = 任务未完成，禁止交付。**

## 时机：两段式

1. **中途门**：S3 通读完成后，审 A1–A4，全 ✅ 才准进 S4/S5。
2. **终审**：交付前，审 A1–A10 全部 + Preflight 全部。

## 清单

| # | 审查项 | 证据要求 |
|---|---|---|
| A1 | 文件真的取到了 | `pipeline\script.txt` 存在，字符数 >2000（贴数字） |
| A2 | 提取没踩空 | `extract_docx.py` 输出无 `[WARN]` |
| A3 | 体检脚本真跑了 | `01_结构体检.json` 存在，且报告中的数字与 json 字段一致（贴 2 组对照） |
| A4 | **全文真通读** | 集段表覆盖全部集段，抽查任意 3 集原文均能在集段表与讨论中找到对应 |
| A5 | 版本对比真做了 | 若有其他版本，`01_结构体检.md` 第八段存在；若无，需说明「已确认无其他版本，检索范围=___」 |
| A6 | 市场数据是联网取的 | 报告含 ≥1 处「采集日期：YYYY-MM-DD」+ 可追溯来源名 |
| A7 | 对标是真的 | 对标作品名/热度/排名可在报告中复述，不是编的 |
| A8 | 钩子取自正文 | 引用钩子句处标注来源（如「第1集 音画同步行」） |
| A9 | 改写没编造 | 优化版每个素材可在本剧找到出处；填空的标 `___`（逐项列出对照） |
| A10 | 原稿未被改动 | 原文件修改时间未变，或明确说明改了什么 |

## 报告（随交付强制输出）

```
## 执行审查
| # | 项 | 结果 | 证据 |
|---|---|---|---|
| A1 | 取稿 | ✅ | script.txt, 41993 字符 |
| A3 | 体检 | ✅ | 集数58 ←json.episodes=58；同场景17-29集 ←json.same_scene_run |
...
任一项 ❌ → 当场补执行并重跑该项；改动了 S2/S3 产物 → S2 起全部重跑。
```

## 补执行与再触发

- A4（通读）不通过 → **必须重读全文**，不得用关键词搜索代替。
- A6/A7（市场数据）不通过 → 删除相关结论重做，不得「大概是」。
- A9（编造）不通过 → 撤回该条改写，改为填空模板或向用户索要素材。
- 全部修复后更新 `manifest.json`，并在下一次回复中附上修复后的审查表。
