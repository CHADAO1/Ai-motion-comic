# 剧本版本差异分析 — 总控

拿到同一部剧的两份剧本稿，产出一份**可指回原文行的差异报告**，并回答用户的业务问题（哪个更痛、要不要合并、哪些集要重做）。

**本文件只做调度**：执行到某阶段才读取对应模块文件。

## 0. 全局铁律

1. **禁止段落级整体 diff。** 只要两版集数不同（哪怕只差 1 集），段落索引就会全局错位——某剧本实测 1186 条"差异"里 **1133 条是假信号**（把错位的两段配成一对）。**必须先用「逐集序列相似度」对齐，锁定真正的改动区**，再只在改动区内做逐行 diff。
2. **改动范围必须量化到集。** 结论不能是"改了不少"，必须是"只改了前 3 集，后面 44 集一字未改，相似度 0.995+，差异仅为集号场号"。
3. **结论必须可指回原文。** 每条"新增/删除/改写"都要附原文引用 + 场次号；不给原文的判断视为未完成。
4. **不擅自改剧本。** 除非用户明确要求，只出差异与建议，不动笔。
5. **相似度 ≠ 无改动。** 0.99 也要逐块列出来验证——常常是集号/场号变化，但也可能藏着真改动。

## 1. 流程

| 阶段 | 动作 | 读什么 |
|---|---|---|
| **S0 定位** | 确认两份文件真实路径；UNC 路径**必须带 IP 前缀**（裸 `\\共享名\...` 不可达） | — |
| **S1 提取** | 两版全文提取为纯文本（保留段落分隔） | `scripts/extract_docx.py` |
| **S2 对齐** | 按「集标记」切分，逐集做序列相似度比对，求最优偏移量，锁定改动区 | `scripts/align_versions.py` |
| **S3 精比** | 只对改动区做逐行 diff；主体区逐块列出并确认差异性质 | `scripts/align_versions.py --detail` |
| **S4 解读** | 量化统计（集数/场次/字数/卡点）+ 逐条改动归类（删/并/改/修bug） | — |
| **S5 评估** | 回答业务问题：痛感/节奏/共鸣/商业效率，给出双版胜负与理由 | `rules/evaluation.md` |
| **S6 交付** | HTML 图文报告 + 纯文本速查版双交付 | `templates/report.md` |

## 2. 关键口径

### 集标记识别
剧本常见形态（都要兼容）：
- `第一集` / `第1集` / `第 01 集`（中文数字与阿拉伯数字混用）
- 场次行：`1-2 日 内 李满仓家` / `2-3夜 内 某处`（`-`/`－`/`—` 都要识别；日/夜与内/外之间可能无空格）

### 最优偏移量
两版常常是「删掉 N 集 + 全文集号前移 N」的结构。**偏移必须带符号地双向扫描**：

| 情形 | 偏移 | 例 |
|---|---|---|
| 新版**删**了 N 集（集数变少） | `d > 0`：新第 N 集 ↔ 旧第 N+d 集 | 47→45，d=+2 |
| 新版**增**了 N 集（集数变多） | **`d < 0`：新第 N 集 ↔ 旧第 N−d... 即新 N ↔ 旧 N+d，d 为负** | **47→49，d=−2（实测）** |

算法：对候选偏移 `d ∈ [-4, 3]` 逐个计算「新第i集」与「旧第(i+d)集」的平均相似度，取最高者。
**对齐成功后，主体区应当出现大批相似度 ≥0.99 的整集**，这就是"内容零改动"的证据。

> ⚠️ **踩过的坑**：早期版本只扫 `d ∈ [0,3]`，遇到「新版集数更多」的项目（HDM028：47→49 集）时，
> 最优解被截断成 d=0，导致 **47 集全部被判为「内容」改动、平均相似度只有 0.10**，
> 完全没法定位真正的改动区。现已改为 `[-4, 3]`，并在输出里标注符号含义。

### 差异性质分类
| 类型 | 判据 | 处理 |
|---|---|---|
| **编号变化** | 仅「第N集」行与「N-1 场次」行不同 | 不计入内容改动，但要在报告中明示"仅编号" |
| **整场删除** | 源有、目标无，且是完整场次 | 记入，标注是否含关键台词 |
| **整场合并** | 源两场位于相邻两集、目标并作一场 | 记入，这类通常**提升观感**（情绪不被打断） |
| **逐句改写** | 同位置句子有增删改 | 逐句列新旧对照 |
| **顺序调整** | 同内容换位置 | 记入，注意是否影响因果 |
| **bug 修复** | 源有错名/错号/矛盾，目标已消除 | **单独成节**——这是修订版的加分项 |

## 3. 已知陷阱（实测踩过）

- **`tencent-local-office-edit` 的 `doc_resolve_document_structure` 取不到全文**：`text_preview_length` 上限 200 且按**字节**计（≈66 汉字），长段被截。要全文必须直接解析 docx（`scripts/extract_docx.py`）。**这是允许的兜底路径，但需告知用户。**
- **`doc_compare_documents` 在集数不同时不可用于定位改动**：段落级对齐会错位。可作为"结构增删"的参考，但**不能作为主证据**。
- **Bash 环境 PATH 可能损坏**（`dirname`/`head`/`basename` 找不到）→ 避免管道与 `head`，改用 Python 脚本落盘后再读。
- **网盘 UNC 需 IP**：`\\共享名\...` 不可达，用 `\\192.168.x.x\共享名\...`。
- **改动的常见形态不是"改写"而是"移动"**：一个字没改，只是把被拆到两集之间的同一场戏合并了。别只盯着文字差异。
- **偏移量是全局统一的，重度重写的集会配错"名义对应集"**：`align_versions.py` 求的是单一偏移 `d`，所以被重写的开头几集会与「旧第 N+d 集」配对（实测新第1集被配到旧第3集）。这不影响结论——**相似度 <0.6 就该判定为"整集重写"，不必去论证它到底对应旧版哪一集**。真要确定，需按内容人工比对。
- **相似度 ~0.995 是"内容零改动"的正常值，不是改动信号**：集号与场号变化会把整集相似度压到 0.995 左右。判断内容是否零改动，看**差异块是否全部由集号/场号行组成**，不要看相似度阈值。

## 4. 输出要求

- **双交付**：`<项目>_两版剧本对比分析.html`（图文、含结构映射图、新旧对照） + `<项目>_两版对比_速查版.md`（纯文本，可直接复制的原文段落清单）
- 报告必备节：结论 / 差异总览（量化表） / 对齐证据（逐集相似度表） / 逐条改动（新旧并列） / 业务评估 / 合并建议（精确到镜头与台词） / 顺手发现的 bug
- **合并建议要给成本**："这条补丁只需 1 个场景、4 个镜头"，让用户能直接决策
