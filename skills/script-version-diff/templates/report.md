# 对比报告骨架（S6 交付）

固定双交付：`<项目>_两版剧本对比分析.html` + `<项目>_两版对比_速查版.md`

---

## HTML 报告章节骨架

| 节号 | 标题 | 必备内容 |
|---|---|---|
| **00** | 先给结论 | 一句话：差异在结构还是内容；改动范围量化到集；直接回答用户的业务问题（哪个更痛） |
| **01** | 差异总览 | 量化表：集数 / 卡点 / 段落 / 字数 / 场次 / 年代设定 / 人物小传是否一致 |
| **02** | 「只改前N集」是怎么证出来的 | 逐集相似度表 + **一张集数映射 SVG**（旧版条带 → 新版条带 + 偏移箭头 + 卡点位置） |
| **03** | 逐条改动（改动区） | **左右并列**：左=旧版原文（红底），右=新版原文（绿底）；改动点用 `<del>`/`<ins>` 或高亮标出；每条注明场次号 |
| **04** | 哪个更痛 | 双方优势分列；引用原文；给出总分与"两版各赢什么"的总结句 |
| **05** | 关键场面逐条打分 | 打分表 + 评分口径说明 |
| **06** | 合并建议 | 补丁 ①②③，每条给**精确拍数/秒数**与**成本**；给"最小改动方案" |
| **07** | 顺手发现的 bug + 待确认项 | bug 对照表（旧版原文 / 判断 / 新版是否已消除）+ 待用户定夺清单 |

## 视觉规范（沿用 `html-report-layout`）

- **浅色主题**（IDE 为 light 时）：白底卡片、深色文字，禁止深色面板
- 旧版内容用 `--red-bg` 面板，新版用 `--green-bg` 面板，形成稳定视觉语义
- 剧本原文用等宽/衬线小字，`△` 动作行走灰色、`（……）` 括号行用强调色——**让用户一眼分清动作/台词/VO**
- 交付前必做：标签配平、锚点无断链、`url(#)` 无悬空引用、章节编号无重复（脚本核查）

## MD 速查版要点

- 结论 → 差异总览表 → 改动范围对齐表 → 逐条改动 → 四维评估 → 合并建议（代码块给出可直接复制的原文段落）→ bug 清单 → **建议动作清单（可勾选 `- [ ]`）**
- 原文段落用 ``` 代码块包裹，便于用户直接复制去改剧本
