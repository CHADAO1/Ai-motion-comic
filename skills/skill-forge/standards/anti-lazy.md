# 标准S3 — 防偷懒设计标准

> 任何带执行流程的技能（T1 强烈建议、T2 必须）按本标准设计验收机制。目标：不依赖 AI 自律，用流程让它难以偷懒。

## L1 偷懒的四个根源 → 对策映射

| 根源 | 对策 |
|---|---|
| 注意力稀释（长流程中段规则被忽略） | 瘦总控 + 按阶段只读所需模块；关键约束放铁律区与阶段表"通过条件"列 |
| 省力倾向（输出缩水） | 要素计数型完成定义（L3）；逐单元即时验收（L2） |
| "完成"定义模糊 | 每阶段有硬性通过条件 + 失败回退路径，无主观判断空间 |
| 漏做无成本 | 证据落盘（文件/表格/manifest），缺失即肉眼可见；审查报告缺失=任务未完成 |

## L2 证据绑定（最高优先级）

- 每个 ✅ 必须落到**可核查证据**：磁盘路径 / 脚本原始输出行 / JSON 字段值 / 具体数值 / 点名清单。
- **空泛结论黑名单**："已检查""无问题""符合要求""均已处理"——出现即视为该项未执行。
- 可计算项优先由脚本出数，AI 引用脚本输出而非自行声称。

## L3 要素计数，禁止字数

- 完整性一律表达为可数的要素：`七要素是否逐项在位` `弧线≥3拍` `三件套齐否` `N 个段落 N 行表格`。
- **禁止任何最低字数/字数区间标准**：提示词/产物长短由内容决定，短而全即合格；字数下限只会逼出注水，且对合法短产出是误伤。
- 设计清单项时自问：这项能不能用一个数或一个名单来核对？不能就改写成能。

## L4 逐单元即时验收

- 多单元任务（多段落/多镜头/多文件）强制循环：**完成一个单元 → 立即校验该单元 → 记入验收表一行 → 再做下一单元**。
- 禁止攒批到最后统一补审——攒批补审是漏检主因。
- 验收表本身落盘（如 `pipeline\05_逐段验收表.md`），作为终审证据载体。

## L5 双门 + 回退

- 内容门（产物对不对）与执行门（步骤真做了没）分开；两道都过才可交付。
- 任一项 ❌ → 当场返工该单元并更新对应记录，再重跑受影响的后续门。
- 技能文本中显式写入："审查报告缺失 = 任务未完成，禁止交付。"

## L6 给技能作者的自检三问

1. 我的每个阶段，AI 能不能只凭"看起来像完成了"混过去？（能→加证据要求）
2. 我有没有用形容词当标准？（"详细""完整"→改成要素清单）
3. 漏掉某步时，用户能否在 30 秒内发现？（不能→把该步状态写进落盘产物）
