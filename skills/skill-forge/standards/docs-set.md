# 标准S4 — 文档套件标准（README / MAINTENANCE / CHANGELOG）

> T1 可选（建议至少 README）、T2 必备。全部放技能包根目录——对加载器零成本，需要时才被读取。

## D1 README.md — 通用入口（给人 + 其他工具）

必备七块：
1. 一句话身份定位
2. 双模式/多功能触发表（含中英文触发短语）
3. 在 OpenCode 中使用（自动发现、流水线概览）
4. **在其他工具中使用**：按宿主能力分档降级（全能型→按总控调度 / 只能读文件→按必读清单贴入 / 只能贴文本→总控+当前阶段单个模块拼接），各档共享同一套产物目录约定
5. 目录结构指引（指向 SKILL.md File Map）
6. 最易踩的坑 TOP 列表（≤8 条）
7. 维护入口指向 MAINTENANCE.md

## D2 MAINTENANCE.md — 维护者/AI 编辑入口

必备六块：
1. 架构分层一页图（数据流：总控→工作流→规则→审查→脚本→中间产物）
2. **最小阅读集对照表**：常见修改任务 → 只需读哪些文件（这是"不用通读全包"的关键）
3. 规则编号注册表（前缀→文件→领域）
4. 标准变更 SOP：新增规则 / 修改规则 / 删除规则 / 新增阶段 / 新增脚本，每条以"跑 lint PASS"收尾
5. 一致性防线：单一事实源、lint 用法、常量全局同步意识、frontmatter 纪律（name 不动、description 改动影响触发需谨慎）、回滚单元=CHANGELOG 条目
6. 禁止事项（含：禁最低字数标准、禁空泛验收结论、禁规则正文进总控）

## D3 CHANGELOG.md — 变更记录

- 条目格式：`[版本] 日期 标题` + 动机 / 变更点（列文件）/ 兼容性说明。
- **每条变更 = 一个回滚单元**：单条回滚按条目内所列文件反向操作。
- 新条目置顶；规则编号废止必须注明取代关系；原始版本（如外部下载原状）记为 [1.0] 并注明存档路径。

## D4 放置纪律

- 三件套放包根目录；模板骨架见 templates/docs-skeletons.md。
- 这些文档永不参与运行——不要为了"省事"把其内容合并进 SKILL.md。
