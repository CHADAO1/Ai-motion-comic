# 模板 — 规则模块 / Preflight / Audit 骨架（T2 复制后填空）

## A. 规则模块（rules/<领域>.md）

```markdown
# 规则模块 R{n} — {领域名}

> 总控在 Stage {S?} 读本文件。规则编号 {PREFIX}-*。

## {PREFIX}-01 {规则短名}（硬性|重要|建议）
{规则正文：只写本条，含正例/反例各≤1个}

## {PREFIX}-02 …
```

要点：文件头注明作用域与前缀；一条规则一节；正反例各最多 1 个；禁止把别条规则的内容抄进来（需要时写"见 xxx.md YYY-nn"）。

## B. Preflight 内容门（review/preflight.md）

```markdown
# 审查模块 C1 — Preflight 内容检查清单

## 使用原则
1. 完整性以要素计数为准（几要素/几拍/几件套），禁止最低字数标准——短而全即合格
2. 每个 ✅ 必须附可核查证据：路径/脚本原始输出/数值/名单；"已检查""无问题"按未检查处理
3. 多单元任务必附《逐单元验收表》（落盘 pipeline/）

## 分组清单
- [ ] {组名}
  - [ ] {检查项}（{PREFIX}-nn）
```

要点：每项括号标规则出处；按主题分组不超过 8 组；可脚本校验的项注明脚本名。

## C. Audit 执行门（review/audit.md）

```markdown
# 审查模块 C2 — Audit 执行审查（硬性）

## 时机：两段式
1. 中途门：{阶段X}之后只审 A1–A{k}，全 ✅ 才进下一阶段
2. 终审：交付前全清单 + Preflight 全项

## 清单（逐项给可核查证据，禁止空勾）
| # | 审查项 | 证据要求 |
|---|---|---|
| A1 | {强制步骤是否真执行} | {文件路径/脚本输出/结论} |

## 报告：随交付强制输出，缺失=任务未完成
任一项 ❌ → 补执行并重跑该项；改动产物 → 重跑全流程；补执行后更新 manifest。
```
