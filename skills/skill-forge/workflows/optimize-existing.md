# 工作流 — Mode B：优化/体检既有技能（B0–B5）+ Mode C 快检

> 核心纪律：**先分析后动手**。外部建议只作参考，采纳与否必须对照本套标准逐条判断并记录理由。

## B0 备份原版
确认原包位置并宣布"原目录永不再改"；后续全部工作在正式安装副本上进行。若原包未安装，先落暂存区体检。

## B1 技能体检（输出逐项报告）

| # | 检查项 | 方法 | 判定 |
|---|---|---|---|
| H1 | 文件清单与规模 | 递归列出+行数 | 记录基线 |
| H2 | frontmatter 合法性 | 对照 opencode-platform.md F2（name 正则/必填/驼峰致命键） | PASS/FAIL+原因 |
| H3 | 布局合规 | 是否一层深 SKILL.md；编码 UTF-8 | PASS/FAIL |
| H4 | 引用完整性 | grep 全部 references/ 链接与 §章节引用，逐一核实存在 | 悬空清单 |
| H5 | 重复度 | 通读正文标记同一规则出现≥2次的位置（重复是膨胀主因） | 重复热力点 |
| H6 | 架构分级 | 按 architecture.md 分诊表判当前处于哪层、是否错配 | 建议层级 |
| H7 | 平台适配 | 硬编码的外部环境约定（特定子代理/平台命令）标注等效替代方案 | 适配清单 |

体检报告以表格交付，先于任何改动。

## B2 差距分析与方案确认
对照 standards/ 四件逐项列：✅已达标 / ⚠️缺口(补什么) / ❌不适用(为什么不)。**明确写出不采纳某做法的理由**（例：字数下限→违反 anti-lazy L3）。方案经用户确认后才动文件。

## B3 执行改造（按确认的方案）
- 单体→分层：旧章节映射到新模块（保留映射表进 CHANGELOG），去重后每条规则给唯一编号；审查清单改为编号引用。
- 补防偷懒机制（anti-lazy.md）、文档三件套（docs-set.md）、lint 落位 scripts/。
- 外部环境硬编码改为本宿主等效写法或注明降级路径。

## B4 验证
同 create-new.md A4 清单全部项 + 若为改造：抽 2–3 条原规则核对语义未丢失（对照备份原文）。

## B5 CHANGELOG 与交付
重构记为一个大版本条目（动机/映射/兼容性/回滚基准路径）；向用户交代使用方式变化（通常不变）与回滚方法。

---

## Mode C 快速合规检查（不改文件）
只执行 B1 的 H2/H3/H4 三行，输出 PASS/FAIL 结论与一句话建议（可直接安装 / 修 X 后可装 / 不兼容）。适合"帮我看看这个能不能用"类请求。
