## v1.1.0 (2026-09-30)

新增 **MODE 3 — 去标点拆条**。来源：《女巫与狼王》用户追加需求「字幕里不能出现标点符号，标点符号的要断成两个字幕」。

- 新增 `scripts/strip_punct_split.py`：以基准轨时间窗为权威，把目标轨按标点切成多条，标点丢弃；父窗口内按字数比例分配时长（水位填充，单条最低 700ms）；首条起点 / 末条终点严格等于基准条（**父窗口边界零漂移**）；内置 `--min-seg-ms`（默认 300ms）防闪卡兜底 + 残留标点白名单反查。
- `SKILL.md`：新增 §3 MODE 3 与三条拆条铁律；`when_to_use` / `description` 补充「去标点 / 无标点字幕」触发词。
- 已用真实项目数据回归验证：脚本产物与手工交付稿 MD5 完全一致（`0208c5214f6c2c757d8b53b43cdd8472`，2116 条，124965 字节，CRLF 无 BOM）。

### 记录在案的新坑（MODE 3）

1. **需求自相矛盾**：用户先要求「时间轴与英文完全一致（条数 1:1）」，再要求「带标点的断成两条」——数学上不可能同时成立。→ 必须先摆出冲突、让用户选口径，禁止默默选一种。实测用户选「拆条但保留英文边界」。
2. **间隔号 `·` 漏网**：`，。！？、；：…` 这类好枚举，`·`（人名分隔）容易忘。→ 改用**白名单反查**（`\w` + 中文 + 显式保留符号），比黑名单可靠。且 `·` 应「只删不拆」，否则「芬里斯·康尼克」会被劈成两张卡。
3. **闪卡**：父窗口短时按比例分配会产出 250ms 的卡片，肉眼看不见。→ 加 `--min-seg-ms` 兜底，退化为单卡（标点照删），并在报告里逐条列出退回项。
4. **不能只看校验通过**：必须抽检「原句 → 拆后各条 + 各条时长」的人眼可读性。本次闪卡问题就是这么发现的。
5. **《》口径要问**：书名号属专用标记而非句读标点，是否保留必须问用户（本次用户选保留）。

## v1.0.0 (2026-09-30)

首版。来源：《女巫与狼王》中文字幕重建到英文字幕时间轴（1760 条 1:1 对齐）实战。

- `SKILL.md`：总控 + 六阶段流程（S0 探基线 → S1 译名表 → S2 出译文 → S3 合轨 → S4 四道校验 → S5 锚点抽查 → S6 交付）
- `scripts/rebuild_srt.py`：`build` / `check` / `anchor` 三命令，纯标准库
- 已用真实项目数据回归验证：脚本 `build` 产物与手工交付稿 MD5 完全一致（`be25c7574edf12f286171ff8067eb1ab`，1760 条，111457 字节，CRLF 无 BOM）

### 记录在案的两个坑

1. **整块错位**：早期用 `parts/p001..p012` 按文件名顺序承载译文，写入过程中错位一整块（丢 150 行 + 重复 150 行），全文偏移 150 行。→ 改为强制 `zh_map.json`（键＝条号），脚本对缺键/越界键直接报错终止。
2. **行尾混合**：`'\r\n'.join(lines)` 只替换了条目之间的换行，条目内部仍是裸 `\n`。→ 改为先 `'\n'.join` 再整体 `replace('\n', nl)`；`check` 增加 `裸LF` 计数，非零即报警。
