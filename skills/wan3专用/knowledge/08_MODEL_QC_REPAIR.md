# 08 Model QC Repair

priority: highest knowledge
scope: 模型适配、Wan3.0 稳定性门、故障修复、最终检查

## 输出修复优先级

如果回答变得冗长、英文化、像知识库摘要，优先按以下方式修复：

1. 删除显性分析、规则解释、测试用例和 Knowledge 索引内容。
2. 把英文标题改成中文标题并恢复固定顺序：`第01段`、`【角色/场景/素材锁定】`、`【基础风格】`、`【运镜与时间轴】`、`【声音设计】`、`【画面限制】`。
3. 只保留必要英文技术短语；其他全部改成中文。
4. 输出可复制提示词，不输出“我将如何做”的说明。

## 模型适配原则

只有 Wan3.0 的以下规则作为硬约束：

- 先执行时长与镜头结构确认门：`wan3.0-video` 是单一模型，`Tmax=30秒`（`duration` 取 2–30 或 `-1`，默认5），并确定单镜模式（无时码，必须显式写「生成单镜头」/「一镜到底」）或多镜模式（`第N个镜头[a-b秒]`，时间戳从0连续、首尾相接、无重叠/倒序/留白、求和=`duration`）。`<=4镜` 只是跨镜一致性风险提示（5镜以上用一致六补丁做稳），不是自动拆段触发器；是否拆成多个独立段由 `split_policy`（默认 `off`）决定。用户提供剧本或要求 Wan3.0 提示词但既未给 `duration` 也未给镜头结构时，必须先询问，未确定前不出成稿，也不同时索要完整剧本、素材或其他信息。
- 每段 `<=Tmax=30秒`。
- 每段 <=5000 字符（中英文各算1字符）。
- 参考素材入口上限：`reference_image <=10张`；`reference_video <=5段（总<=15s，单段[1,15]s）`；`reference_audio <=5段（总<=15s）`；`file×1` 或 `link×1`（需 `enable_thinking=true`）。图片/视频/音频分开计数、各自从1起编号；上限不是目标，仍取本段最小充分素材集。`reference_*` 与 `first_frame`/`last_frame` 互斥，`last_frame` 必须搭配 `first_frame`，`file` 与 `link` 互斥；V2V 输入视频总时长 + 输出 `duration` `<=30秒`，超了报 `duration exceed`。
- 每段先做节拍级最短可读估时，再把相邻兼容节拍拼成 `<=Tmax` 整段。两个候选段合计 `>30秒且<40秒` 时优先压成26-30秒。压缩方式：台词跨 CUT、动作反应并行并删除冗余；压缩后仍超 `Tmax` 或存在强边界才拆，不延长单一动作补时长。
- 每段独立完整。
- 每段重复关键锚点。
- 不要默认一镜一段；同空间、同主要人物/说话者、同一连续动作或同一段台词优先拼成同一段。
- 是否把一次交付拆成多个独立段由 `split_policy`（默认 `off`）决定：`off` 时即使出现切场景/地点、切景别或机位变化大到影响模型理解、切主要人物/说话者、切时间状态或一段动作链结束等强边界，也优先留在同一段内用段内 `CUT`/`hard cut` 承接（前提仍 `<=Tmax=30秒` 且 `<=5000 字符`）；只有 `split_policy=on`（用户明确「允许智能拆段」）才在这些强边界处拆成多个独立段。单段客观压不进硬上限时不静默拆，先向用户说明并请授权。

其他模型规则可能随产品更新变化。用户指定非 Wan3.0 模型时，按用户给出的当前规则优先；如果用户没有给规则，只做保守适配。

下表只描述保守写作倾向，不是产品规格、最长时长、上下文记忆或功能承诺。更换模型、账号、地区或日期后，不从表中推断当前能力；用户需要精确规格时，只核对该模型官方最新资料。Wan3.0 原生使用 `@图片N/@视频N/@音频N`：带 `@` 前缀、用全称“图片”而不是“图”，图片/视频/音频各自从1起编号，同一对象可在不同位置多次 `@` 以提高指代命中率；只为真正作为 media 传入的素材写 @ 行，未提供的素材不编号、不声称已挂载。例外（最高优先级）：客户原提示词自带的显式资产索引（如 `@[uploaded:xxx]`、`@图片x (xxxx)` 或客户平台特有句柄）一律原样保留字面形式，不改写、不重新编号、不剥离括注，`@图片N` 规范写法让位于客户形式。

## Fast Preflight Card / 普通交付快速预检卡

普通初稿、续段、长篇中的单段和窄修改只运行本卡一次；编译时已经完成的空间、朝向、容量、因果和OUT证明在此只核对结果，不重新推演整稿：

1. **包络硬门**：目标镜头结构（单镜/多镜）、`duration` 与 `Tmax=30秒` 已解析；一行合法段标题加依次五栏；每段字符（<=5000）、时长及需显示时码连续性合法，多镜模式时码求和等于 `duration`（`<=4镜` 只是跨镜一致性风险提示，不作硬门、不自动拆段），单镜模式已显式写「生成单镜头」/「一镜到底」。栏目只按独占整行的标题识别，正文中引用`【栏目名】`、规则说明或台词不得被计为额外栏目。
1A. **模型可见载荷门**：逐句问“删除这句，是否会改变当前应生成的像素、动作、声音、camera/时序、真实附件控制或技术卫生？”若答案为否，该句不属于模型提示词。普通Fast Preflight直接拦截素材数量/文件管理、来源授权、分析取证、项目窗口、跨段依赖、验收历史、后期挂接以及“哪些素材不作为生成输入”等元说明；不等待冷审。禁止出现”本段独立冷启动/不依赖其他段落””只使用下列素材/其余由文字生成””参考片仅作分析证据/不作为生成输入””授权BGM母带后期挂接”等管理句。**素材溯源meta同属禁止（最高优先级）：** “具体X由模型自由生成””交模型””交模型决定””原文未指定，交模型””本段不出现，仅作身份锚点”——这些是制作台账管理句而非像素指令，模型看到”交模型”无法执行只增噪声；**留白的正确做法＝直接省略未指定细节**（如无参考图且原文未描述花纹，就不写花纹，不补一句”交模型”），让该维度自然缺省。**隐式跨段引用同属禁止：** “延续X时间线，同一空间””X已飞离/已离开””承接上段的X””延续Seg XX质感/空间/状态”——每段零记忆冷启动，模型看不到前段，此类引用既非像素指令也暗示了模型无法访问的上下文；**正确做法＝每段自足描述当前可见状态**（写”长椅空无一人”而不是”鸽子已飞离”；写”午后光线，普通公寓客厅”而不是”延续闪回时间线，同一空间”）。场景改写为当前可见事实；真实生成素材逐项写用途与控制维度；分析-only素材整句省略；后期-only母带留在台账，声音栏只写模型本段应生成的声音或静默。若某张真实参考图有灰底/平铺背景漂移风险，把正向控制范围并入该素材自己的单行，不另设汇总排除句。**注意区分**：真正传入 media 数组、但其主体本段不出镜的素材（典型是上游按整集固定挂载的参考图）不属于“分析-only”。首选把它从 media 移除、文案不再写它；若上游固定删不掉，本门不得把它整句省略——保留恰好一条「本段不出镜」正向排除绑定行（这是对已传入生成输入的渲染排除，不是被禁的管理句，详见 `02` 的「传入但本段不出镜的素材」），并须已在交付说明里向用户告警请上游移除该图。要清楚：这条排除行只是**不保证生效**的降级缓解，串脸由 media 数组决定、不由文案决定，删掉它会留下悬空条件图更不可控，但保留它也拦不住模型把图当垫图，唯一可靠解仍是不传这张图。只有确实没传给模型的素材才整句省略。
2. **冷启动硬门**：任取一段都能重建身份/声线、服装、地点/拓扑、道具归属与状态、参考职责、开场动作相位和本段OUT；素材各有唯一主行。
2A. **多镜模式段级执行合同门**：每个多镜模式独立段是否在`【运镜与时间轴】`内部、CUT 1之前依次写`前提 / 核心关系 / 导演意图 / 演员指令 / 对白规则`五行；内容是否只属于本段；导演意图是否由编译器基于剧本/正史主动提出，并明确本段戏剧功能、观众认知/情绪路径、调度/摄影目的和关系/权力/信息OUT，而不是用户、原片/原视频、参考素材、提示词工作流或视频模型需求的转述；演员指令是否可表演，对白白名单是否仍在CUT中准确触发。缺任一行、意图来源污染、把它们做成第六栏目、塞进基础风格、复制成逐CUT同义总则，均失败。单镜模式不机械要求该合同。
2B. **粗略输入导演化门**：`input_profile=director-expand`时，原文省略动作、表情、演员调度、分镜、运镜、焦点、反应或声音，不得被误判为禁止补充。每个剧情beat是否已经从故事事实编译出角色目标/策略、可见动作与表情变化、对白双方或冲突双方的同步表演、空间关系变化、camera/edit/focus证明和新可见状态；不能只是逐句换写、站桩说话或通用机位覆盖。所有补充必须可追溯到当前角色目标、空间、既有道具和剧情功能，并保持原身份、台词、关键事件及其顺序、剧情因果、关键道具归属、关系事实和OUT。`constrained-compile`、精确复刻、已验收稿及`narrow-repair`不得因本门被重新导演。
3. **拓扑建立与CUT动态可重建门**：先确认世界拓扑基础层完整且未被切镜篡改；新场景或尚未建立的空间系统，首个CUT必须用camera可见地标、主体关系、朝向与路线证明当前剧情所需拓扑。随后每个CUT必须具备：`IN` camera/主体元组；camera与主体分开的三维PATH、旋转和速度轮廓；主体跨foreground/midground/background的顺序；遮挡对象、覆盖峰值与解除点；screen投影滑移/缩放、真实后景视差与focus；`OUT`制动/稳定或保留明确速度向量的运动交棒点。只有明确 `locked-off camera` 才允许零长度camera path，此时真实背景稳定且无camera parallax，但主体投影仍可变化。若正文只有 `world-*`、面向某固定物或平面图关系，却没有camera-visible投影，直接失败；若所有CUT无叙事理由地固定，也判为镜头调度退化。每次换机位或camera/主体运动都重算相关画框，方向性道具的可见面、功能方向与目标成立，画外人物不被误列为可见。
3A. **主观转场与CUT本体门**：`CUT N`数量是否等于真实剪切/setup数量；同一setup内的rack focus、match dissolve、overlay、double exposure或状态变化是否作为连续BEAT而未伪增CUT。相同姿态/构图触发跨时态或跨状态转换时，是否冻结身份、world/screen锚点、景别、肢体角度、camera/lens/framing，只改变授权状态变量；重影层是否有明确出现峰值、消退终点并回到单一指定层；每次真实切镜是否同时有叙事理由和视觉/动作/声音接力。
4. **容量因果门**：对白按约3–5字/秒（安全线4字/秒）有最低容量，串行动作/camera/read/reaction/settle不超窗；逐个接触点都留出可读的进入、接触、双方反作用与恢复，不把多次命中和camera回稳塞进不足以辨认的窗口。`<=2秒`的接触CUT只承载“已预载的单次攻击 -> 一次接触/格挡 -> 立即双方反作用”；超过一步的位移、取道具、完整蓄力、第二次接触或稳定settle必须前置、并行有证据或扩展窗口。动作路线避开当前人物/家具占位，无穿越或瞬移；下一CUT的IN从上一CUT的OUT继续，不重做已经完成的动作。任何仍在移动、滑落、传递或失稳的活动道具，在下一CUT不再入镜前必须可见落定、交接、被接住、离画或明确持续去向，不能从frustum和状态台账中直接消失。
4A. **表演幅度与关系反转门**：剧情是否先分配表演基线/面具、触发泄漏、主动压制、击穿点、唯一主要情绪表演峰值和峰后余波；动作能量峰、决定点与情绪峰是否被正确区分。若后续接触/后果才是情绪兑现，是否没有在转身、奔跑或靠近时提前透支最高强度；每阶段是否使用当前景别可读的眼神/呼吸/嘴部/肩背/手/重心/步态/距离证据并服务角色策略，WS是否没有虚构瞳孔/嘴唇/吞咽等不可读微动作。峰后不能继续同强度表演；受伤、感染、醉酒或失神状态若无剧情恢复，不自动出现正常保护反射、协调步态或主动安慰/回抱。
5. **声音卫生门**：`audio` 默认 true（有声），声音层必须存在——要台词写全人声六要素（说话内容+情绪+语调+语速+音色+口音，语调/口音选配），不要人声写「全片无台词」，不要配乐写「无背景音乐」，否则模型自编BGM；台词/OS/旁白位于对应CUT并指明说话者/对象/表演；环境/动作/生理声音可归因；保留无BGM、无字幕/水印/乱码和人物结构/身份稳定等技术卫生；不让模型生成字幕（一律「画面干净无字幕叠加」，画面文字与道具文字交后期）；`ratio` 靠参数不靠文字（提示词写“竖屏”模型不吃）；不依赖 `prompt_extend`，用结构化公式一次写足；`negative_prompt` 已废弃，所有“不要X”已改写成正向排除（例外：「镜头不要切镜」这类已验证固定控制短语）。

第一次PASS即记录结果并停止检查。若失败，集中修复一次，只复跑失败项与第1项包络硬门；候选未改变时不得再次运行同一验证器或把下方扩展清单线性重扫一遍。长篇每段PASS后冻结，只核对相邻段边界；最终仅汇总段数、总时长、每段字符上限。窄修改还必须核对实际diff符合差分合同。

## Extended Diagnostic Index / 按问题加载的 Wan3.0 稳定性门

下列细项保留为失败定位、生成结果复盘、`full`审阅或用户明确要求穷尽检查时的诊断索引。普通PASS候选不线性扫描全部条目：

1. 是否已解析 Wan3.0 时长与镜头结构（`Tmax=30秒`，`duration` 2–30 或 `-1`，默认5）；每段是否 <=30 秒，全部是否 <=5000 字符且默认保持 `5-Tmax` 秒；多镜模式时码是否从0连续、首尾相接、无重叠/倒序/留白且求和等于 `duration`，镜头数 `>4` 时是否已用一致六补丁做稳跨镜一致性（`<=4镜` 只是风险提示，不自动拆段；是否拆成多段由 `split_policy`（默认 `off`）决定）；单镜模式是否已显式写「生成单镜头」/「一镜到底」。
1A. **Wan3.0 已知弱项门**：空间逻辑（躺卧朝向写错、人物与物体比例失衡）是否用显式坐标（位置+朝向+距离）写死，躺卧是否必写头脚方向并给出比例锚点；剧烈物理交互（打戏/摔倒/破碎/泼洒/高频身体接触/快速多人穿行/精细手部）画面稳定性弱，是否走“检测 -> 提醒 -> 方案 -> 用户决定”，不硬阻断也不静默软化创作意图；特效/动效（幻术/分身/能量）弱，是否降预期或拆段；长台词易截断，是否按 `3–5字/秒` 核算，超标20%以内原样保留、超过20%才拆段并加衔接锚点；文本绿网在输入阶段过审，命中敏感词直接 `FAILED`（Green net check failed for text），是否软化触发词或如实告知，而不是用画面级补丁治文本级拦截；开场默认看镜头（摆拍感），是否显式写“四分之三侧身、视线锁定对手/目标物、不看向镜头”（对镜独白除外）；硬切转场跨镜一致性不自动保证，客户要求硬切时是否没有擅自改一镜到底，并用六补丁（每段复述角色标识、显式跨镜一致约束、场景视觉锚点、固定 seed、切点避开中间字、参考图最小化）做稳；转场是否按场景选、忌一律硬切——同场景连续动作用运镜衔接（不切），同场景换机位顺切，跨场景/跨时空/情绪跳转选叠化、淡入淡出、闪白闪黑、匹配剪辑、遮挡Wipe、甩镜或光效过渡。
2. 每段是否独立完整，不依赖上一段记忆。

34N. 行人追逐/逃亡是否分别建立被追者、每名追赶者和 camera 的 world route/safety corridor，锁定出口、障碍、拥堵点和关键距离；camera 是否没有占用追赶者必经线，任何穿轴/让路/转向都由可见横移、弧移、减速或地标绕行证明。
34O. 追逐表演是否让回头遵循注意/视线先行、颈肩躯干跟随、步态受扰或平衡修正、视线回到路线；负重是否按携带拓扑产生下坠、相位滞后、碰撞和阻尼，并实际改变摆臂/转弯/疲劳；每名追赶者是否有不同策略、步态、障碍反应和呼吸，而非复制奔跑。
34P. 追逐一镜到底是否只有一个连续 camera start-path-end，camera相对位置、look direction 与人物可见身体面是否一致：前方回看的 `lead tracking` 见正面/斜正面，后方同向的 `follow tracking` 见背面/斜背面，侧向平行的 `lateral tracking` 见对应侧面，绕行/转身后已重算；定焦景别变化是否来自距离/构图、焦段变化是否来自明确 optical zoom；每次遮挡和 focus/framing handoff 是否写清旧主体、触发、新主体、短暂失焦与重新捕捉依据，遮挡前后的人物距离、camera高度/方向和视差连续，离画由真实空间或画框边界完成。
35. 剧本未提供详细动作时，是否已根据目标、阻碍、策略、关系、空间和既有道具补充不改变剧情的专业调度，而不是直接生成站桩对白。（例外：若提供了站位参考图，起始相对站位/间距/朝向/队形以站位图为准，不自行臆想编排，只补充参考图未覆盖的时间维走位与动作相位；见 SKILL.md「站位脑补禁令」。）
36. 每句台词是否有开口前触发、说话中动作、语义节点上的听者反应和句尾新状态；台词是否没有机械地从每个 CUT 第一帧开始，跨 CUT 时是否在自然分句处连续说完。
36A. 是否先在项目台账建立完整角色表演母档案，再按当前场景的目标、阻碍、策略、触发和压力改写；每个有功能且与台词、动作和摄影机不冲突的表演层是否被保留为可同步状态，而不是因字段较多被误删或整份母档案逐段复制。
36B. 眼部行为是否有明确注视对象、思考领先于转头/身体、与压力相符的眨眼状态，以及近景可读时的自然 catchlight；是否避免随机眨眼、错误 eyeline、无意看镜头或把眼部微动作排成独立流水线。`<=1秒` 新反应仍只有一个主反射，`1-2秒` 只有一个主变化和最多一个同步辅助；close-up 只提高已选层的可读性。
36C. 年龄锚点是否只在角色已确认成年且有助于身份稳定时写入；是否没有把未知年龄推成精确数字、把未成年人写入成人年龄模板，或为满足模板静默修改正史年龄。
36D. 每个具名角色的描述是否包含地域语境、口音、音色/音区/共鸣、说话习惯和当前生理状态，即使角色本段暂不发声；是否把稳定声线身份与哭腔、气短、疼痛、疲劳等本场变量分开，没有只写“东北味、御姐音、电影嗓”等抽象标签。无名后景群众可免除个体声线。
36E. 声音身份来源是否遵守“用户/正史 -> 已分配声线参考 -> 直接可听证据 -> 保守生产推断”；无证据时是否使用通用标准口音并保持具体省市未锁定，没有从脸、服装、职业或类型刻板印象编造强方言。若使用参考音频，素材是否独占一行，角色主行是否写完整声音身份并引用声线锁定名，音频行是否只写可听实现/增量差异而未逐项复述，本场生理变化是否在对应CUT发生。
36F. **单 CUT 台词密度门**：是否有任一 CUT 把越过密度阈值的连续台词（单镜连续口播约 `>8–10 秒`/安全线约 `>32–40 字` 而无视觉变化、同一说话者+同一机位连续念 `>2–3 句`而无信息/情绪/权力变化、或一段台词内出现两次及以上语义转折或说话者↔听者来回）压成一个静止「说话头(talking head)」长镜；如是，是否已按覆盖(coverage)设计分配到多个有动机的 CUT（正反打/反拍到听者、`reaction cut`、道具/手/环境 `insert`、`push-in` 或景别/机位/角度变化），并用 J-cut/L-cut 或「台词跨 CUT 连续」让同一人声在切点自然延续。护栏核验：① 这是段内 CUT 覆盖、不是拆段，`split_policy`（默认 `off`）与台词总时长/`3–5字/秒` 可读性未因覆盖而改变，没有因台词多就把一段拆成多个独立段；② 每个新增切点仍过「切镜理由 + Hard Cut 准入门」，由语义/信息/权力变化或听者反应驱动，没有逐句机械切或为凑镜头往返切；③ 单镜模式/一镜到底没有伪增真实切镜，改用同一连续 camera path 上的 push-in/orbit/重构图、`rack focus` 到听者或道具、`BEAT` 变化与每 2–3 秒 marker；④ 有明确戏剧理由的长 hold/长镜独白（慢节奏、情绪渲染、权力压迫、对镜独白）不被本项误判为失败；⑤ 本项与「长台词超标 20% 才拆段」是不同轴——先做覆盖，覆盖后仍超 `Tmax`/5000 字符才回到拆段判断，二者互不替代。详见 `06`「对白密度触发镜头覆盖」。
36G. **逐字保留审计**：源剧本/小说中每一句 spoken line（角色实际说出的台词、旁白 VO）是否在编译后的正文中有明确落点——归属到具体 CUT/BEAT、标明说话者并保留原始措辞。特别注意：① 短答/插入语（如 `"Provisions?"`、`"What?"`、`"Go on."` ）因字数少极易在段边界或 CUT 拆分时被吞掉，须逐句核对；② 源文本中被叙述归因标签（`X said/continued/asked`）包裹的台词，剥离归因标签后仍须确保 spoken words 本身完整落点（见 `06` TTS 归因标签剥离规则）；③ 多段拆分时，前段末尾与后段开头的台词衔接须无缝——前段 OUT 不能吞掉后段第一句的触发语，后段开场不能遗漏前段最后一句的回应。审计方法：逐句比对源文本 spoken lines 与编译正文中的引号/台词标记，确认每句有且仅有一次落点（跨 CUT 连续算一次）。
36H. **锁定区与 CUT 级描述一致性**：`【角色/场景/素材锁定】` 中对道具、服装、空间属性的方向/顺序/状态描述是否与 `【运镜与时间轴】` 中 CUT 级描述一致，无矛盾。典型失败：锁定区写"纽扣从上至下逐颗扣上"而 CUT 写"从下往上第二颗"；锁定区写"右手持剑"而 CUT 写"左手抽出"；锁定区写"门向左开"而 CUT 写"向右推开"。核验方法：对锁定区中每个带方向/顺序/ handedness /状态的属性描述，grep 其在时间轴中的所有出现，确认一致或在时间轴中标明了变化触发点（State-changing prop 按道具状态时间轴处理，不算矛盾）。
37. WS/MS 多人对白是否有前中后景注意力层级、主次动作幅度和错峰反应；是否避免全员同时转头、停手、点头或抢动作。
38. 慢节奏 CUT 或 `locked-off camera` 是否用低幅呼吸、握力、视线、重心、道具动作以及焦点、光影、环境或声音变化持续推进，并落到明确的下一状态或切镜条件。
39. 对话 camera setup 是否由关系、权力和信息归属选择，而不是默认平视正反打；camera movement 是否没有被用来掩盖演员缺少调度。
40. 动作声、道具声和生理声是否与时间轴中的动作同位、同序；`【声音设计】` 是否没有把声音事件挪到动作之前或之后。
41. `【声音设计】` 是否默认明确“无背景音乐”，并保留现场声、动作声、环境声、台词及明确要求的声音；用户要求 BGM 时是否只覆盖这一冲突项；`audio` 默认 true，声音层是否存在——有台词是否写全人声六要素，无台词是否写「全片无台词」，不留空声音层让模型自编BGM。
42. `【画面限制】` 是否只保留精简固定模板：无字幕、无水印、无乱码文字；人物身份稳定，面部、身体和手部结构自然完整；是否没有让模型生成字幕（一律「画面干净无字幕叠加」，画面文字与道具文字交后期），且 `negative_prompt` 已废弃后所有“不要X”都改写成正向排除（例外：「镜头不要切镜」这类已验证固定控制短语）。
43. 最终提示词中的演员行为是否全部使用肯定句；后景连续性是否用主体、身体部位/道具、路线和节奏重复表达。正向机位、动作、身份、道具或 OUT 状态已锁定后，是否删除同义否定句。
44. 每个 CUT 是否只承担一个明确变化；是否允许多个肢体、焦点、运镜、材质、环境和声音辅助变化共同建立、推进、确认或接力它，同时避免出现第二个同等级叙事结果、新动作目标或结果承受者。一镜到底是否保留 `CUT 1`，并以同样规则组织内部 BEAT。
45. 每个 CUT 是否从上一镜末端的同一动作相位、screen direction、焦点、材质运动或声音状态接入，没有重演接近、蓄力、迈步、挥击或坠落的准备阶段。
46. 翼拍、巨口、肢体/武器路线、视线、焦点、飞散材质、自然前景遮挡或声音等接力载体是否在上一镜末端已经可见，并由下一镜明确接收。
47. 是否先完成节拍级最短可读估时，再把相邻兼容节拍拼成 `<=Tmax` 整段；台词、动作和反应是否尽量并行。
47A. 是否没有用“总时长 ÷ CUT数量”平均分配；每句普通中文台词是否先按实际可听文本约 `3–5字/秒`（安全线 `4字/秒`；5秒≈15–25字，10秒≈30–50字）计算最低口播时长，不计角色名、标点、引号、空格和 `【动作】`，数字/英文按实际读法折算，明确停顿另加。
47B. 每个CUT是否只把必须串行的动作、反应、信息读取和camera settle加到口播底线；并行轨是否只追加超出口播窗口的余量；同一句跨CUT是否只计算一次并按对应字数分配，而不是重复整句或平均切秒。
48. 是否执行压缩：合计 `>30秒且<40秒 -> 26-30秒`；是否避免可并回前后段的短碎段，同时没有为了接近 `Tmax` 拉长单个动作、普通反应、空镜、慢动作或结尾 hold。
48A. 多镜模式是否没有误套单镜模式的 `3-6 CUT` 或 `3-6 marker` 上限；新增 CUT/marker 是否都由可读的明确状态变化、阶段推进或有效声音重音驱动，而不是为了填满30秒；镜头数多本身不算过载，只有串行语义负载超出可读时长才算过载；`>4镜` 的跨镜漂移风险用一致六补丁做稳，而不是按镜头数自动拆段（是否拆成多段由 `split_policy`（默认 `off`）决定）。
48B. 多镜模式完整30秒多事件叙事是否允许6-12个有动机CUT，简单内容是否允许更少；是否没有用CUT数量直接判定过载，而是检查串行语义负载。
48C. 多镜模式计划 `T>=20秒` 且命中长段门时是否自动启用全部镜头连续时码；是否从 `Resolved Policy` 读取整秒推荐/小数允许/整秒硬要求，而不是把默认整秒提升为失败条件；是否建立原因先于行动、行动先于结果的里程碑。
48D. 多镜模式每段的五行执行合同是否完整且互不越权：前提无历史说明，核心关系能约束各方行为，导演意图是编译器从本段剧本/正史主动形成的戏剧阐释，包含场景功能、观众认知/情绪路径、调度/摄影目的和关系/权力/信息OUT，不含用户/原片/参考素材/提示词/模型等来源叙述；演员指令包含逐名目标/策略/身体任务/升级曲线，对白规则是准确白名单；合同中的全局事件数量、关系不变量或camera母题是否只声明一次，逐CUT只补本次实际执行。
48E. 是否先从最终必达OUT倒排结局和高潮预算；开场建立、普通反应、环境展示和装饰运镜是否没有侵占预留尾段；每个CUT是否按自然台词、串行动作、camera travel/settle、接触反应完成静默排演。
48F. 持续环境状态是否跨CUT继承且每镜只选1-2个方向证据；实体退场是否保持不透明并通过路线、距离/深度检查点、尺度缩小、受力姿态和真实遮挡/离画完成。
49. 同一说话者跨 CUT 时，前一镜是否标明开始及准确前半句，后一镜是否标明同一人声连续及准确后半句；画面是否可交给听者、道具或空间而不丢失声音归属。
50. 台词、呼吸、电话声和声音桥的“跨 CUT 连续”是否只发生在同一独立段；若进入新段，是否已重新点名声音源、当前接通/发声状态和准确语句，而不是依赖上一段。
51. 锁定名是否只在当前独立段内复用；角色、场景、关键道具、声线和文字贴图在每个出现它们的独立段都重新声明了原始引用、用途和当前状态。
52. 是否先建立不随 CUT 或机位改变的世界拓扑：墙、门、窗、工位/座位、入口出口、人物位置/朝向、路线、危险线和行动轴；用户验收过的空间纠正是否已锁定为连续性正史。（有场景参考图时，该世界拓扑/布局/门窗结构/陈设/材质/光线氛围从场景参考图读取，不自行设计或脑补一个与参考图不同的场景，也不复述参考图已载明的陈设外观；仅在无场景参考图时才自行构建最小充分世界拓扑。见 SKILL.md「场景脑补禁令」。）
53. 每个 CUT 是否明确或可推导摄影机所在侧和看向方向，并据此重新计算人物正面/背面、可见固定物、foreground/midground/background 与 screen-left/right，而不是复制上一镜标签。
54. 是否把 background 当作摄影机相对概念；人物面对的门/对象只有在摄影机位于人物身后朝该对象拍时才可成为背景，正面反拍时是否改为画外/摄影机后方并显示人物身体后方的真实空间。
55. reverse angle、侧拍、俯拍和跨段首个 CUT 是否继承同一世界拓扑和行动轴；如需过轴，是否有中性正轴 CUT、可见穿轴运动、空间再建立或明确叙事理由。
56. 每个 CUT 是否通过画面可重建门，同时仍只有一个明确变化；简单近景是否只合并表达，而没有把“构图紧”误当成可省略地点、摄影机侧、主体位置、实际画框内容或真实后景。
56A. 多人、对白、门洞/相邻空间、人物依次入场、交接或正反拍场景，是否先建立统一世界拓扑；首个相关CUT是否用可见画面建立剧情所需空间关系；之后正文是否持续按“摄影机与视锥 -> 实际画面/真实后景 -> 逐个可见人物的画面位置/可见面/任务 -> 对白归属”重投影，而不是用段首总站位或纯世界关系替代camera所见。
56B. 每句对白是否明确说话者的世界位置、身体/脸/目光终点和 intended addressee；目标听者是否通过 reciprocal eyeline 或可见反应接收，第三人是否没有误占该视线终点。
56C. dialogue axis、threshold/observation axis、handoff/task axis 和 movement axis 是否分开维护；相邻 OTS/CU/reaction cut 是否没有把第三人错误编译成隐式 shot/reverse-shot 听者。
56D. 当第三人仍是最强可见听者或当前场景缺少对白动作动机时，是否已通过重排 blocking、移出当前 frustum、三人建立镜或迁移对白场景解决，而不是继续堆同义否定句。
56E. 锁孔、门把、手脚、鞋或道具 insert 是否只控制当前 setup；下一 CUT 是否以 hard/direct cut 声明新机位/景别/视锥，身份重要时是否保留脸/发型/服装锚点而非孤立局部。
56F. 每个 CUT 是否足以独立重建当前画面：地点/子空间、开场画框、摄影机与真实后景、所有可见命名人物的深度层级/画面位置/身体朝向/目光/道具接触/当前任务与表演状态、持续场景状态、本镜明确变化和可见 OUT 是否齐全。
56G. 是否把“同一时刻成立的状态声明”与“按顺序发生的状态变化”分开；站位、姿态、表情底色、持续任务、光线和后景状态是否用“保持/同时/画面内/background持续”等并列，而没有被误算为第二个主变化或额外时长。
56H. 详细描述是否只增加当前画面所需事实；是否使用锁定名而未重复身份/服装/风格全文、同义形容词或不影响轴线/对白/路线的画外信息。
56I. 开场同时有四个以上需独立辨认的活跃主体且空间关系未建立时，是否允许约首秒 WS/EWS 校准全部主体、地标、任务和主关系线；它是否承载真实低幅活动并计时。三个及以下主体、空间已建立或关键台词/接触必须立即发生时，是否避免机械插入首秒全景。
57. 场景与人物是否按实际显现顺序描述：运动 CUT 为起始画面 -> camera movement/遮挡/视差 -> 新揭示对象 -> 最终焦点；静态全景为焦点优先或 foreground -> midground -> background、每层 left -> center -> right。
58. 本段素材锁定是否覆盖所有 CUT 会进入摄影机视锥或声音场的参考并集，包括虚焦后景人物；是否排除了不会出现也不承担控制任务的无关素材，并保证每个维度只有一个主参考。
59. `@` 素材是否写清短锁定名、类型/用途、控制维度、本段作用域和当前状态；动作/运镜参考是否把运镜逻辑与参考视频画面内容分开。
60. 是否把前后段关系、已完成内容、未来保留内容、验收历史和制作解释全部留在静默制作台账，模型提示词只含本段生成事实。
61. 最终 CUT 是否只锁定当前可见 OUT：人物/道具位置与接触、动作相位、摄影机、构图、焦点、环境运动和声音；没有解释下一段将发生什么。
62. 机位连续性是否使用“摄影机位置/看向 + 轴线侧 + 焦段 + 人物角度 + 人物大小/景别 + 眼睛高度”的正向元组；是否删除“不得正脸/不要换焦段/不要改变大小”等同义反向提示。
60. 运镜是否写清承载方式/路径、方向、速度或加减速轮廓、主体保持、起点、终点和剧情结果；`smooth/gradual/fast` 是否没有被单独当作完整指令，复合运镜是否写清各分量的机械关系。
61. 是否原样保留三种已确认的台词控制语法：引号内全角圆括号 `“（内容。）”`表示内心 OS，半角星号包裹的 `*内容*`表示重音，台词结构中的全角方头括号 `【动作】`只表示角色在该位置执行的动作；是否没有把 `【贴近】`等角色动作误判成声音距离，也没有把标记改写成“内心OS标签”“重读某词”或引号外的错位动作。复杂位移、接触、反作用和听者动作是否仍在 CUT 正文中完整描述。
62. 从教程/讲解视频新提炼的硬规则是否具有“原视频 + 带时间码音频转写 + 同时间画面/界面示例”三项证据；是否避免把自动章节、标题、评论或单独转写直接升级为模型协议。
63. 运镜参考视频是否优先为约5-8秒、单一可读运动逻辑，并与目标主体运动类型相近；手持是否写幅度与频率，POV 是否写视角来源与高度，画内 lip-sync 对白是否保持嘴部可读、正常语速并完整留在同一独立段。

## 战斗与来源审计补充门

在 Wan3.0 时长与镜头结构已确定、准备输出打戏段时，再逐项执行：

1. **战斗简报追问门**：若需求极简或信息不足，先问不超过3个高价值战斗问题（双方差异/目标、场地结构与可用道具、必达 OUT）；用户明确授权默认时才跳过，不能用猜测填空。
2. **交换链先于镜序**：无参考的长打斗先依据角色差异、目标、场地结构和必达 OUT 写出2-3条可区分的攻防交换链，再选择 CUT 与 camera；不得套用固定镜序、焦段序列或外部样片节奏。
3. **逐 CUT 动作时长核算**：纯动作 CUT 逐项核算预载、路径、接触/落空、双方反作用、恢复、重定位及 camera travel/settle；任何一项未完成，不得只缩短时码来“塞进”段长。
4. **不间断长 CUT 的 BEAT 例外**：普通短 CUT 仍只有一个主运镜；整段一镜到底或多 CUT 中明确标记的 continuous action master 才可在该不间断 CUT 内用 BEAT 串联阶段，每个 BEAT 只设一个主 camera phase，并继承上一 BEAT 的摄影机终点、方向/速度、主体大小、焦点、动作相位和效果残余。
5. **联网研究证据门**：自动联网研究若启用，来源、证据和适用动作字段必须直接服务当前动作/物理/摄影消歧；未经授权的外部角色名、招式名或整套镜序不得进入当前提示词。
6. **宏观结构指纹审计**：记录段落顺序、CUT 密度、镜序、焦段/节奏峰值及其来源；参考提示词仅在用户明确授权的结构节奏维度生效，不能借结构指纹带入未授权内容。
7. **无台词打斗声线例外**：纯无台词打斗且没有用户/正史/声线参考硬要求时，五维声线（地域语境、口音、音色/音区/共鸣、说话习惯、当前生理状态）可压缩为“无台词 + 呼吸/受力声/必要喊声”的可听层；不为补齐这些字段而稀释动作、接触、恢复和 OUT 核算。
8. **打击感摄影反馈门**：重击或用户要求强受击反馈时，是否写成“接触前可读 -> camera沿攻击向量follow/whip-pan -> 接触点一次同向短促jolt/shake -> 受击者位移 + 攻击者反震 + 材质/环境/声音确认 -> 阻尼回稳到后果OUT”；横拳才默认横甩，其他动作服从真实向量，且没有用随机全程震屏、过量失焦或motion blur遮住接触。
9. **相邻状态差分门**：逐项比较每个 `OUT N -> IN N+1` 的世界锚点、距离、高度/台阶、深度顺序、支撑、朝向、握持/接触、动作相位和速度；连续交锋中的每个差分是否由可见位移、新camera重投影或明确允许的省略证明。camera同侧且人物未可见交叉时，screen-left/right相对顺序不得翻转。
10. **景别覆盖门**：本CUT声称必须看见的脚、手、双人关系、长兵器两端、接触点和环境支点是否真实落在当前shot size/frustum内；需要同时读全身支撑与长兵器接触时是否使用MLS/WS，CU/MCU/MS是否没有宣称裁切外证据可见。
11. **决定性慢动作原子窗**：降速起点、实体/能量边界接触、接触后VFX与第一拍双方反作用是否位于同一CUT或同一不间断BEAT；期间是否没有hard cut、隐藏切、另起insert、动作悬停或重复预载，恢复实时后才进入恢复/OUT或新机位。
12. **长兵器接触见证门**：是否可连续还原持有者、前后手握点、完整杆身、功能端/被施力柄段、命名接触面/支点、反力方向和恢复/脱手顺序；杠杆缴械是否区分法向夹持、切向旋转与第二支点，避免只断言结果。
13. **动作承诺与覆盖加速门**：是否依据场景功能决定开段先证明即时冲击、迫近威胁还是空间关系，而非固定“两秒内命中”；连续多击是否由前一击造成的防守、位移或空门生成下一击条件；快速多角度覆盖是否仅在轴线清楚且每次切换新增空间、路线、接触或后果证据时使用，并以动作相位、运动向量、视觉重心或同步声音接力。若是一镜到底，是否把这些信息任务编入连续 camera 路径而没有伪造 CUT。

## 模型预算分配

Wan3.0 一段生成不能同时把所有维度做到最高。写提示词前先判断主消耗。模型预算限制的是互相竞争的高精度任务和按时间发生的状态变化，不限制重建当前画面所需的地点、站位、后景、持续任务和表演底色；这些同帧状态只有各自发生新变化或要求独立读取时才增加时间负载：

| 主消耗 | 适合 | 必须牺牲 |
| --- | --- | --- |
| 角色一致性 | 近脸、台词、表演、产品形状 | 大幅动作、复杂人群、快速切镜 |
| 动作幅度 | 打斗、追逐、摔倒、救援、机器运动 | 精细脸部、手指、文字、logo |
| 场景密度 | 人群、灾难、市场、战场、复杂背景 | 单个路人身份、细小道具、精确台词 |

修复原则：

- 近脸说台词时，使用 `locked-off camera`，或只使用一种写明方向、路径、幅度和终点的低幅摄影机运动；保留一条可读的承载动作、呼吸/握力/视线微反应或句尾状态变化，手部和背景使用更低幅度。
- 强动作时，把情绪写到身体、重心、接触点和恢复姿态，不强求脸部微表情。
- 人群/灾难时，让群众成为一个有方向的群体，不让每个人做独立动作。
- 可读文字、字幕、logo 优先交给后期；不要让它和复杂动作竞争。

## 动作成片三通道验收

用户提供实际生成视频时，动作戏先按三个互补通道验收，再决定保留、后期修、重跑或重写：

1. **静音观看**：不依赖声音判断空间、身份、攻击源、路线、接触/闪避、双方受力、恢复和状态更新是否可读；摄影机是否展示动作而不是遮盖错误。
2. **只听声音**：确认预载声、破风/机械升频、接触主音、低频体积和尾音层级；轻击与重击不能同样响，角色/武器/环境声来源与画面相位一致。
3. **逐帧检查关键接触**：检查接触前后约3-5帧的手脚、关节、握点、刃口/枪口、武器数量、碰撞点、穿模、反作用、特效遮挡、环境反光和进入/离画路径。

再做两层语义验收：

- **镜内完成层**：启动、路径、接触/落空、响应和退出条件是否依次完成；证明姿态读清后是否立即离开，没有无因停留。
- **全段状态层**：站位、空间区域、支撑、遮挡、持有关系、主动权和材料后果是否持续更新，没有因 CUT 增加而停在同一关系。

验收结果先写入观察台账：实际 OUT、动作相位、摄影机尾态、声音尾态和偏差。只有用户明确指定某段视频继续控制动作、运镜、节奏或声音时，才把对应维度授权给下一段 `@视频`；接受为正史不等于自动成为全维度生成参考。

## 生成结果复盘 / Retake Protocol

用户给出生成结果、尾帧、失败描述或要求“怎么修”时，先判断结果属于哪类：

动作/多镜结果先额外标记一种主故障层：`Cut Boundary / Action Change / Relation Change / Temporal Occupancy / Frame Adherence`。切点出现不证明关系变化，时间戳接近也不证明动作完整；只修主故障层及其直接依赖，避免用加 CUT 修镜内冻结或用改 OUT 修跟随脱靶。

| 结论 | 判断 | 下一步 |
| --- | --- | --- |
| 保留 keep | 主目标达成，瑕疵不致命 | 接受为正史，记录结尾状态，继续下一段 |
| 后期修 fix in post | 问题是调色、字幕、裁切、混音、轻微尾帧 | 不重跑，用后期修 |
| 单层编辑 edit one layer | 构图和时机正确，只有一个图层错 | 保留源片，只改该层 |
| 重跑 re-roll | 提示词合理，只是抽样不理想 | 同提示词换 seed/重跑 |
| 重写 rewrite | 同类错误连续出现 | 改提示词结构，不加形容词 |

一次只改一个变量：

- 一个提示词句子。
- 一个参考素材。
- 一个模式。
- 一个 seed / retry。
- 一个时长或分段策略。

如果一次改很多变量，无法判断哪一项有效。连续两次出现同一失败，说明不是运气问题，需要重写结构：拆段、重锚角色、减少动作、删除文字依赖、降低人群密度或改用末尾帧位置参考并重新设计新机位。

### 提示词-视频配对学习

复盘时逐项对比“提示词意图”和“实际可见结果”：身份、画面结构、动作路线、接触点、运镜、光线、声音、结尾状态。每项只标一种结果：`遵循 / 误读 / 遗漏 / 过度执行 / 漂移`。

可复用证据等级：

- A：至少两个不同提示词-视频配对重复成功，可升级为稳定规则。
- B：单个案例清楚成功，只作为候选规则，继续验证。
- C：项目专名、角色/IP、偶然风格或单次抽样特征，不泛化。

生成样片和审片视频默认只用于分析；只有用户明确指定时才成为下一次生成的 `@视频` 参考。复盘结论只进入规则或制作记录，不把网址、历史、验收意见和失败原因写进可复制的视频提示词。

## 故障修复矩阵

| 问题 | 原因 | 修复 |
| --- | --- | --- |
| 角色漂移 | 每段未重复身份锚点，或跨段丢失参考绑定 | 每段重新绑定该角色的 `@图片N` 参考句柄（身份/长相/服装由参考图承载）+ 复述姿态/位置/朝向锚点；**不得靠脑补文字服装来"补锚点"**——编造的外观与参考图冲突反而加剧漂移（见下「外观脑补/编造」行） |
| 外观脑补/编造 | 锁定行或时间轴写了原文没写、参考图也未必如此的服装颜色/发型/妆容/年龄感/体型/配饰（如按「商界男＝深色西装」「女性＝精致妆容长发」「长辈＝灰夹克/深蓝衬衫」刻板印象填词） | 做减法：删掉无出处外观，留白交给参考图，锁定行只写短名+该图职责+当前动作/情绪/位置/作用域。两层危害：① 编造外观与参考图冲突→给模型矛盾身份信号致漂移；② 给不同角色编出相近外观（如都穿深色系上衣）→在文字层面制造相似度，叠加机位反转的空间投影重叠，直接诱发串脸/融脸（第二类串脸文字诱因）。只有原文/客户提示词字面写明或参考图直接可见可证的外观才可原样引用，与 36C 年龄不编造、36E 口音不臆测同一纪律 |
| 串脸/融脸/多余同貌人 | 未出场角色的人脸参考图仍被上游按整集固定传入 media——只要图被传入，模型就会把它当垫图融进出场角色或后景；串脸由 media 数组决定、不由文案决定，写“本段不出镜”或删绑定行都拦不住（删绑定行还会退化成“传入了却无描述”的悬空条件图，更不可控） | 唯一可靠解＝不传这张图：能裁 media 数组就把该图从数组移除、从源头消除，文案也不再写它；media 由上游固定删不掉时，文案无法可靠防串脸，必须向用户显式告警“请上游把该图从本段 media 移除，提示词层面拦不住模型把它当垫图”，保留的「本段不出镜」正向排除行只是不保证生效的降级缓解（避免主动指示渲染/避免悬空/留痕），不得当成已解决 |
| 分段过碎 | 把每个分镜都输出成独立提示词 | 把同空间、同人物、同动作链、同说话者的 beats 拼成 `5-Tmax` 秒段落 |
| 场景漂移 | 没有固定空间结构 | 写 foreground/midground/background 和 fixed objects |
| 后景人群消失 | 只在首个 CUT 写了群众，后续全景/reaction cut 未重复 | 每段和每个 WS/EWS/全景 BEAT 重复 crowd density、位置层级、主方向、拥堵点；写 background crowd remains softly blurred but visible |
| 段落边界重复 | 静默规划未比较前段 OUT 与当前开场 | 在制作台账中改景别/机位/主体/动作状态/空间尺度/信息焦点；模型提示词只写改好后的当前正向开场 |
| 独立段首句缺对象 | 用“停止吹气、收好东西、沿来时路线、门回落、文件下垂”等句子依赖前文 | 按“角色名 + 身体部位/工具 + 命名对象/目的地 + 起始状态 + 路线/接触点 + 可见结果”重写本段开场 |
| 独立段素材锁失效 | 角色、道具、文字贴图或声线只在总说明/上一段锁定 | 每个出现该素材的独立段重新声明原始引用、锁定名、控制维度和当前状态；时间轴仅在本段内部复用锁定名 |
| 跨段台词/声音悬空 | 把同段跨 CUT 规则误用到两个独立提示词块 | 优先把完整发声链装进同一段；必须拆段时重新点名声音源、接通状态和当前准确语句 |

| 临时状态覆盖固定声线 | 一次哭腔、气短或醉意被写成跨段永久音色 | 固定地域/口音/音色/语言习惯留在角色锚点；本场变量在触发CUT开始、变化或消退，并进入口播时长核算 |
| CUT错序或结果倒灌 | 长因果链没有可执行顺序、前置关系和状态里程碑 | 为多镜模式高因果长段全部CUT分配 `第N个镜头[a-b秒]` 连续时码并服从已解析粒度；单镜模式使用明确CUT顺序和相对相位；写原因->行动->结果前置图和最迟完成状态 |
| 环境状态抢占人物时间 | 每个CUT逐件展示风场、雨幕、碎物或灯具反应 | 把环境写成跨CUT持续状态机；每镜只选1-2个方向最清楚的证据，其余保持为背景状态 |
| 实体远去时渐隐/透明 | 用“剪影、吞没、消失”代替物理路线 | 主体保持不透明；写距离/深度检查点、尺度缩小、受力倾斜/旋转，最后由真实遮挡或离画结束 |
| 听者动作缺失 | 只标声音归属，没有设计听者反应 | 补视线/表情和手、呼吸、肩线、重心、脚步或道具反应；画面容量不足时裁切、遮挡或安排合理离画 |
| 说话者站桩 | 台词只绑定口型，没有开口动机和承载动作 | 按“开口前触发 -> 说话中动作 -> 语义节点 -> 句尾新状态”重写；选择符合呼吸和发力条件的动作 |
| 多人同框像排队念词 | 只设计当前说话者，其他人同步停手或转头 | 指定主行动者、第一反应者和低幅持续任务；前中后景错峰变化，camera framing 在语义节点转移注意力 |
| 为反站桩而全员乱动 | 把“每人有任务”误解为每人持续大动作 | 每 CUT 只保一个主要注意力事件；次要动作降低幅度和速度，只服务潜台词、空间、切点或下一状态 |
| 对话 camera setup 平淡 | 默认平视正反打或用 camera movement 代替调度 | 从权力、亲密、回避、隐藏、喜剧延迟或反转选择双人纵深、前景遮挡、高低差、负空间、reaction cut，或有明确戏剧理由的 `locked-off camera` |
| 慢节奏画面停滞 | 只写情绪或 locked-off，没有可见进展 | 补触发后的低幅呼吸、握力、视线、重心或道具动作，并让焦点、环境、光影或声音进入下一状态 |
| 道具瞬移或穿模 | 没有锁握点、分离状态和容器拓扑 | 写初始分离 -> 接近 -> 接触 -> 握紧/承重 -> 移动，并锁定开口、固定件、可动件和空气间隙 |
| 文字乱码 | 要求模型生成复杂文字 | 默认用无可读文字的画面结构；必要文字保持短句、单一位置和固定字形 |
| 血腥过度 | 接触点写成伤口细节 | 改为遮挡、反应、停机、静默、物体位置变化 |
| 光线空泛 | 只写暖光/冷光 | 补光源、方向、强度、阴影、材质反应 |
| 风格不稳定 | 风格名堆叠 | 编译为线条、色彩、光线、材质、构图 |
| 基础风格缺摄影机 | 只写“真人电影风格”或只有焦段/运镜 | 每段补 camera body/class、感光/画幅和可见成像特征；CUT焦段不能替代采集基线 |
| 技术质感词堆叠 | 每段同时写强空气透视、8:1、柔光扩散、压黑、各向异性和焦散 | 按当前光源、介质、材质和剧情功能选择，删除没有物理载体或可见任务的术语 |
| 光比/黑位损害信息 | 8:1与压黑导致必须识别的人脸、危险点或动作路线消失 | 降低光比或保留局部补光，使用`compressed black toe with retained narrative detail` |
| 色温成为整幅滤镜数字 | 只写“3200K画面”而未说明来源 | 分别点名主光、环境光和practical的色温及方向，再写混合后的冷暖关系 |

### 主体-道具-摄影机相对几何审查

冷审对每个出现手机/屏幕、枪械、刀刃、盾牌、门、书页、标牌、容器开口或其他方向性道具的 CUT 执行一次投影核对：

```text
人物世界站位与身体前向 -> 脸/目光方向 -> 道具握点
-> 道具正反面或功能方向 -> 动作目标/射线
-> camera position/look direction -> 实际可见身体面、道具面与遮挡
```

1. 人物的“面向对象”不能直接替代摄影机看见的正面/侧面/背面；道具“被拿着”也不能替代屏幕、枪口、刀刃、盾面或开口的方向。
2. 手机位于正面朝镜头的人物与摄影机之间、屏幕朝人物时，审查应要求手机背壳朝摄影机；若剧情必须显示屏幕，最小修复是明确人物转腕展示，或把camera改到人物肩后/侧后，并重算脸部可见角度。
3. 射手位于camera与目标之间且朝目标射击时，审查应要求射手背面/斜背面朝camera，枪口背离camera指向目标；若设计为枪口朝camera，必须证明camera位于目标一侧并处理目标遮挡，不把它当默认构图。
4. camera、人物身体、头部、手腕或道具发生转动/移位后，在该动作完成点与OUT重新核对可见面和功能方向；不能只在CUT开场检查一次。
5. 修复使用正向几何句：明确camera位置/看向、人物世界朝向、摄影机可见身体面、道具摄影机可见面、功能方向和目标。不要追加“不要露屏幕/不得枪口朝镜头”等同义否定句。
6. 只审当前frustum内可见的主体/道具，或方向直接影响画内动作的画外来源；明确被景别裁切、真实遮挡或位于camera后方的主体保留世界方向即可，不把它强行加入画框。
7. `screen-left/right`位移不证明人物发生yaw转身。侧倒、横移、滑行或画内坠落后，若没有躯干/头部/手腕旋转证据，保持原camera-visible side，只更新画面位置、倾斜/滚转和深度。
8. OUT把“道具功能方向”和“当前目标位置”分开核对：目标离开原射线不代表枪口/刀尖自动跟随；必须明确保持原方向或由具体关节重新追踪。遮挡也按新深度重叠重算，不因目标倒地自动消失。

### AI演员/生成世界元场景修复

只在剧情明确包含“角色知道自己被生成、读取外部指令、场景加载、服装热切换或创作者界面”时启用，不把它当普通剧情的默认风格。

| 风险 | 正向修复 |
| --- | --- |
| 场景加载时角色消失 | 世界站位与接触只在后台保持；正文先固定当前camera和完整入画角色的可见身体/接触点，再让视锥内环境按地面 -> 墙体 -> 道具 -> 光线的顺序围绕该可见角色显现 |
| 加载被误做硬切 | 明确 `one continuous shot`，以材料逐层形成承载变化；若剧情需要切镜则反向明确 `hard cut` 和新机位 |
| 外部指令变成画面文字 | 将指令定义为角色可听见但画面外的声音，画面只显示视线和反应；需要文字时使用用户提供的固定贴图 |
| 服装切换重绘面部 | 在角色侧身/背身或面部稳定的独立构图中分阶段改变服装材料，变化区域不越过脸部身份锚点 |
| 创作者界面生成乱码 | 只显示模糊界面结构、手部输入和按键声音；可读 UI 使用固定图像或后期合成 |
| 低声对白被误作内心OS | 写明画内低音量对白、说话者、自然 lip-sync、听者可听见及对应反应；内心OS继续使用括号语义 |
| 回调姿态漂移 | 只在确有必要时锁定身体姿态、手部握点、头部角度、服装和场景；仍允许当前台词所需的眼、唇和呼吸动作 |

## 已验收稿窄修改快速路由

当输入是“当前已验收提示词 + 当前项目规则/本轮用户修改 + 当前生成视频证据”时，进入窄修改路由：

1. 只读取当前已验收候选、当前用户/项目要求和当前生成视频或逐帧证据；旧候选、历史聊天、旧审阅结论、无关参考与模板全部退出事实源。宿主上层策略若强制记忆检索，记忆只用于定位当前Skill/文件，不得成为项目事实、保护项或扩大加载模块。
2. 只加载 `01_CORE_EXECUTION_CONTRACT.md`、修改层直接相关模块和本文件；禁止重新摄取完整知识库、legacy V3或无关导演模块。
3. 把已验收时间、CUT、人物、场景、对白、素材职责和OUT写入保护基线。只修指定层；直接依赖需要联动时，改动限制在问题CUT及其必要接力CUT，并在差异台账中说明因果。
4. 写明预期只改变的字段，完成后用diff证明其余保护基线未漂移；优先做精确替换，不重建世界或整篇重写。
5. 只运行快速预检卡中受影响项与包络硬门。第一次PASS即停；失败后集中修复一次，再复跑失败项与包络硬门。窄修改不是重新创作，不得借机替换已验收镜序、风格或台词。

## 初稿快速质量门与按需冷审 / Draft-First QC And Optional Cold Review

本门适用于 Wan3.0 单镜模式与多镜模式，质量检查项不因镜头结构改变；`Tmax=30秒` 固定，只按所选镜头结构调整容量、时码与参考输入上限。先在 `Resolved Policy` 写入 `review_mode=critical-only|full|off`，默认 `critical-only`。

### 初稿快速路由

普通初稿、普通续段和窄修改不生成审阅包，不调用独立审阅者：

1. **事实先行**：先锁当前剧本事实、素材职责、已验收正史和本段必达OUT；来源冲突或输出格式冲突在写稿前处理。再解析`input_profile`：粗略故事默认`director-expand`，明确忠实/精确复刻/格式转换为`constrained-compile`，已验收窄修改为`narrow-repair`。
2. **导演化骨架先行**：`director-expand`先把每个story beat编译为角色目标/阻碍/策略、可见动作与表情、空间调度、camera/edit/focus证明和新状态；原文省略这些细节不是禁止补充。随后建立静默场景拓扑和人物/道具状态表，再为每个CUT执行camera变换、视锥裁切、遮挡与画面投影。CUT骨架预先确定剧情目的、camera所见开场画框、逐个可见人物的位置/可见面/任务、明确变化、接力载体、声音/对白和可见OUT，再写完整提示词；不把故事逐句换写成站桩覆盖，也不把世界坐标清单当成画面骨架。`constrained-compile`和`narrow-repair`只补执行必需信息，不重新导演保护内容。
3. **容量先行**：按约`3–5字/秒`（安全线4字/秒）核算对白，再叠加不能并行的动作、反应、信息读取、camera travel和settle；先重排/并行/删冗余，再确定CUT窗口。
4. **一次快速预检**：执行本文件顶部 Fast Preflight Card。空间/朝向、时间/对白、动作因果/CUT接力和OUT在步骤2-3编译时已证明，此处只核对是否落入成稿，不另开整稿语义巡检。
5. **失败才修**：第一次PASS立即交付。失败时集中修复一次，只复跑失败项和包络硬门；禁止为了确认PASS再跑同一验证器、扩展清单或第二次同上下文审查。

### 长篇/多段快速路由

先建立一次全局分段地图、事实台账和跨段状态交接，再按顺序编译。每段完成 Fast Preflight Card 和相邻边界核对后立即冻结；后续只读该段OUT摘要，不回读其完整提示词。全部完成后仅聚合段数、总时长、每段字符上限和边界状态，不对冻结段进行全篇重摄取、全篇重写或全篇语义复检。发现局部失败只解冻问题段及其直接相邻边界。

### 冷审触发路由

- `critical-only`：仅当用户明确要求定稿/最终版/提交生成，当前段将成为后续批量复用的首个样板基线，或当前段包含后续提示词必须继承的不可逆跨段交接时触发。复杂、动作多、CUT多或普通打戏本身不自动触发。
- `full`：用户或项目明确要求每段/每次都冷审时触发；多段项目仍一次只审一段。
- `off`：不启动语义冷审或内部sealed-packet验收；仍执行一次 Fast Preflight Card。只有不可覆盖的宿主上层规则可以强制开启。

### 已有候选快速密封

用户已提供“最终稿/样板稿/待审候选”时，该文本就是冷审输入，不在密封前重新导演、润色、补镜或做语义质量扫描。先运行机械预检；若标题/五栏顺序、时码标签或工具包裹等机械项失败，最多执行一次格式-only标准化，并用diff证明剧情、动作正文、时长、人物、场景、对白、素材职责和OUT语义未改。允许的旧格式归一化包括：删除文件级说明标题、重排五栏、把一镜到底的`节拍N｜起止时间`标签等值改为`BEAT N（起止秒）`并补一个覆盖同一总时长的`CUT 1（0-T秒）`容器；不得改变任何时间边界或节拍正文。随后立即密封。语义问题由唯一独立审阅者首次提出；主智能体不得为了“提高通过率”在审阅前抢先修改候选。

### Sealed Preflight / 冷审启动硬门

冷审已触发时，机械预检与语义冷审必须分开，且机械预检先执行。新编候选已在编译中建立空间/容量/因果证明；已有候选只做上节的机械-only intake。独立冷审负责语义检查，所以密封前不得再追加普通路由的整稿同上下文自检：

1. 冻结单段候选文件/字符串；候选必须恰好包含一个合法段落信封标题和对应五栏目。`PROJECT_RULES.md` 必须在唯一 `## 候选提示词` 区域内嵌该段全文。只写候选路径、链接、文件名或“请读取某文件”，以及一次嵌入多个段落信封，一律视为未密封。BOM安全读取之外不trim、不改换行、不做语义等价替换；两者逐字一致后才允许记录 `EXACT_MATCH=True`。
2. 文件及候选不得含 `Exit code`、`Process exited`、`Output:`、`tool output`、工具调用参数、命令回显或其他包裹；不得存在缺失/多个候选区、旧版本候选、候选后残留正文或候选与审计包不一致。
3. 用 `Resolved Policy` 驱动机械验证器。必检项是：一行合法段标题 + 依次五栏目、总时长和连续时间窗、已生效的@句柄位置策略、时间粒度策略和候选字符上限。项目已给出确定值时，再以低自由度机械合同检查CUT数量、具名角色五维声线、按约`3–5字/秒`的对白最低容量、群体比例合计、不可逆道具状态/交接状态；没有项目确定值时不得发明期望值或升级为失败条件。
4. 标准段标题不计为第六栏。时间粒度不得固定假设 `integer_only`。当前项目明确要求“后四节@句柄为0”时调用 `--reference-handle-policy lock-only` 并检查每个句柄只在锁定区出现一次；其他项目保留默认 `any-section`。
5. 密封工具必须先验证候选，再原子发布唯一审阅包；审阅启动前同时产生并记录 `EXACT_MATCH=True`、`MECHANICAL_PASS=True` 和冻结候选哈希。任一项失败都禁止启动冷审，先修复包并重新预检；审阅者不负责替机械包“猜”正确候选。优先使用 `scripts/seal_review_packet.py` 和审阅轮次门禁脚本，不用手工复制代替可执行检查。

本地工具顺序固定为 `seal -> start -> 审阅 -> finish`。首轮PASS收到后立即`finish`并终止。首轮REPAIR收到后，主智能体先完成最小修复和机械复核，再调用`finish --structural-change true|false`；该参数描述实际完成的修复是否改变结构，不描述审阅意见严重度，也不描述计划中的修改。只有`true`才允许重新`seal`新快照并`start`第二轮。

### 冷审调用边界

1. **轮次定义**：一轮 = 一个冻结候选快照 + 一名全新无上下文语义审阅者。同一冻结快照只能登记一名审阅者；禁止并行或串行启动第二名审阅者审同一候选。
2. **首轮停止条件**：首轮 `PASS` 后立即结束语义审阅并交付，严禁为了“确认PASS”再增加审阅者。首轮 `REPAIR` 后由主智能体做最小修复；只有修复实际改变多个CUT、时间戳、空间轴线、对白分配或同等级结构层，才允许第二轮。
3. **第二轮边界**：结构性修复后重新冻结新候选、重建密封包、重新取得 `EXACT_MATCH=True` 与 `MECHANICAL_PASS=True`，并换另一名全新审阅者。第二轮包只含新的Resolved Policy、当前事实和新候选；严禁泄露首轮结论、疑似问题、期待修复、旧报告或原审阅者身份。第二轮结束即语义审阅终点，禁止第三轮。
4. **第二轮仍有阻断**：主智能体依据现有证据做最小修复并只跑机械复核；不得追加第三名审阅者。只有仍未解析的事实冲突，或“项目规则 vs Skill输出格式”优先级冲突，才询问用户。
5. **独立冷审路由**：只有 `review_mode` 已触发本次冷审且sealed preflight通过后，才新建无上下文审阅实例并只提交唯一 `PROJECT_RULES.md`。审阅者必须全量读取本文件、Resolved Policy全部类别和完整候选；不附原聊天、主智能体推理、怀疑问题、预期答案或旧报告。
6. **禁止伪冷审**：参与过创作、看过原对话、收到“这里大概有某个错误”暗示的智能体不能充当本轮冷审；同一审阅者不复用到第二轮。
7. **GPT/无独立审阅路由**：GPT 智能体版以及其他宿主只在本次冷审被触发时，才冻结候选并读取 `PROJECT_RULES.md` 做内部审核验收；普通初稿不建包。该流程不是实际子智能体，不得对用户声称已经完成真实多智能体审阅。
8. **多段/长项目逐段门**：本次冷审激活时，完整分段地图、跨段正史和待处理段号只留在静默项目台账。一次只冻结、密封、审阅并交付一个段落信封；该段得到用户明确验收或用户明确要求继续后，才建立下一段候选。审阅PASS、机械PASS、已交付或用户沉默不构成验收。当前段要求修改时继续使用当前段自己的最多两轮机制；下一段另建独立候选、`PROJECT_RULES.md` 和review-state。
9. **审阅输出语法**：`VERDICT`只接受大写`PASS`或`REPAIR`。审阅者误写`FAIL/FAILURE/NEEDS_FIX`等未知词时，不接受为新结论；只允许同一审阅者把判定词机械更正为`REPAIR`，其余报告逐字不变，不计新轮次、不再做语义审阅。

> 首轮 PASS 即终止语义审阅；不得为确认 PASS 增加第二审阅者。一次冻结候选只允许一个审阅者。第二轮只由首轮 REPAIR 后实际发生的结构性修复触发。第二轮结束后禁止第三轮。

### 等待、并发与流程异常门

- 单次等待审阅者最多60秒；一次超时后只查询同一任务状态，不重启、不复制任务、不换审阅者。等待期间可以并行执行本地机械检查，但不得并行启动多个语义审阅者审同一候选。
- 窄修改工作预算：无视频证据通常5-10分钟；需要全帧视频诊断通常10-18分钟；含结构修复和第二轮的上限通常20-25分钟。超过25分钟先标记流程异常并停止扩张审阅范围；达到55分钟必须终止新增审阅者，只完成当前证据支持的最小修复、机械复核与交付/必要提问。

### 提示词污染检查

整篇候选提示词共同参与模型语义加权。冷审在常规导演/时间轴QC之外，再执行以下最小污染检查：

1. **当前来源门**：可用来源只有当前用户请求、已分配用途的参考素材、当前项目正史/验收事实、当前领域规则授权的导演编译选择、固定技术卫生和用户明确批准复用的规则。旧项目、旧失败、旧成功模板或“听起来专业”的习惯句都不能自动成为当前来源。
2. **按语义簇而非字符串检查**：把近义形状、路径、生命周期、结果、姿态、camera行为和声音结果视为同一概念检查；不同措辞不能掩盖同一效果被全局重复加权。
3. **污染类别**：检查旧上下文残留、否定/纠错词激活不需要的名词、默认模板惯性、强关联抽象标签代替可见证据、近义正向描述过权、内部工作流/失败分析泄漏、同一控制面的互斥锚点。不要据此建立永久禁词表，每个项目重新按当前来源判断。
4. **跨栏目归属**：`【角色/场景/素材锁定】`只拥有身份、空间拓扑、参考用途/维度和开场状态；同一实体的静态事实由唯一主描述行拥有，其他素材行只能增加独有控制维度。`【基础风格】`拥有项目级camera/lens倾向、全局光线、色彩、材质和整体质感，不承载前提、核心关系、导演意图、演员总指令、对白白名单或单次事件生命周期；多镜模式五行段级执行合同位于`【运镜与时间轴】`开头，该栏目同时拥有事件专属外观/材质反应、触发/路线/接触/结果/消退、当前camera如何证明、表演、台词和时序；`【声音设计】`拥有环境/动作/生理/机械/声线等可听层及质感，逐事件声音触发仍在对应CUT定位；`【画面限制】`只保留固定技术卫生和当前确有的残余漂移风险。机制名可作为短锁定名复用，完整几何、路径、生命周期或结果只在权威栏目描述。
5. **必要重锚例外**：不同独立段必须重复冷启动身份/场景/关键道具/素材用途/基础风格；相关CUT必须重写当前地点、frustum、逐人站位/任务、后景、人群、动作相位和对白来源。这些重复服务不同作用域，不是污染。只有同一作用域内换近义词复述、且没有新增可见/可听控制时才删除。
6. **负面词边界**：除“无背景音乐；无字幕、无水印、无乱码文字；人物结构稳定”等固定技术卫生，以及用户明确要求保留的安全/法律/品牌硬禁令外，把纠错式否定改写成当前画面可直接观察的正向主体、路线、材质、camera或OUT状态；不需要的旧名词直接删除，不在否定句里继续激活。
7. **抽象标签解码**：`史诗感/压迫感/动态镜头/高速战斗/某招式名`等标签只有在身体、物体、空间、方向、接触、位移、光线、camera或声音已给出可观察证据时才可保留为短句柄；否则改写为最小可见/可听证据。
8. **冲突与删除测试**：同一控制面出现互斥要求时只执行Resolved Policy中的生效项，不折中保留两套。若发现项目规则与段落标题/五栏结构冲突且表中没有用户裁决，返回“未解析格式冲突”并停止，不得自行删标题、改栏目或选优先级。删除重复句前继续执行独有控制保真测试。

冷审可在后台使用一张短表：`语义簇 | 当前来源 | 唯一任务 | 权威栏目 | 允许重复作用域 | 保留/改写/删除/移位`。这张表不进入最终提示词；发现必须回到 `BLOCKING_FINDINGS` 的具体位置和最小修复。

### 主智能体裁决与修复

- 只接受能引用 `PROJECT_RULES.md` 中具体事实、用户要求或规则的发现。审阅者擅自新增情节、人物、道具、台词、镜头偏好、否定句或模型规格时直接拒绝。
- 审阅者必须按规则快照的完整语义判定：共同建立、推进、确认或接力同一个明确变化的视线、焦点、肢体、材质、环境和声音属于辅助变化；只有出现第二个同等级叙事结果、独立动作目标或新的结果承受者时才判为第二个明确变化。
- `PROTECTED_FACTS` 只能来自文件中的来源事实/锁定和用户额外要求。候选稿里未经授权的导演/摄影选择是可修订项，不得因审阅者复述而变成项目正史。
- 污染清理只改变来源不明、任务重复、栏目错位、语义过权或彼此冲突的表达，不以缩短字符为目标；独有控制和必要重锚必须保真。
- 修复顺序：事实/用户硬要求 -> 段落独立性与素材控制 -> 因果/空间/轴线/对白对象 -> 时长与台词 -> CUT画面可重建 -> 摄影灯光风格 -> 精简重复。
- 使用最小修复：改写问题 CUT 或相邻接力，不因一个局部问题重写全部段落，不破坏已验收台词、动作、机位或 OUT。
- 已启动的密封包是不可变审阅证据，不得用修复稿覆盖。`REPAIR`后主智能体生成独立最终候选，只复跑受影响项与包络硬门并记录最终候选哈希：非结构修复以`structural-change=false`终止状态，不建新包、不再调用语义审阅者，也不得声称旧包与最终稿逐字一致；结构修复以`true`结束首轮后，才把修复稿冻结为第二轮新包并重新取得`EXACT_MATCH=True`与`MECHANICAL_PASS=True`。第二轮后只允许主智能体最小修复与机械复核，不得第三轮。
- 密封前的机械PASS覆盖 `Tmax=30秒`、`3–5字/秒`口播、单镜模式无时码顺序与「生成单镜头」/「一镜到底」声明、多镜模式 `第N个镜头[a-b秒]` 连续覆盖（求和=duration）、素材作用域、标准信封和技术卫生；候选未改变时，冷审PASS后直接交付，不重复同一机械检查。候选有改动时按上一条定向复核。
- 默认只输出修复后的“段标题 + 五栏目”提示词；标题前和最后栏目后不附加审阅/研究/统计。只有用户明确索要分析时另行说明。

## 扩展最终诊断清单 / Failure Or Full Review Only

本清单用于快速预检失败定位、生成结果复盘、`full`审阅或用户明确要求穷尽检查。普通候选的 Fast Preflight Card 已PASS且候选未改变时，不得把本清单再执行一遍；以下仍是成稿必须满足的规则，而不是第二次流程：

- `Resolved Policy` 已记录 `review_mode` 和本次是否命中关键节点。普通快速路由已经通过一次 Fast Preflight Card；冷审激活时才要求唯一 `PROJECT_RULES.md`、候选全文唯一内嵌、逐字一致、无工具包裹/旧候选，以及 `EXACT_MATCH=True`、`MECHANICAL_PASS=True` 和快照哈希。
- 冷审激活的多段项目中，当前密封包恰好包含一个段落信封；前一段已有用户明确验收/继续指令才启动当前段，未把审阅PASS或用户沉默误作验收，也未提前审阅后续段。快速路由按用户请求交付当前段或完整初稿范围，不创建伪密封包。
- 成品-only响应严格以一行合法段落信封标题开始，再按顺序出现五栏目，以最后一个`【画面限制】`内容结束；标题没有被误判成第六节。
- 若本次启动审阅，审阅者没有新增剧情、角色、道具、台词、素材控制或模型能力；首轮PASS后没有追加确认审阅者，同一快照没有重复审阅；结构性修复若触发第二轮，使用了全新审阅实例且总轮数不超过两轮，第二轮后没有第三轮。
- 每个模型可见语义簇都有当前来源、唯一任务和权威栏目；没有旧项目/模板残留、纠错式旧名词激活、无证据强关联标签、内部工作流语言、跨栏目互斥锚点或同一作用域近义过权。
- 污染清理没有误删跨段冷启动、每段基础风格、逐CUT画面/动作/对白重锚、人群后景、固定技术卫生或其他独有控制。

- 第一栏是 `【角色/场景/素材锁定】`，且没有重复拆出 `【参考素材使用】`、`【场景锁定】`、`【角色锁定】`；每个实际参考素材独占一行，每个实体只有一条主描述行，附加素材行没有复述主行的静态身份/外观/拓扑事实。
- 对照本次实际传入的 media 数组逐项核验：每个真正传入的 `@图片/@视频/@音频` 都恰好有一条可见绑定行，没有"传入了却无描述"的悬空条件图。对主体本段不出镜却仍被传入的参考图（典型是上游按整集固定挂载）：首选已从 media 数组移除、文案不再写它；若上游固定删不掉，则须已在交付说明/改写要点里向用户显式告警"请上游把该图从本段 media 移除，提示词层面拦不住模型把它当垫图"，并保留一条「本段不出镜」正向排除行作为**不保证生效**的降级缓解（不出现其面部/身形/背影、不把五官/发型融到出场角色或后景、不派生同貌人物、不改变已出场角色身份锁定），没有被当成"精简"删掉。切勿把这条排除行当作已消除串脸。
